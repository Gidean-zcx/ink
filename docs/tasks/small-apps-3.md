## 为什么

用户 2026-11-12：“所有的应用和系统应用都是移植的最优秀的三方项目吗 我怎么感觉不太像呢”；“好不好不是看移植工作量小 是看功能成熟度 用户使用体验 这些”（D-129）；“我需要你先把当前的壳和现有已有的应用移植或参考重写搞到成熟可用”（D-131）。

调研（`docs/tasks/replan-sysapps/APPS.md` A05、`CURRENT.md` A05）：现在的计算器（`system/apps/calculator/calculator.c`）是定点小数四则运算，有优先级、百分号、正负号、连续运算、出错后能改，界面和 AI 共用能力；缺的是成熟计算器的计算历史和回填、根号乘方、完整的算式编辑。已知问题：文字大小 120% 时算式区挤。**不要**为了“复用”整块换成 ZSWatch 那种没有优先级的链式计算器（`APPS.md` A05 写明那是功能倒退）。

三个小游戏：五子棋本来就是 CrossMux 原版引擎，贪吃蛇和翻牌已经移植（`system/apps/snake/SOURCE.md`、`system/apps/memory/SOURCE.md`），这次只把页面换成新设计语言，玩法一行不改。

## 要做的

1. **计算器页面**（照 Fossify）：上面一行是算式（能看到整条），下面一行是结果（边输边预览，按“=”定下来）；按键照 Fossify 的布局，补上它有而我们没有的根号、乘方，用我们的定点核心算；超出定点范围或无意义（负数开根号）给清楚的提示，不崩、不给假数字。
2. **出错能改**：`5÷0` 显示“不能除以 0”，按删除去掉 0 改成 5，结果就出来，不用清空重来。
3. **百分比**：照 Fossify 的含义；和现在的百分号行为不一样的地方逐条写进报告（用户用惯了现在的，要知道哪里变了）。
4. **连续等号**：照 Fossify 的行为（重复上一步运算还是不动，以它为准），写进 `SOURCE.md`。
5. **历史**（照 Fossify）：每次按“=”记一条“算式 = 结果”；历史页按时间倒序，点一条把算式（或结果，照 Fossify）填回去接着算；清空历史照现有删除规则。每位家人一份，存在现有的按家人数据集合里，最多 50 条。
6. **修已知问题**：最大文字大小下算式区不挤——放不下就让算式换行或从左边省略（照 Fossify 的处理），不缩字。
7. **三个游戏**：五子棋、贪吃蛇、翻牌的页面只换样式——用共用按钮和令牌，不画粗框和圆圈，状态和分数用文字；引擎和玩法不动（`engine.*`、`vendor/` 一行不改）。

## 验收

1. **照参照路径走一遍**（`APPS.md` A05，模拟器脚本，每步截图并断言）：`1+2×3` = 7 → `200+10%` 和 `200×10%` 的结果和 Fossify 的代码一致 → `-5×-2` = 10 → 连按两次“=”照 Fossify 的行为 → `5÷0` 显示“不能除以 0”→ 删除改成 `5÷5` = 1 → `√9` = 3、`2^10` = 1024 → 打开历史，最上面是最后一条 → 点一条填回去接着算。同一组操作用能力调用（来源是 AI）走一遍，结果一样。现有计算器测试的业务断言照过；只有百分号含义因为照 Fossify 而变的那几条可以改期望，逐条列进报告（原来是多少、现在是多少、Fossify 代码的出处）。
2. **定点边界**：超出范围、负数开根号给提示，不崩；反向对照：去掉除零检查，`5÷0` 的断言必须失败。
3. **最大文字大小**：一条 30 个字符的算式在最大文字大小下完整可读（换行或左侧省略），按键不被挤小。
4. **家人隔离**：A 的历史 B 看不到。
5. **游戏**：三个游戏各自现有的测试照过；玩法和分数不变。
6. **改前改后截图**：计算器主页、出错提示、历史页、三个游戏的主页面，默认和最大文字大小各一套。
7. 主工程普通全量 ctest 过（含 `ui-scale`）；ASan 跑计算器、游戏和 `ui-scene-*` 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告。报告写固件增量、产品代码行数、`gcccheck` 结果、改过的已有测试（只改定位方式和页面结构，不改业务断言）、改名或删除的能力。
