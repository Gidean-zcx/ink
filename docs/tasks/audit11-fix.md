# audit11-fix：修 batch11 审计的 B11-01、B11-02

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/audit11-fix/REPORT.md。

审计报告是 docs/audits/batch11/report.md，每条有位置、复现和建议修法，先读它。报告里的实验驱动在审计自己的构建目录里，这里没有；复现要自己写成测试。每条配一个测试（修之前失败、修之后通过），产品代码净增不超过 80 行。

## 要修的

1. **B11-01（中）一次读文件状态失败，就把还在的文件的编号删了**：清理旧记录时只把“确认不存在”当作删除依据。`hal_fs_size` 返回 -1 时分不清“不存在”和“读出错”，可以用父目录枚举确认缺失（file-index-3 修卡身份文件的 B4-04 用过同样的办法），或者给存储 HAL 加一个能区分的查询（S31 端口的空实现跟着补）。读出错时停掉这次清理、保持“未完成”，不写完成标记，下次再清。测试：清理时让一个仍存在的文件读一次状态失败，它的编号保留，重启后也在；数量正确。
2. **B11-02（中）清理途中查一次文件列表，清理就停了**：集中修正“整卡建好”的判定：局部的同步扫描（`file.index` 首页查询走的 `index_scan`）不能结束还没做完的整卡清理，也不能取消它的后台调度；只有清理游标走到尾、而且落盘完成，才算建好。测试：清理批次之间通过正常能力查询一个空目录，清理照样做完，索引条数等于卡上实际文件数。

## 边界

- 只修这两条，不顺手重构。
- 没有别的任务在跑，但不要改索引的记录格式和存储服务。

## 验收

1. 两条各有测试，修之前失败、修之后通过（报告写清测试名）；index-prune、index-compact、index-durable、file-index-3 原样通过。
2. 全量测试和内存检查通过；S31 能编过。
3. 报告逐条写：改了什么、测试、还有没有没做到的。
