# 换成原厂代码的公共规矩（port-cell-3、port-display-3、port-board-2、port-wifi-2、port-bt-audio-2、port-power-2 共用）

总规则先读 docs/tasks/codex-rules.md，**第 10 节优先**（用户 2026-11-11：“这种级别的底层流程和驱动 你能复用就直接复用 拷贝过来都行 我已经受不了你反反复复踩坑了”）。

1. **拷原文，只写胶水**。原厂最新代码 = 提交 `874538e`（v2.0.77）：导出在 `$INK_DEPS/../ink-hw/upstream/Metalio-E-INK4-Plus-874538e`，导出里没有的用 `git -C $INK_DEPS/../ink-hw/upstream/Metalio-E-INK4-Plus show 874538e:<路径>` 取（可联网取对象）；**不许 checkout 或移动这个克隆的 HEAD**。拷来的文件放进 `vendor/<名字>/` 或 `ports/esp32s31/vendor/<名字>/`，文件内容保持原文，旁边放 `SOURCE.md`（来源路径、提交、每个文件的 SHA-256、改了哪几行和为什么）和原许可证（原厂根目录 MIT；文件头写 Apache-2.0 的照它；GPL 一律不用）。确实非改不可的几行（换成我们的 HAL 调用、去掉对原厂 UI/NVS/Application 的依赖、安全闸口），在 `SOURCE.md` 逐条列出。
2. **我们的接口不变**：`hal_*` 头文件、系统服务、能力表、测试里用到的对外函数保持原样；原厂代码接在它们下面。原厂的产品策略（自动重启整机、直接写 NVS、原厂 UI 提示）不搬进来，碰到就留接口、写进报告“和设计不一致的”。
3. **我们自己的安全检查保留**：AT 命令允许列表、日志脱敏（不出现 IMEI、ICCID、手机号、短信正文、基站位置码和小区号、MAC、Wi-Fi 名称和密码）、成员隔离、存储准入。原厂代码内部直接发的配置命令或打的日志也要过同一道闸。
4. **今天真机已证实的行为不能丢**（见 `docs/hardware/2026-11-10-trial.md` 换装 4～15）：凡是原厂代码没有、我们有真机证据的偏差，保留并在报告里写明证据。
5. **审计报告是输入**：`docs/tasks/driver-audit-1a/REPORT.md`（4G、Wi-Fi、蓝牙）、`docs/tasks/driver-audit-1b/REPORT.md` 和 `DISPLAY-CHANGES.md`（屏幕、触摸、按键、前光、加速度计、I2C）、`docs/tasks/driver-audit-1c/REPORT.md`（电源、充电、电量、时钟、睡眠、存储、相机、声音、配置）。本任务范围内的“前 10 个坑”和“直接拷贝清单”逐条处理，报告里给出每条的结果。
6. **只改本任务列出的文件**；别的任务同时在改别的底层文件。需要别的模块配合时，只调用它现有的接口，不改它的文件，写进报告。
7. **测试**：`ports/esp32s31/tests/`（S31 宿主机测试，单独的 CMake 工程：`cmake -S ports/esp32s31/tests -B <目录>` 再 `ctest`）全部要过，现有断言不放宽、不删，只因内部实现换了而把私有字段断言改到 HAL 层；每个修掉的坑加一条测试，并做撤销修复的反向对照（必须失败）。主工程普通全量 ctest 过一遍（不用跑 ASan），S31 固件 `ports/esp32s31/build.sh` 编译通过、无新警告。CI 用 Linux gcc，注意第 8 节的坑。
8. **不碰设备**：不烧录、不接串口。真机验证由主会话做；报告最后写“上机核对清单”（要看哪些日志、哪些现象算过）。
9. **规模**：胶水和适配的新增代码按任务书给的预算；拷来的原文不算预算，但要整文件或整函数拷，不要挑几行改写。不新增常驻任务或线程，除非原厂原文就是这么做的（写明栈大小和内存在哪）。
10. 报告写到 `docs/tasks/<任务名>/REPORT.md`，中文，边做边提交。
11. **功能移植的三条**（用户 2026-11-11：“特别是底层逻辑可以充分复用集成 + AI接入能力改造 + UI风格尽量统一”）：移植的是底层逻辑（解析、排版、协议、同步、存储格式、引擎），整块拿来集成；在它上面加我们的 AI 接入层（能力表里的原子能力人和 AI 共用、页面快照、软总线事件、成员隔离、存储准入）；界面**不一定重写**（用户随后补充：“但是界面也不一定要重写 因为你的UI很多做的也不太行 只在有明显风格或交互冲突的情况下改造UI”）：对方成熟的界面和交互（布局、流程、页面结构）可以照搬；只有和我们系统在风格或交互上明显冲突的地方才改造，改造时用我们的主题令牌和统一组件（`system/ui/ink/ui_theme.h`、`ui-audit-2` 定的规格）。CrossPoint 一系用它自己的 GfxRenderer 绘图、不是 LVGL，照搬的是它的布局和交互，用 LVGL 重现；原厂和社区固件的 LVGL 页面可以直接移植代码。
