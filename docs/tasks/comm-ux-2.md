# comm-ux-2：短信、联系人、电话照手机的标准流程重做

总规则先读 docs/tasks/codex-rules.md，再读 `docs/tasks/ui-feedback-4.md`（用户原话和共同设计基准）。

## 要做的

1. **短信**（`system/apps/sms/`）照 iOS 信息 / Android 信息的标准结构：
   - 会话列表（每行：对方名字或号码、最后一条摘要、时间、未读标记），右上角“新建”。
   - 新建：顶部“收件人”一行，**可以直接输入任意号码**，输入时下面提示匹配的联系人，也可以点“+”从联系人里挑；不需要先建联系人。正文输入条在底部，发送按钮在输入条右侧。
   - 会话页：气泡或左右对齐的消息列表（墨水屏用分页，不用动画），底部输入条，发送中/已发送/失败状态（失败可重发）。
2. **联系人**做成**独立应用**（`system/apps/contacts/`）：从应用列表直接进，不用先进电话；列表（按名字排序、可搜索）、详情（打电话、发短信）、新建和编辑（名字、号码、备注），表单用统一输入框规格。
3. **电话**（`system/apps/phone/`）：拨号盘、通话记录、联系人三个入口（照手机电话应用的底部分页或顶部分段），拨号时提示匹配联系人；通话中和来电页照通行布局。
4. 输入框用 `system/ui/textfield.c` 的现有接口，**不改**它（`ui-input-2` 在改它的规格，接口兼容）。号码规整：去掉空格、横线、括号再发（现在号码必须是纯数字才能发，用户输入带格式的号码应该能用）。
5. 能力表里的 `sms.*`、`message.*`、`contacts.*`、`phone.*`、`call.*` 能力保持兼容（AI 要能照样调用）；改了页面结构的地方，页面快照和 AI 操作跟着更新，`docs/system/capabilities.md` 用 `tools/capabilities.py` 重新生成。

## 范围和预算

- 只改：`system/apps/sms/`、`system/apps/contacts/`、`system/apps/phone/`、注册应用列表需要的地方（只加联系人入口）、`system/services/comm/` 里号码规整的那一处、相关测试和截图基线。
- 产品代码净增不超过 600 行；不新增服务或常驻任务。

## 验收

1. 发短信给一个没存的号码：最多 3 步（新建 → 输号码 → 写正文发送）；新建联系人：从应用列表 2 步进入表单。附前后截图对比，放在 `docs/tasks/comm-ux-2/`。
2. 主工程普通全量 ctest 过（不用跑 ASan），能力表检查过；S31 编译不用跑（主会话合并时跑）。
3. 报告写清三个应用的新结构、每个流程的步数。
