# audit3-fix：修 batch3 审计查出的九条

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/audit3-fix/REPORT.md。

审计报告是 docs/audits/batch3/report.md，每条都有位置、复现和建议修法，先读它。报告里的实验文件在审计自己的构建目录里，这里没有；复现要自己写成测试。九条都修，每条配一个测试（修之前失败、修之后通过），产品代码净增不超过 250 行。

## 要修的

1. **B3-01（高）相机 PNG 编码**：只改 system/apps/camera/png.c。编码期间记下申请的每块内存；任何一次申请或扩容失败都释放全部、返回 NULL，不崩、不漏。测试：用会失败的分配替身，在第 1 次到第 N 次申请上各失败一遍。
2. **B3-02（中）搜索**：某个来源（联系人、备忘、文件索引）读不出来时，保留其他来源的结果，并标明哪些分类暂时搜不了；不要整次失败。测试：拔卡后搜“电话”“音量”仍有结果，插回后文件结果回来。
3. **B3-03（低）AiLog 返回**：从 `AiReceipts` 返回 `AiLog` 时回到原来那一页；`AiLog` 和 `AiReceipts` 各有自己的分页位置，换成员或重新打开列表才清零。
4. **B3-04（中）备份页**：AI 调用 `backup.now` 失败时，打开着的备份页也要变成 `BackupFail`，和按按钮一样。失败要进备份服务对外的状态（`backup.status` 或它发的事件），页面只看这一处，不靠按钮自己的回调。
5. **B3-05（中）两个拍照能力**：`camera.capture` 只取一帧放在内存里、不保存。把它的标题和回执改成如实说明（例如“取一帧画面给 AI 看，不保存”“取好了，没有存到相册”）；要“拍照并保存”就走 `camera.photo`。不要删 `camera.capture`，也不要让两者都说“拍好了”。
6. **B3-06（中）文件里的图片打不开大图**：文件应用里点图片的“打开”，进相册的看图页 `Photo`，看的是这个文件。看图页要接受成员有权限的任意图片文件编号（经文件服务核对），不只认相册当前列表里的；孩子仍只能看自己的。
7. **B3-07（中）改名后成员页不刷新**：`SetMembers` 订阅 `member.changed`，开着的列表和快照马上换成新称呼；正在编辑的输入框保留已输入的内容，目标成员被删了就让这次操作失效。
8. **B3-08（中）中文称呼被截出坏字节**：`member.rename` 和 `member.add` 按实际字节核对长度，放不下就明确拒绝（回执说“称呼太长”），不静默截断；输入框的上限和能力声明一致。测试：11 个汉字被拒、10 个汉字完整保存。
9. **B3-09（中）经选择器设壁纸被记成触摸**：`wallpaper.choose` 打开选择器时记下调用来源，选完写设置时用这个来源；AI 走选择器设壁纸，活动记录里要有。

另外把报告“顺手发现”里的三处 `%u` 直接打印 `uint32_t`（camera.c、gallery.c、ai_pages.c）改成先转 `(unsigned)` 或用 `PRIu32`；真机的工具链里 `uint32_t` 是 `unsigned long`，会编译不过。全仓库的同类写法留给真机移植时统一查，这次不扩大。

## 边界

- 只修这九条和三处 `%u`，不顺手重构；不改审计报告。
- 同时在做的有 batch4：kid-2、transfer-pages、remote-app、activity-card、fw-f8、storage-usage。transfer-pages 也改 system/apps/files/files.c（只在首页加两行入口），你在 files.c 里只改“打开”的接线；其它共用文件只加最少的行。

2. 全量测试和内存检查通过；产品代码净增不超过 250 行。
3. 报告里逐条写：改了什么、测试、还有没有没做到的。
