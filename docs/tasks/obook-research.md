# obook-research：参考国文 OBOOK 5 的学习和阅读器功能（R-074）

总规则先读 docs/tasks/codex-rules.md，第 7、8 节优先。报告写到 docs/tasks/obook-research/REPORT.md。**这是调研任务，只写报告，不改产品代码，不替用户做决定。**

## 背景

用户 2026-11-10：“国文obook5的学习和阅读器的功能也比较符合我的一些想法”。我们有阅读器，规格见 `docs/product/` 和阅读器相关的任务报告，还有“继续读”卡片、AI（问这一页、长回答朗读）、录音备忘、文件和存储卡，墨水屏刷新算法也已经定了（D-110）。

## 要做的

1. 查资料，运行环境可以联网，用 curl 抓公开网页：国文 OBOOK 5 的官方介绍、说明书、应用商店或电商详情页、较长的评测。同类墨水屏阅读器里，学习功能做得好的，也挑两三款作对照，比如带词典、生词本、翻译、AI 阅读助手的。记下每个说法的网址和查阅日期，抓不到的写明，不要凭印象补。
2. 按主题整理：
   - 阅读：格式、排版、目录、书签、批注、高亮、进度同步、翻页手感、刷新模式；
   - 学习：查词、生词本、复习、翻译、听读、跟读、错题、作业、学习计划；
   - AI：问答、总结、讲解、出题；
   - 笔记和手写：如果有，写清它依赖什么硬件，比如电磁笔；
   - 内容来源：书城、导入、云盘；
   - 护眼和使用时长。
3. 每一条对照我们现在的设计，标“已有”“部分”“没有”，写我们的对应位置。依赖我们没有的硬件（比如手写笔）的功能，单独列一类，写明做不了的原因。
4. 给出建议清单：每条写好处、工作量（大中小）、风险，以及要用户定的问题，排推荐顺序，和事实分开写。

## 验收

1. 报告里每个事实都有出处网址；OBOOK 5 之外，至少再对照两款产品。
2. 对照表覆盖上面六个主题。
3. 建议清单有推荐顺序，写清哪些要用户定；依赖硬件的功能单列。
4. 不改产品代码、不改 `docs/requirements.md`、不改 `docs/decisions/`。
