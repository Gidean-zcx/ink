# sms-multipart：长短信（收到的分段拼成一条，长的分段发）

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

缺口检查（`docs/tasks/phone-gap-2/REPORT.md` A2）：收到的分段长短信不拼接（`drivers/chips/nt26/nt26.c` 只用文本模式 `AT+CMGR`），发送上限 118 个汉字（`system/services/comm/comm_service.c` 两处），超过 70 字的发送靠模组分段、没核实。完成标准要求短信完全可用。

## 要做的

预算：产品代码不超过 350 行（不含模拟器的芯片模型和测试）。

1. **收**：按 3GPP TS 23.040 / 27.005 处理分段短信：用 PDU 模式读（或模组支持的等价方式），解析用户数据头里的拼接信息（8 位和 16 位参考号两种）、GSM 7 位和 UCS2 两种编码。分段先存起来（断电不丢，按现有存储做法），齐了拼成一条进会话；乱序要能拼；缺段超过一段时间（写清取值和理由）就把已到的部分作为一条显示，并标明“短信不完整”。单段短信行为不变。
2. **发**：去掉 118 字的上限，长短信按 UCS2 每段 67 字（GSM 7 位每段 153 字）分段，用拼接头发出；写短信页显示“将按 N 条发送”（每条都算钱，用户要看得到）；任何一段失败，回执如实说明哪些发出、哪些没发出。设一个合理的总长上限（例如 10 段），写清理由。
3. **模拟器的 NT26 模型**：补上 PDU 模式收发和分段（模拟器只模拟硬件行为，依据写 3GPP 条款号）；能注入乱序、丢段、重复段。
4. 真机上 NT26 对 PDU 模式和分段的支持没查到厂家手册：按标准做，报告里列出上机要核对的点。不发真短信。

## 验收

1. 测试：收 3 段（顺序、乱序、重复一段）拼成一条；缺一段超时后显示不完整的一条；拼到一半断电重启，再收到剩下的段能拼上；发 150 个汉字分 3 段、模型收到的 PDU 拼接头正确；某一段失败的回执；单段收发原样。
2. 原有短信、通话、通信服务测试原样通过（期望不改）；全量测试和内存检查通过；S31 能编过。
3. 报告列出写短信页“将按 N 条发送”和不完整短信的截图路径。
