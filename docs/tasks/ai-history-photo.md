# ai-history-photo：AI 对话记录和重播（G2），把照片交给 AI（G4）

总规则先读 docs/tasks/codex-rules.md，第 7、8、9 节优先。报告写到 docs/tasks/ai-history-photo/REPORT.md。**只编译、跑宿主机测试，不碰设备。**

## 背景

最后一次缺口检查（`docs/tasks/phone-gap-3/REPORT.md` 的 G2、G4）。用户 2026-11-11：“都并行做吧，你自己按最合理的、工作量较小的方式来补齐这些”。真实模型和视觉在中枢上，还没有；设备这边先做完整，用模拟中枢（`simulator/environment/sim_hub.c`）测。

- G2：`system/ui/shell/ai_chat.c` 的 AiHome 总是空记录；AI 面板（`ai_panel.c`）没有重播当前回答。界面规范的 AiHome 要能找回以前问过的内容。
- G4：相册单图的“问这张图”只唤起 AI，问答请求（`system/services/ai/ai_service.c` 约第 550 行）只带页面文字。

## 要做的（取最小做法，不新造机制）

1. **对话记录**：每轮问答结束后，按成员存一条（时间、问题、回答、所在页面标题），用已有的数据集合存（参照 memo、提醒的存法），每人最多保留最近 50 条、总量有上限，超了删最旧的。AiHome 按新到旧分页列出，点开在 AI 面板里显示那条回答；可以删一条，清空全部要确认（删了找不回）。孩子只看得到自己的。能力：列出、打开、删除，AI 可调（只限当前成员自己的记录），页面有快照。
2. **重播**：AI 面板对当前或打开的回答有“再读一遍”。在线时向中枢请求把这段文字读出来（协议加一个方法，模拟中枢给合成的声音；真实中枢没有语音时返回不可用），离线时按钮不可用并说明原因。和人共用同一个能力。
3. **照片交给 AI**：相册单图的“问这张图”把当前照片缩成小图（长边不超过 512 像素、灰度、不超过 64 KiB，用已有的缩略图解码和编码），作为附件随问答请求发给中枢；只发当前成员能看的照片，换人或照片已变就丢弃。协议文档和模拟中枢一起改，模拟中枢核对收到的附件。
4. 协议改动写进 `docs/hub/` 对应文档；真实中枢 `hub/` 里加最小桩（收下附件、重播返回不可用），中枢测试照样通过。

预算：产品代码净增不超过 600 行。

## 验收

1. 测试覆盖：记录写入、上限和删旧、分页、换人隔离、孩子只看自己、清空要确认、AI 只能动自己的记录；重播在线和离线；附件大小上限、成员授权、换人丢弃。每项有反向对照。
2. 模拟器全量测试和 ASan 版通过（中枢测试要建好中枢环境，见 `hub/README.md`）；能力清单重新生成并 `--check` 通过；S31 能编过；gcccheck 通过；ui-scale 0 违规；隐私扫描。
3. 报告写清和设计的差别、截图路径。
