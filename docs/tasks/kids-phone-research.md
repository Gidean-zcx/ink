# kids-phone-research：参考多亲儿童手机和防沉迷学习手机的设计（R-073）

总规则先读 docs/tasks/codex-rules.md，第 7、8 节优先。报告写到 docs/tasks/kids-phone-research/REPORT.md。**这是调研任务，只写报告，不改产品代码，不替用户做决定。**

## 背景

用户 2026-11-10：“多亲儿童或反沉迷学习手机的许多设计比较满足我的想法 你可以想办法调用一下”。我们的设备有多成员和孩子模式：孩子的应用名单和禁用时段（kid-apps）、每天的时长（kid-1～kid-3）、孩子的确认规则（D-105）、紧急呼叫（emergency-call）。产品文档在 `docs/product/`，需求在 `docs/requirements.md`。

## 要做的

1. 查资料，你的运行环境可以联网，用 curl 抓公开网页：
   - 多亲（Qin / 多亲 AI 手机、多亲儿童相关产品）；
   - 市面上主打“防沉迷”“学习”的儿童手机和学习机，至少三款不同品牌。
   看官方介绍页、说明书、应用商店描述、较长的评测，记下每个说法的网址和查阅日期。抓不到的页面，写明抓不到，不要凭印象补。
2. 按主题整理它们的设计：
   - 家长怎么管：名单、时长、时段、远程、审批；
   - 防沉迷怎么做：内容过滤、学习模式、奖励机制、无娱乐应用；
   - 孩子用起来什么样：界面、语音助手、通讯限制、紧急联系；
   - 护眼和健康：墨水屏、距离、姿势、休息提醒；
   - 学习功能：作业辅导、词典、听读；
   - 隐私和安全：定位、陌生号码拦截、聊天限制。
3. 每一条对照我们现在的设计，标“已有”“部分”“没有”，写我们的对应位置，比如能力名、页面、任务报告。
4. 给出建议清单：每条写好处、工作量（大中小）、风险，以及要用户定的问题。排一个推荐顺序。建议放进报告的“建议”一节，和事实分开写。
5. 也写出不建议照搬的地方和理由。比如，依赖手机号和运营商的功能，我们这台设备做不了。

## 验收

1. 报告里每个事实都有出处网址，至少覆盖三款以上产品。
2. 对照表覆盖上面六个主题，每条都有我们的对应位置或“没有”。
3. 建议清单有推荐顺序，并且写清哪些要用户定。
4. 不改产品代码、不改 `docs/requirements.md`、不改 `docs/decisions/`。要新增的需求和决策，写进报告的“要用户定”。
