# ai-answer-long 复核（主会话，2026-11-10）

结论：**合入。** 改动小而集中，测试覆盖逐字一致、截断、流式和朗读，有反向对照。

## 看了什么

- 截断（`ai_service.c`）：`room` 先扣掉提示的长度；放不下时从 `room` 往回退到 UTF-8 字首再拷，接上提示（含结尾的 0），总长最多 `ANSWER_CAP - 1`；截过以后两个分支都不再追加。截过之后 `room` 的减法会回绕成很大的数，但两个分支都先看 `answer_cut`，不会用到它。
- 面板（`ai_panel.c`）：只有在已经展开、多于一页、新文字以旧文字开头时才从最后一页接着排，其余照旧整篇重排；测试核对了两种分页点完全一样。4 KB 的单页上限只在一页已有 4 KB 时才触发，不会卡住。
- 外部内存：回答 32 KB、面板文字 32 KB、页起点 `uint16_t[32769]` 64 KB，比原来多约 114 KB（报告写的“约 90 KB”偏少）。页起点按每页至少 1 字节留够，最坏情况才用得到；以后要省可以按每页最少行数收紧，不影响这次合入。
- 文档两处只改了设备一侧的事实，中枢的 1.8 KB 规则留着，对。
