# ui-semantics：控件语义合同（应用框架 F1）

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/ui-semantics/REPORT.md。

## 背景

用户 2026-11-08 定了应用框架 5 个待定项，全按推荐，都取 A（docs/system/app-framework-design.md §7）：系统应用用 C 写，AI 生成的页面用页面描述，以后再加受限脚本；生成页可用输入、分段、滑杆，确认仍只由系统请求；短输入框放固定区，长文和表单进专用编辑页；密码、验证码、证件只由本人填。决定的记录（D-111）由主会话写，你不改 docs/decisions/。

## 要做的

§9 表里的 F1，预算 300 行产品代码：字段、动作、对象与版本的接口；测试里一个最小的 C 页面，同时导出快照（AI 看到的页面）；秘密字段（密码、验证码）在快照里不出现明文，要有反例测试；复用现有 UI 的主题和组件，不另造绘图库。

## 从哪里看起

- app-framework-design.md：§9 的 F1 一行，以及前面讲控件语义、快照、秘密字段的章节（自己找）。
- 现有 UI：system/ui/（ui_task.c、theme.c、app_registry.c）。AI 读页面：system/services/ai/ai_service.c 约 520–540 行拼页面文字和状态。
- 现有快照、页面文字的测试：在 tests/ 下搜 snapshot、page_text。

## 边界

- 只做接口和一个测试页面。不改已有页面，不做 F2 以后的内容（输入宿主、列表、卡片等）。
- LVGL 只在 UI 任务里用；不新建常驻任务。
- 同时在跑的还有 member-quiesce（system/policy）、file-index-1（文件服务）、speech-cache（audio 服务）。不要改它们的文件。ai_service.c 只读不改；要改的写进报告。

## 验收

1. 接口头文件和实现；一个最小 C 页面用它声明字段和动作（测试）。
2. 同一页面导出快照，字段、动作、对象编号和版本都在（测试）。
3. 秘密字段在快照里只有“有值、无值”，没有明文；去掉遮盖，测试失败（反例）。
4. 页面版本变了，按旧版本发来的动作被拒（测试）。
5. 全量测试和内存检查通过；产品代码不超过 300 行。
