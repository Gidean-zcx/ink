## 前后数据

单位 ms；每格为 p50 / p95。每次启动复用同一份“已完成设置”的合成 Flash 镜像，SD 目录独立；先采基线，再采优化版，各 20 次独立进程。内部路径每进程 20 次，共 400 个样本。分位数用 nearest-rank，从 trace 中的原始 probe 数值计算，未拿每轮分位数再平均。

【实现】使用原始 `metalio-plus.json`、`--cpu measured`，沿用档案的 `host_to_target_default=40.0`、RelWithDebInfo。点按复用预算指标 `ui.action_to_first_change_ms`（输入事件到波形开始），翻页和应用首屏记录相应显示完成回调。开机使用主页与显示均空闲的观测点，轮询分辨率 20 ms。应用为设置、文件分类首页，以及空相册、空短信列表、空 AI 对话列表；不是满载内容库测试。

【实测】点按 p95 235.298 ms，低于 `home_basic.budget.json` 中 400 ms 的既有门槛。其它既有场景预算由完整测试验证，没有改预算。全流程时延的小幅变化含宿主机 CPU 波动，不据此宣称开机或所有应用都加速。

【实现】measured 模式将宿主线程 CPU 时间计入虚拟时间，纯 CPU 的周期注释在此模式中不重复计入。它能比较同机同配置的软件路径，不能直接推导 ESP32-S31 实机时延。开启 trace 便于保留逐样本数值；其探针开销两版一致。测量前后分别出现 245 / 240 条现有的“长时间未进入内核”告警，均已保留在本地测量证据中；未修改或屏蔽告警。确定性及资源预算使用原有 annotated 模式单独验证。

## 四处结论

- **活动卡：保留。**【实测】每次主页读取从两次 `job.list` 降为一次；本路径 p50 1.042→0.543 ms、p95 1.885→1.259 ms。【实现】主页偏移计算已读过活动，随后绘制复用这一轮结果；控制中心仍自行读取最新活动，没有增加缓存。
- **AiLog：保留。**【实测】514 条合成记录（含过期和无时间记录）从扫描 515 次降到 3 次；计数 p50 15.479→0.129 ms、p95 18.086→0.267 ms。【实现】复用数据库维护的存活总数，只扫描按时间排序的过期前缀，无时间记录仍保留。新增检查覆盖成人/孩子保留期；原有成员隔离与删除测试照常运行。大量过期记录时仍须扫描过期前缀，没有引入计数缓存。
- **缩略图：保留。**【实测】真实 1024×1024 合成 PNG 解码期间发起文件查询，查询 p50 110.003→19.997 ms、p95 149.995→20.007 ms。【实现】读完编码数据后，MEDIA 暂时持有现有缓存并在锁外解码；重新加锁后用现有文件修订号和成员 epoch 核对，变化时丢弃结果并返回忙。测试等待真实解码进入，不人为卡住线程；正向断言查询在解码结束前完成。
- **长文本：未改。**【实测】3000 字节合成正文、每轮 20 次拼音键，保存草稿相关单键处理 p50/p95 为 2.437/4.216 ms；优化版的 2.330/3.814 ms 没有对应文本改动，视为波动。【实现】数据服务原已异步写盘，本次没有证明改动它能显著缩短首帧；改成延后保存会改变断电恢复窗口，另加合并写机制超出本任务边界。保留逐次保存及现有断电恢复测试。
