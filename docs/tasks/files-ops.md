# files-ops：新建文件夹、写文件、多选

总规则先读 docs/tasks/codex-rules.md，第 7、8 节优先。报告写到 docs/tasks/files-ops/REPORT.md。

`docs/tasks/settings-gaps/INVENTORY.md` 里 `file.mkdir`（新建文件夹）和 `file.write`（写文件）只有能力没有入口；文件应用也没有多选。用户 2026-11-10 定：没有画板的页面照规范自己设计（D-117），按手机的标准补齐（D-125）。

## 要做的

预算：产品代码不超过 300 行。

1. **新建文件夹**：文件列表里一个“新建文件夹”，起名用现有的短输入框（键盘托管），名字不合法（空、重名、含 `/` 等）给明确提示；走 `file.mkdir`。
2. **写文件**：新建一个文本文件、打开已有的文本文件编辑后保存（用现有的长文本编辑页，text-long 的做法，草稿断电不丢）；走 `file.write`。只做纯文本（`.txt`），其他类型不提供编辑。
3. **多选**：文件列表进入多选，可全选，选中的一起删除（照现有删除的确认规则：放回收或确认，按现有做法）、移动、拷贝；进度和结果如实（部分失败要说清楚哪几个没成）。
4. 按钮和 AI 走同一套能力（已有的 `file.*` 能力，批量没有就补一个按列表操作的能力），快照里有选中的数量和可做的动作；能力表重新生成；新字符串用 `TR()` 并补英文。
5. 按成员隔离照旧；孩子的权限照现有规则。

## 验收

1. 测试：新建文件夹（合法、重名、非法名）；新建文本文件写字保存、重开内容一致、编辑到一半断电草稿还在；多选三个文件删除、移动到另一个文件夹、拷贝，部分失败的提示；AI 用能力做同样的事；换成员看不到别人的。
2. 原有文件应用、文件索引、传输测试原样通过；全量测试和内存检查通过；S31 能编过。
3. 报告列出新建文件夹、写文件、多选的截图路径。
