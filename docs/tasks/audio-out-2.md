# audio-out-2：音乐音质第二轮——把滤波降采样挪到出声之前做好，播放不再断续

总规则先读 `docs/tasks/codex-rules.md`（第 9、10 节优先）和 `docs/tasks/vendor-common.md`（第 1～3、6、7 条）。

## 背景

`audio-out-1`（本分支前面的提交，报告 `docs/tasks/audio-out-1/REPORT.md`）把音乐改成解码后直接送原始声音、用 speexdsp 带滤波地降到 16 kHz（外放芯片固定 16 kHz），频率特性对了，但滤波计算放在出声的音频任务里，挤得播放断续：完整流程欠载 44 次、660 毫秒，1 kHz 信噪比只有 18 dB。用户嫌现在的音乐发闷，但断续比发闷更糟，所以第一轮没合并。

## 要做的

1. **滤波降采样挪到生产这一侧**：在解码那一路（或一个独立的低优先级任务）里把解码出的原采样率声音先降到 16 kHz，放进一块放在 PSRAM 的缓冲（至少 500 毫秒）；出声的音频任务只照搬这块缓冲里的数据，不做任何滤波计算。
2. **滤波档位按算力选**：speexdsp 的质量档从高到低试，选在 S31 上算得过来、10 kHz 衰减仍不低于 40 dB 的那一档，报告写每档的计算量估算和取舍。
3. **不能挤内部内存**：缓冲放 PSRAM；DMA 描述符等内部内存新增不超过 4 KB（`audio-out-1` 报告里 DMA 4→6 会超）。
4. 暂停、定位、切歌、换成员、语音插话打断后恢复，这些流程照第一轮的测试走一遍。

## 范围和预算

- 只改：声音服务和 S31 声音 HAL 里第一轮动过的那些文件、`third_party/speexdsp/`、相关测试、`docs/tasks/audio-out-2/`。不碰别的任务的文件。
- 产品代码改动不超过 300 行（相对本分支）。

## 验收

1. 第一轮那组测试全过：整段流程欠载 0 次；1 kHz 信噪比不低于 60 dB；10 kHz 衰减不低于 40 dB（反向对照：把滤波放回出声任务，欠载测试要失败）。
2. 改前改后的频谱图和一段合成音乐的 WAV 放 `docs/tasks/audio-out-2/`（单张不超过 300 KB）。
3. 主工程普通全量 ctest 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告，报告写固件和内部内存变化。
