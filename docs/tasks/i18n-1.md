# i18n-1：多语言机制和语言设置（中文、英文）

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

用户 2026-11-10（R-069、D-116）：“语言有中英两种就可以了，但是设计上最好可以做好 i18n 的准备”。这是第一步：把机制和设置做好，先迁一小块页面证明可行；其余页面以后成批迁（i18n-2 起）。

## 要做的

预算：产品代码不超过 350 行（不含译文表和测试）。

1. **机制**：中文原文就是键，界面代码写 `T("中文")`（或同等的宏），按当前语言查表，查不到就原样用中文并计数（探针），绝不显示空白或键名。译文表放成一个按语言分的文本文件（例如 `assets/i18n/en.tsv`：一行“中文<TAB>英文”），构建时生成查找表（编进固件，不占内部 RAM）；构建时检查格式错误、重复键、占位符（如 `%d`、`%s`）两边不一致。以后加一种语言只加一个文件，不改页面代码。
2. **语言设置**：设置里加“语言”一项（中文／English），落盘保留；切换后当前页面立刻按新语言重画（用现有的页面重建方式），不用重启。一个能力切换语言，按钮和 AI 共用。
3. **AI**：发给中枢的请求带上当前语言，让回答用同一种语言（协议文档 `docs/hub/device-protocol.md` 里补这个字段；`sim_hub` 和 `hub/` 的假模型按语言回一句对应语言的话即可）。
4. **先迁两块**：首次开机的页面（`boot_flow.c`）和设置首页（分组标题、每一行的名字）。英文要写得自然、简短（照手机系统的常用说法，如 Settings、Wi-Fi、Bluetooth、Display、Sound）。
5. **排版**：英文更长，这两块页面在英文下不能截断或重叠（按规范换行或缩字号）；英文用的字体照现有字库（Noto Sans CJK 自带拉丁字母，数字用现有的数字字体），缺字要在构建时报出来。
6. 日期时间的显示格式先不改，写进“没做到的”留给后续。

## 验收

1. 测试：切到 English 后首次开机页和设置首页的快照、截图是英文；切回中文恢复；重启后保持；查不到的字符串回落中文且计数；构建时译文表的格式检查（故意放一个占位符不一致的条目，检查要失败）；AI 请求里带着语言，假中枢按语言回答。
2. 原有测试原样通过（中文是默认语言，现有快照不应变化）；全量测试和内存检查通过；S31 能编过。
3. 报告列出英文下两块页面的截图路径，写清以后迁其余页面的做法和估计的条目数。
