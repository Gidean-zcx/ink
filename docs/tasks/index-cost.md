# index-cost：文件索引放在内部闪存的代价，量出来给方案（只写报告）

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/index-cost/REPORT.md。

## 背景

文件索引集合 `file.index` 最多 1024 条，每条 216 字节，放在内部闪存（`INK_DB_DEVICE`）。audit5-fix 合入时测到，压缩一次要整体重写约 220 KB，模拟器里一次写盘 4.7 秒；这段时间里别的写盘，包括有人在等的，都要排队。

## 要做的（只写报告，不改产品代码）

1. **量**：卡上 1000 个文件时，典型使用一小时（拍照、存笔记、删文件、插拔卡、电脑归还）里 `file.index` 的写盘次数、压缩次数、每次时长，以及有人在等的写盘因此多等了多久。模拟器数字标【实测，模拟器】，真机估算单独标【估算】并写依据。
2. **给方案**：至少三个，每个写改动量、风险、收益。例如：卡的索引放到卡上（跟着卡走，不占内部闪存）；缩短记录（路径改成相对成员根目录，或者用目录编号）；调大压缩阈值或分段压缩；别的。推荐一个，写理由。
3. 实验代码只放在测试或工具里，不改产品代码。

## 验收

1. 报告里有上面的计量表和方案对比表。
2. 推荐方案写清楚要改哪些文件、大约多少行、怎么验证。
