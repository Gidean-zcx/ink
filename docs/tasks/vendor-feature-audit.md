# vendor-feature-audit：先补触感反馈，再盘点原厂功能和硬件还有哪些没用上（R-072）

总规则先读 docs/tasks/codex-rules.md，第 7、8、9 节优先，**第 9 节是这个任务的依据**。报告写到 docs/tasks/vendor-feature-audit/REPORT.md。

## 背景

用户 2026-11-10：“硬件马达利用上了没有 对一些按键有触摸反馈 这个原厂应该是具备的 你借此看下还有哪些原厂功能或者硬件相关的没有利用上”。

已经查到的：
- **原厂有一整套触感反馈**（`ink-hw/upstream/Metalio-E-INK4-Plus/main/haptic_feedback.h/.cc`、`main/boards/metalio-e-ink4-plus/input/metalio_vibe.*`）：
  - 开关默认开；
  - 强度弱、中、强三档，默认弱；
  - 手指按下时，按在可点的热区上才立刻震一下，不抢界面锁；
  - 按键也震。
- **我们只在来通知、闹钟响铃时用马达**（`system/services/audio/audio_service.c` 的 `ink_audio_haptic`，被 `notify_service.c`、`interrupt.c` 调用），点按和按键都没有触感反馈。马达的端口（P03 脉冲，`hal_haptic_pulse`）已经有了，模拟器也模拟了马达。

## 要做的

预算：第一部分产品代码不超过 200 行；第二部分只写报告，不改代码。

### 第一部分：触感反馈，照原厂做

1. 照原厂的规则做：
   - 手指按下时，按在可点的控件上，立刻震一次短脉冲。从输入服务这一层判断热区，不等界面重画，也不在界面任务里阻塞；
   - 实体键（电源、音量、AI 键、盖板键）按下时也震；
   - 长按、拖动不重复震。
   出处写到原厂文件和行号；和原厂不一样的地方，写清理由。
2. 设置：沿用现有的“振动”开关（`audio.vibration`），加强度弱、中、强三档，默认弱，和原厂一致。强度怎么对应脉冲长度，照原厂的数值。
3. 静音、勿扰、孩子模式、锁屏时震不震，照原厂的行为；原厂没写的，写清你选的做法。
4. AI 能读、能改这两个设置，走现有的 `settings.set`；页面有快照；中英文都要有。

### 第二部分：原厂功能和硬件盘点（只写报告）

把原厂固件里的功能和硬件用法逐项列出来，对照我们的代码，分成“已有”“部分”“没有”三类，每一项写原厂出处（文件和行号）和我们的对应位置。至少覆盖：

- 前光：冷暖混光和渐变；
- 音频模式：通话、蓝牙音频、耳机检测；
- 存储卡：U 盘模式（`usb_virtual_disk.cc`）；
- 摄像头：UVC 和 DVP 两条路；
- 待机页和关机图：壁纸库；
- 字体转换；
- 云传输和日志上传；
- 电量和充电：充电芯片的再充、VREG、欠压时切断电池；
- 4G 帧协议；
- 加速度计：自动旋转跟踪；
- 触摸虚拟键；
- 自检页面、电池测试页面；
- 系统监控日志；
- 硬件上有、两边都没用上的能力。

每个“没有”给一句建议：要不要做、大概多大工作量、要不要用户定。建议和事实分开写。

## 验收

1. 第一部分：测试覆盖
   - 点可点的控件会震，点空白处不震；
   - 实体键按下会震；
   - 长按和拖动不重复震；
   - 关掉“振动”就不震；三档强度对应的脉冲长度正确；
   - 勿扰和孩子模式照规则。
   原有测试照原样通过；全量测试和内存检查通过；S31 能编过；gcccheck 通过。
2. 第二部分：盘点表覆盖上面列的每一项，都有出处。
3. 报告里给出中英文截图的路径（振动设置页）。
