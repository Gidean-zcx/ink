# audit12-fix：修 batch12 审计的 4 条中级和 3 条低级

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

审计报告是 `docs/audits/batch12/report.md`，先读它。每条中级配一个测试（修之前失败、修之后通过）；低级的能测就测，不能测的写清怎么核对。产品代码净增不超过 150 行（中枢的 Python 另算，越小越好）。

## 要修的

1. **中 1**：AI 用 `settings.set` 改 `net.airplane`、`wifi.enabled` 不能绕过“先回执、再断网”和专门能力。用一处集中的办法（例如设置定义上的“只能经由专门能力改”标记，`settings.set` 遇到就转调或拒绝并说明该用哪个能力），不要在 `settings.set` 里按名字特判一串。`tests/airplane_mode.c` 里 AI 用 `settings.set` 关 Wi-Fi 的那句按新规则改，写进“改过的已有测试”。
2. **中 2**：孩子在飞行模式下不出“关闭飞行模式”按钮，改成说明“请家长关闭飞行模式”（电话、短信的面板和 AI 断网页都一样）；任何按钮被闸门拒绝时不能静默，至少显示原因。测试用孩子成员走一遍。
3. **中 3**：打开 4G 射频时不要在后台执行器上持着 AT 锁等注册：只发打开射频的指令就返回，注册交给通信服务已有的轮询；`sim_switch` 也不要在关飞行模式的这条路上持锁长等。测试：没卡、没信号时关飞行模式，后台作业（例如一次 Wi-Fi 扫描或一个设置的 apply）在 1 秒内照常完成，拨号能拿到锁。
4. **中 4**：中枢把一轮回答的文字上限提到和设备一致的 32 KB（`hub/ink_hub/gateway/wire.py`、`hub/ink_hub/voice/flow.py`；朗读的预算另算，不在这里改），超出时中枢也在末尾附上和设备同一句提示；改 `docs/hub/device-protocol.md` 第 75 行；同步 `hub/tests/contract/test_protocol.py` 里断言 1800 的地方（写进“改过的已有测试”）。中枢测试照 `hub/` 现有方式跑。
5. **低 5**：`navigation.c` `apps_walk` 里两个随 `TOOLS_MAX` 变大的数组不再放在界面任务栈上（改 `static` 或等价做法，确认只在界面任务里用）。
6. **低 6**：`ai_panel.c` 页起点数组的上限改成合理的页数（例如 1024），超过时按现有的截断提示处理，测试覆盖“全是换行”的极端回答不越界。
7. **低 7**：`apps/reader/reader.c` 的 `reader.last` 内容没变就不写；开书时那次写交给原有的保存定时器，不在界面任务上同步写。

## 边界

- 只修这七条，不顺手重构。
- 同时在做的有 sms-multipart（改通信服务、NT26 驱动的短信部分）、weather、memo-record、i18n-1、dictation-flake；只改各自需要的文件，通信服务里只动射频和换卡那一段。

2. 全量测试和内存检查通过；中枢测试通过；S31 能编过。
