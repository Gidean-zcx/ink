# index-compact：文件索引记录按路径实际长度保存

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/index-compact/REPORT.md。

## 背景

docs/tasks/index-cost/REPORT.md 量过：文件索引每条固定 216 字节内容（加帧头 252 字节），第一次给 1000 个文件的卡建索引，要先一次追加 252 KB，再压缩重写一次 252 KB，模拟器里各约 4.5 秒，按闪存手册估算真机各 3.8～17.5 秒；这期间有人在等的写盘要排在后面。报告推荐方案 B：按路径实际长度保存记录，每条约 92 字节，写盘量少约 64%。

## 要做的

预算：产品代码改动不超过 180 行（增删合计），集中在 system/services/file/file_service.c。

1. 记录改为“卡身份、大小、修改时间、路径（实际字节数加结尾零）”，schema 升到 3；读写都走同一处编解码和校验。
2. 兼容旧记录：schema 2（index-durable 的定长格式）和更早的格式读得出来，编号不变；升级在后台补建时顺带完成，不另起迁移流程。
3. 不改数据服务的帧格式、存储队列和写盘顺序；完成记录（`file.index_ready`）照旧。

## 边界

- 不改刷新算法（D-110），不改存储服务。
- 同时在做的有 ime-quality、settings-gaps 和 audit7-fix（它也改 file_service.c 的 `index_edit` 和借卡入口），只改记录的编解码和用到它的地方。

## 验收

1. 前后对比【实测，模拟器】：1000 个文件第一次建索引的追加字节数、压缩字节数和各自耗时，以及压缩期间有人在等的写盘多等多久（沿用 tests/index_cost 的测量工具）。
2. 测试：旧格式（schema 2）的索引升级后编号不变、重启后不再重建；最长路径（报告里的 155 字节虚拟路径）能存能取。
3. 全量测试和内存检查通过；S31 能编过。
