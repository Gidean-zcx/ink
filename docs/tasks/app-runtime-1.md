# app-runtime-1：可装可卸的页面描述应用（G11，D-08 第二阶段、D-111）

总规则先读 docs/tasks/codex-rules.md，第 7、8、9 节优先。报告写到 docs/tasks/app-runtime-1/REPORT.md。**只编译、跑宿主机测试，不碰设备。**

## 背景

最后一次缺口检查（`docs/tasks/phone-gap-3/REPORT.md` 的 G11）：R-008 要求应用能动态加载安装；`docs/system/app-framework.md` 写明还没有应用包加载器和声明页运行时，现在只能用 C 写应用。D-08：内置 → 声明式页面 → 脚本，分阶段；D-111（用户已定）：AI 或中枢生成的页面用受限页面描述，可用输入、分段、滑杆，确认只由系统请求，以后再加受限脚本。设计见 `docs/system/app-framework-design.md`。用户 2026-11-11：“都并行做吧，你自己按最合理的、工作量较小的方式来补齐这些”。

## 要做的（取最小做法：只做页面描述，不做脚本）

1. **应用包**：存储卡上一个文件夹 `/apps/<id>/`，里面一份清单（id、名字、图标、版本、要用的能力和权限）和若干页面描述（JSON）。复制进去就是装，删掉就是卸（经现有的文件能力和传输）；系统启动和卡插拔时扫描，坏包跳过并记日志，不影响别的应用。
2. **页面描述运行时**：页面由文字、列表、输入框、开关、分段、滑杆、按钮组成，按钮和控件只绑定已有能力和参数，数据来自能力的回执；用现有的界面组件画（遵守主题和 ui-scale），页面快照照现有的语义规范导出给 AI。
3. **权限**：清单里没声明的能力一律调不动（用能力闸门里已有的应用权限检查 `ink_app_foreground_may`）；孩子的应用名单、成员隔离、确认卡照旧由系统管。
4. 应用列表里出现装好的应用，打开、返回、卸载都能用；AI 能列出和打开它们。
5. 附一个示例应用包（比如“单位换算”或“每日一问”），放在 `examples/`，测试用它。

预算：产品代码净增不超过 900 行。

## 验收

1. 测试覆盖：装、卸、坏包、没声明的能力被拒、快照内容、孩子名单生效、卡拔出时的处理。每项有反向对照。
2. 模拟器全量测试和 ASan 版通过；能力清单重新生成并 `--check` 通过；S31 能编过（内存和栈在预算内）；gcccheck 通过；ui-scale 0 违规；隐私扫描。
3. 报告写清和 `app-framework-design.md` 的差别、页面描述的格式说明（写进 `docs/system/`）、截图路径。
