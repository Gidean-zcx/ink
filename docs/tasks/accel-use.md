# accel-use：加速度计用起来（拿起亮屏、静止省电）

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

用户 2026-11-10 定（D-122）：加速度计用于“拿起亮屏”和“放着不动时省电”，不做自动转屏（墨水屏转一次要整屏重刷，看书时容易误转）。现在系统完全没用它（`system/` 里没有 `hal_accel_*` 调用）；接口在 `platform/include/ink/hal_device.h`（`hal_accel_read`、`hal_accel_motion_count`），模拟器有模型（`ports/sim/hal/hal_sensors_sim.c`），S31 端口刚接上（port-hal-1）。

## 要做的

预算：产品代码不超过 200 行（不含模拟器模型和测试）。

1. **拿起亮屏**：锁屏（屏幕关着或显示锁屏画面、设备在浅睡）时，被拿起来（运动中断加姿态变化）就唤醒到锁屏，和按电源键唤醒的效果一样（回到哪一页、要不要输密码照现有规则 D-95）。放在桌上被轻碰、在包里晃动不能频繁误唤醒：写清判定（例如姿态从平放到手持角度、运动持续时间）和取值理由。可以在设置里关掉（默认开），按钮和 AI 走同一个设置。
2. **静止省电**：设备平放不动、没人操作超过一段时间（写清取值），提前进入浅睡或降低后台工作的频率（照电源服务现有的省电手段，不新造）；一拿起来就恢复。正在播放、通话、录音、下载时不进。
3. **功耗**：加速度计本身的采样和中断设置要省电（用芯片的运动中断，不在主循环里轮询读数）；在模拟器的功耗模型里给出开和关的待机电流对比【实测，模拟器】。
4. 能力表和快照：设置项、状态（例如“刚被拿起”）进能力表；设置页的 AI 快照里有这一项。
5. 真机上的阈值和坐标轴方向要上机校准，报告里列出要核对的点。

## 验收

1. 测试：锁屏状态被拿起来就亮到锁屏；平放时轻碰、持续晃动的误唤醒判定；关掉设置后不再唤醒；平放不动超过时限进入省电、拿起恢复；播放和通话中不进省电；待机电流对比。
2. 原有电源、锁屏、成员门、待机场景测试原样通过；全量测试和内存检查通过；S31 能编过。
