## 为什么

用户试用时：“键盘按钮大大小小的很奇怪”“键盘的语音按钮太大太难看了”（`ime-reuse-1`）；2026-11-12：“外壳有很多我其实并不满意 希望你参考成熟设计完善一下”；D-129：输入法这类基础框架选最成熟、体验最好的来源，“好不好不是看移植工作量小 是看功能成熟度 用户使用体验”；D-131：键盘和输入法属于先做到成熟可用的外壳。

两份调研一致（`docs/tasks/frameworks-research-1/IME.md` “键盘界面单独排名”；主会话另一份调研 1.2 节）：键盘界面 fcitx5-android 最完整（候选一点展开成分页网格、字母键长按弹符号、符号分类分页、单独的数字键盘），只能照着翻译成 LVGL；符号分类补 Trime；墨水屏上的刷新规矩照 Mogo（同一块屏调过）。

现状：`system/ui/shell/keyboard.c`（`ime-reuse-1` 换成 `lv_keyboard` 键表，有全键、九宫格、符号、数字、密码键盘，语音键在候选条右侧；`fixes-1112` 修了切中英文丢第一个键）。

## 要做的

1. 照 fcitx5-android 的页面逐页翻：全键盘（中文、英文）、九宫格（照 Mogo，带读音选择）、数字键盘、符号面板（分类标签 + 分页 + 最近用过的一行，分类内容照 Trime）、候选展开（▾ 把候选条展开成占满键盘区的分页网格，再点收起）、字母键长按弹出备选符号（能做上滑就做，做不好只做长按，写进报告）。
2. **按键规格**：同一行按键等宽，功能键统一倍数宽，语音键和功能键一样大；尺寸放进键盘自己的头文件（新文件，例如 `system/ui/shell/keyboard_theme.h`），**不改 `ui_theme.h`**（`design-lang-1` 独占）。按键高度保持现在的令牌值（`INK_KB_KEY` 96），另出一套 108（新设计语言的点按下限）的截图写进报告“要用户定”；其它可点的东西（候选、展开网格里的格子、分页按钮、符号分类标签）不小于 108。样式跟新设计语言：键不套圆圈、不画粗框，主次靠样式不靠大小。
3. **刷新**：照 Mogo 的规矩，按一个键只刷组合串和候选条，切布局才重画键盘；长按弹出只刷弹出的那一小块；不主动要求整屏刷新（D-127 由刷新算法统一处理）。
4. **能力和快照**：打字和选词照旧只走 `keyboard.key`、`keyboard.pick` 和文本服务（`system/services/text/`，同时由 `ime-engine-1` 换引擎，**不碰**）；新的用户操作（展开和收起候选、候选翻页、切符号分类、符号翻页、切数字键盘、长按选备选符号）都登记成能力，按钮和 AI 调同一个。快照给：组合串、可见候选和第几页、当前面板和分类、能做的动作；密码键盘照旧不出候选、快照里没有正文。
5. **最近用过的符号**：每位家人一份，最多 8 个，存在现有的按家人设置里，不新建文件格式。
6. 设备自动测试脚本 `tools/device/autotest/memo.script` 是按坐标点键的，跟着新布局改。
