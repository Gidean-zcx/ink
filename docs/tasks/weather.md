# weather：天气

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

用户 2026-11-10（D-125）：“天气还是想办法做一下吧”。做法：家庭中枢去取免费的天气数据（不用注册、不花钱），设备只把城市告诉中枢，不传精确位置。

## 要做的

预算：设备端产品代码不超过 300 行；中枢端照 `hub/` 现有代码的规模，越小越好。

1. **中枢**（`hub/ink_hub/`，Python）：新增天气模块。数据源用 Open-Meteo（免费、不用密钥，个人非商业使用；地名查经纬度用它的地理编码接口），按城市缓存 30 分钟；接口留成可替换的数据源（以后换国内的源不改设备）。测试只用假数据源，不联网；真实数据源单独一个函数，不在 CI 里跑。在报告里写清 Open-Meteo 的使用条款要点（非商业、署名要求等）和以后商用要换源。
2. **协议**：设备向中枢要天气的一个请求（按 `docs/hub/device-protocol.md` 的写法补进去），返回当前温度、天气现象、今天最高最低、未来几天的简要预报、更新时间。`sim_hub` 支持它。
3. **设备**：设置里一个“天气城市”（输入城市名，中枢返回匹配的城市让人选）；今日屏一张天气卡片（当前温度、天气、最高最低）；一个天气页（今天和未来几天）；能力 `weather.get`（按钮和 AI 共用，AI 问“明天要不要带伞”能用上）。没联网时显示上次的数据和更新时间；从没取到过显示规范的空状态。
4. 没有画板：照规范第 1 节和今日屏现有卡片设计；天气现象用文字为主，图标按 `assets/icons` 的规格只画最常用的几种（晴、多云、阴、雨、雪），不要卡通。

## 验收

1. 测试（模拟器加假中枢）：设城市后今日屏卡片和天气页显示假数据；断网后显示上次数据和更新时间；没设城市的空状态；AI 用 `weather.get` 拿到同样的数；中枢的单元测试覆盖地名查询、缓存、数据源出错。
2. 原有今日屏、设置、中枢测试原样通过；全量测试和内存检查通过；S31 能编过。
3. 报告列出今日屏卡片、天气页、设置城市的截图路径。
