# fw-gaps：应用框架补两处——后台打开集合、取消订阅

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/fw-gaps/REPORT.md。

## 背景

docs/system/app-framework.md（F13，写应用的说明）里标了“还没有”的两处，都是写应用天天要用的：

1. **后台打开集合**：`ink_app_db_open()` 第一次打开可能读盘，说明只能叫应用自己“放到后台”。examples/jot 的首次读取是由宿主在界面任务外准备的，应用自己做不到。
2. **取消订阅**：状态、设置订阅没有取消句柄和退订接口（说明 §9 末尾）。页面每次创建都订阅一次，旧回调就一直留着，还拿着已经销毁的控件。能力事件订阅（`ink_cap_subscribe`）同样没有退订。订阅表是固定上限（事件 64、状态 64），留着不退迟早会满。

## 要做的

预算：产品代码改动不超过 200 行（增删合计），示例和说明不计。

1. 后台打开集合：给应用一个调用，在后台执行器以调用时的家人身份打开集合，完成后回到界面任务交回句柄或错误；页面在完成前已经关掉、或者家人已经换了，就不交回并关掉句柄。用已有的执行器和任务，不新建线程。
2. 取消订阅：状态订阅、设置订阅、能力事件订阅各自返回一个句柄，可以退订；退订之后回调不会再被调用，正在调用的那一次结束后才算退完（写清楚在哪个执行器上保证）。已有调用方不用改；返回值的变化要兼容现有代码。
3. examples/jot 改用这两个调用：首次读取由应用自己发起，页面订阅一个状态并在销毁时退订；tests/jot 跟着改。
4. docs/system/app-framework.md 对应两节去掉“还没有”，按真实头文件写用法和行号。

## 边界

- 只做这两样，不顺手改别的框架接口。
- 同时在做的有 storage-order、sound-clock、phone-2、ui-fidelity；system/policy/cap.c、state、设置这些共用文件只加最少的行。

## 验收

1. 测试：后台打开在完成前关页面、换家人，句柄被关掉且回调不到界面；正常时在界面任务上拿到句柄。
2. 测试：三种订阅退订后不再回调；页面反复打开关闭 100 次，订阅表占用不增长。
3. jot 示例和 tests/jot 通过，说明里的代码块仍逐字出现在编译的示例中（沿用 tests/jot/check_doc.py）。
4. 全量测试和内存检查通过。
