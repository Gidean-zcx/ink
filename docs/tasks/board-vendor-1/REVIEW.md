## 高

1. **充电核对和再充占住了电源任务**。
   - 现象：`scenario-standby-metalio-plus` 唤醒到可见从 822.8 ms 变成 1432.1 ms（预算 1200 ms），`integration-member-wake`、`integration-people`、`clock-extras`、`i18n-shell` 失败。
   - 原因：2/10 秒的核对放在电源任务里同步做，一轮要发好几次 I²C；再充那段 200 ms + 500 ms 的等待更是整段阻塞电源任务，这期间它处理不了唤醒和状态通知。
   - 修法：
     - 核对和再充不能阻塞电源任务。用系统已有的共享定时器或执行器来排期（不新开常驻任务）；再充的两段等待改成定时器分两步做，期间不阻塞任何任务。
     - 唤醒、锁屏、浅睡入口优先，核对排在它们后面。浅睡期间不核对，醒来后照原厂的节奏继续。
   - 验收：
     - 上面 5 项全过，唤醒到可见回到基线附近（≤ 900 ms）。
     - 不改脚本的点按时刻，不放宽任何预算。
2. **内部 RAM 超预算**。
   - 现象：`ui-scene-ImeVoice`、`ui-scene-big-ImeVoice` 的最低内部 RAM 是 32568 B，预算 32768 B；原因是前光渐变新加的互斥量和定时器占了 208 B 内部 RAM。
   - 修法：不新增占内部 RAM 的对象。复用前光服务和共享定时器已有的锁和定时器，或者把渐变状态放进 PSRAM（`INK_PSRAM_BSS`）。
   - 验收：这两项过，不提高预算。
