# wireless-transfer：无线传文件

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/wireless-transfer/REPORT.md。

## 基线

你的分支建在 file-index-1（稳定文件编号）的分支上：它还没合入主线，已经自己验收完。只在它上面加；它做的部分不改，除非是修它的 bug（写进报告）。

## 要做的（docs/tasks/backlog.md 原文）

预算 400 行产品代码。无线传输：一次性数字授权、只放一个目录、超时断开、和 U 盘模式互斥、按成员。服务在模拟器里真能传文件。验收：传输过程断开、授权过期、空间不足、文件名不合法都有测试。

## 从哪里看起

- docs/system/ui-dependencies.md 里无线传输、U 盘模式的行；服务设计文档里对应的章节（搜“无线传输”“U 盘”）。
- 文件服务 system/services/file/；存储和 U 盘模式 system/services/storage/；网络 system/services/net/；模拟器的网络在 ports/sim/hal/。

## 边界

- 协议用设计文档定的；没定就用最简单的 HTTP 上传（一个页面、一个表单），不做断点续传、多文件并发。
- 授权是一次性数字码，用过或过期就失效；文件只能放进当前成员的一个收件目录。
- 和 U 盘模式互斥：一个开着，另一个就开不了，如实返回原因。
- 不新建常驻任务，用已有的执行器或网络服务的机制。
- 同时在跑的还有 confirm-durable（system/policy）、ui-input-host（system/ui 和文本服务）。不要改它们的文件。

## 验收

1. 模拟器里真的从外面传一个文件进来：落在当前成员的收件目录，文件服务能给出它的编号（测试）。
2. 传输中断开、授权过期、空间不足、文件名不合法（含 `..`、绝对路径、控制字符）都有测试，结果如实。
3. U 盘模式开着时开不了传输，反过来也一样（测试）。
4. 新操作进能力表；全量测试和内存检查通过；产品代码不超过 400 行。
