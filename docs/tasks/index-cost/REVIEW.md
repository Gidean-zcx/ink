# index-cost 主会话复查（2026-11-10）

结论：成立，合入报告和测量工具（手动运行，不进 ctest），产品代码零改动。第一次给 1000 个文件的卡建索引，要先一次追加 252 KB（模拟器 4.6 秒）、紧接着压缩重写一次（4.4 秒），按闪存手册估算真机每次 3.8～17.5 秒；这期间有人在等的写盘要排在后面（受控实验多等 4.4 秒）。日常一小时内没有压缩。

采纳推荐方案 B（记录按路径实际长度存，每条从 252 字节降到约 92 字节，写盘量少约 64%，只改 file_service.c 约 150 行），记进 backlog，作为下一批的性能任务。方案 B 不能保证同步写盘短于 250 ms；要彻底不让索引卡住内部闪存，需要另做方案 D（分段写、段间让有人在等的写盘插队）或方案 A（索引放到卡上）。
