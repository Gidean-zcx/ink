# 交给 Codex 的开发任务：总规则

这份规则和任务书一起发给执行者，要照字面做。你是执行者，不做产品决定。结果由 Claude 逐条复核，再由用户验收：报告里写“通过”却复现不了，算没完成。

路径用环境变量：`$INK_DEPS` 是放构建依赖的主检出目录（只读），`$INK_DESIGN` 是设计稿导出目录（只读）。

## 1. 绝对不许

- 碰设备：不用 esptool、`idf.py flash`、`idf.py monitor`，不打开 `/dev/cu.*`、`/dev/tty.*`，不写 eFuse，不动 4G 模组。
- 读这些：`~/ink-hw-backup`、`ink-hw` 下除 `upstream/` 以外的内容、这台电脑上和项目无关的任何文件（`~/.ssh`、浏览器、邮箱、别的仓库）。
- 花钱或对外：不调付费接口，不用也不伪造真实密钥，不发短信电话；不 push，不开 PR，不改 GitHub 设置，不加 GitHub remote。
- 改历史或删资料：不 force，不 rebase 已有提交，不删分支，`docs/research`、`docs/briefs`、`docs/audits` 里已有的文件不动。
- 提交这些：MAC、IMEI、ICCID、Wi-Fi 名和密码、令牌、本机绝对路径（`/Users/...`、`/private/tmp/...`）、构建产物、`$INK_DESIGN` 里的设计稿。测试数据要明显是假的（`00:11:22:33:44:55`、`example.com`）。

## 2. 范围

- 只做任务书写的。别的问题记进报告的“顺手发现”，除非挡路，否则不修。
- 不重构、不改名、不挪文件、不升级依赖、不批量改格式。
- 不改 `docs/requirements.md`、`docs/ideas.md`、`docs/decisions/README.md`。要决定的事写进报告的“要用户定”，选最保守、可逆的做法继续，不要停下来等，没有人回答问题。
- 不许自己认定某功能“不需要”“首版不做”。做不到就写“没做”和原因。
- 设计文档和规范是合同：实现和它们不一致时，不改文档迁就代码，写进报告的“和设计不一致”。任务书明确允许改的除外。

## 品味和规模（硬性）

- 小问题小改。修一个问题默认不超过 30 行产品代码；超过 100 行要在报告里写“为什么不能更小”和看过的更小方案。任务书给了预算的，不要超。
- 不加新机制：新任务或线程、状态机、持久文件格式、后台重试、缓存、队列、配置项、抽象层、通用框架、“以防万一”的检查。任务书没要求又确实绕不开的，这一条先不做，写进报告的“要用户定”，继续做别的。
- 一个根因只修一处，能删就删。不要在每个调用方各打一个补丁。
- 只防现实会发生的事。要靠人为卡住线程才碰得到的时序窗口，先想能不能用一个集中点整类消掉；不能就写进报告，不要逐个打补丁。
- 测试和改动成比例，不要为一个小修写一套框架。
- 报告加一节“新增的机制”：每个新任务、状态机、文件格式、配置项各一行，说明谁要求的。

## 3. 诚实

- 占位、假实现、没跑过的，不能写成完成。结论标证据：【实测】本次命令跑出来的，【实现】读代码得到的，【估算】。
- 为了过测试，不许删测试、放宽断言、抬高预算上限、加 sleep 掩盖时序问题、`#if 0`、跳过测试。改已有测试的期望要逐条列进报告并说明原因。
- 修问题要有测试，并做反向对照：撤掉修复，测试确实失败；把结果记下来。
- 同一个问题试过三种办法还不行，记下来，做下一项，不要空转。

## 4. 这个项目的默认规矩

- 代码跟周围一样：C 用 `ink_` 前缀，注释用英文且简短；文档用平白的中文，不写宣传语。用户看到的字用中文，遵守[界面规范](../product/system-ui-spec.md)第 0 节的词表（D-98）。
- 分层靠构建目标保证：系统和应用不能引用模拟器头文件；硬件只走平台接口（OSAL、HAL）。
- 能力和软总线：用户能做的事都要是能力表里的原子能力，按钮和 AI 走同一条路，界面不直接改服务内部状态（R-061）。新页面要提供给 AI 的快照（G-002）。
- 资源：内部 RAM 很紧，预算测试不能放宽；大缓冲放 PSRAM，不放栈上；不随便加常驻任务；输入任务和中枢回调里不阻塞；LVGL 只在界面任务里碰。
- 模拟器确定性：在模拟任务里做宿主机的事（malloc、文件、格式化输出、统计）要走 `vtk_host_call`、`sim_host_malloc`、`sim_copy_name`，不读宿主时间。确定性测试必须还能过。
- 成员隔离：数据和事件都按成员；孩子进不了大人空间；密码框内容不给 AI、不进日志；AI 不能代替人输密码或确认。
- 确认规则（D-105）：人亲口要求的事和非高风险设置直接做，做完说结果；只有花钱、密码证件、找不回来的删除、身份权限、把没提到的家庭资料发出去、不是人要求的对外动作才弹确认卡。
- 第三方资源只用许可清楚的（不用 GPL），记来源、版本、哈希，带上许可证。单个文件不超过 5 MB。
- Linux（ubuntu-24.04）和 macOS 都要能过。这台 Mac 没有 Docker。本机是 macOS 的 clang，CI 的 Linux 是 gcc 加 `-Werror`，更严：`write`、`read`、`fgets` 这类函数的返回值必须检查，写 `(void)` 不算。

## 5. 构建和测试

```bash
cmake -S . -B build -DINK_WERROR=ON -DINK_CJK_FONT=$INK_DEPS/build-deps/fonts/NotoSansCJK-Regular.ttc -DINK_CJK_FACE=2 -DINK_CJK_MEDIUM_FONT=$INK_DEPS/build-deps/fonts/NotoSansCJKsc-Medium.otf -DINK_CJK_BOLD_FONT=$INK_DEPS/build-deps/fonts/NotoSansCJKsc-Bold.otf -DPython3_EXECUTABLE=$INK_DEPS/build-deps/pyenv/bin/python -DFETCHCONTENT_SOURCE_DIR_LVGL=$INK_DEPS/build/_deps/lvgl-src
cmake --build build -j4
$INK_DEPS/build-deps/pyenv/bin/ctest --test-dir build --output-on-failure -j3
```

资源限制（上次并行太多，把用户的电脑卡死到要强制重启）：构建最多 `-j4`，**不许用不带数字的 `-j`**，它在这台电脑上等于不限；`ctest` 最多 `-j3`；同一时间只跑一个构建或一轮全量测试；不要启动带窗口的 `ink-sim-gui`，窗口版由复核者看。

内存检查：同样的命令换目录 `build-asan`，加 `-DINK_SANITIZE=ON`，不要 `-DINK_WERROR=ON` 以外的改动。构建目录都已被忽略。

## 6. 过程和报告

- 你在自己的分支上工作。每完成一个里程碑就提交一次，提交信息是简短的英文祈使句，只提交相关文件。
- 一开始就建任务书指定的 `REPORT.md`，每个里程碑更新，断了也留得下结果。如果开工时已有内容和提交，说明上次断了：先看 `git log` 和报告，接着做，不要重来。
- 结束前：全量测试和内存检查都跑一遍；`git diff --stat` 看有没有夹带；查隐私：`git diff <基线>..HEAD | grep -nE '/Users/|/private/tmp|[0-9A-Fa-f]{2}(:[0-9A-Fa-f]{2}){5}'`，结果写进报告。
- 报告的结构固定：验收表（每条一行：编号、结论、证据、命令）；没做到的；和设计不一致的；改过的已有测试；要用户定的；顺手发现。写短，不复述任务书。
- 只有每条验收都有结论、测试跑过、提交完，最后一条消息的第一行才写 `TASK_COMPLETE`，后面用几行说结果。没到这一步不要结束，不要写“接下来我会”。

## 8. 2026-11-10 补充（这一天查出的坑，和上面冲突时以这里为准）

- 同时最多七个任务在跑：构建最多 `-j2`、`ctest` 最多 `-j2`，命令前加 `taskpolicy -c utility`（2026-11-10 晚上起；只有三个任务时可以用 `-j4`、`-j3`）。
- **按行数分配的固定数组**（如 `values[8][384]`）要用一个命名的上限，并给每张行表加 `_Static_assert(行数 <= 上限)`。Linux CI 的 gcc 带越界保护，第 9 行写出 8 格数组会直接中止；macOS 和 ASan 都发现不了（越界还在同一个结构体里）。
- **先收尾、再改对外能看到的状态**：例如先 `ink_task_end`、再写 `update.state`；先告诉中枢“说完了”、再回到空闲。反过来写，别的任务在两步之间被唤醒就会看到前后矛盾（这一天的听写、更新下载两个竞态都是这样）。
- **同一执行器上调能力，回复可能在调用里面就回来**：不要写 `busy = (ink_cap_call(...) == 0)` 这种“调用后再赋值”，先赋值再调用，失败时再改回。
- **页面收到变化事件就整页重画，会丢掉已经排队的点按**：只对真正影响这一页的事件重画（boot-db-stall 查明，此前“后台打开数据集合会卡住文件列表”是误诊）。
- **测试**：不要依赖主机的目录顺序、哈希顺序、编号顺序（macOS 和 Linux 不一样）；等明确的状态或事件，不盲等；打印 `g_result` 这类长字符串一律带精度（`%.150s`）；点按可能落在一次闪存擦除里被丢，测试要确认驱动收到了这一下。
- **报告**：写清全量测试结果原话、内存检查跑了哪些、S31 是否编过、`ink-codex/tools/gcccheck.py` 的结果、产品代码行数。
