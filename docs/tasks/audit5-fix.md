# audit5-fix：修 batch5 审计的 B5-01、B5-02、B5-03，以及 S31 的等待时长换算

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/audit5-fix/REPORT.md。

审计报告是 docs/audits/batch5/report.md，每条有位置、复现和建议修法，先读它。报告里的实验脚本在审计自己的构建目录里，这里没有；复现要自己写成测试。每条配一个测试（修之前失败、修之后通过），产品代码净增不超过 150 行。

## 要修的

1. **B5-01（高）清空存储卡的范围不在确认说明里**：`system.factory_reset` 带 `clear_media` 时，确认卡写明“同时清空存储卡上的书和音频”；不带或为 false 时写明卡上的书和音频保留。人和 AI 发起都一样，家长密码和参数绑定照旧。测试：AI 直接调用 true、false 两种，读真实的待确认列表，两次说明不同且如实，然后取消（不执行删除）。
2. **B5-02（中）文件改动成功后马上断电，重启后统计漏文件、改名后编号找不到**：
   - 出现新路径（新建、复制、恢复、电脑归还后的 rescan）时，在改动返回成功之前把“整卡建好”标记（`file.index_ready`）的失效落盘。只有建好后的第一次改动需要等这次写盘，到下次建好之前不用再写。
   - 改名、删除的索引记录在返回成功前落盘（`index_edit` 末尾等一次即可），但不要恢复后台建索引的逐条同步写盘。
   - 测试：建好后新建文件、改名，各自在成功返回后立刻模拟断电，重启后新文件有编号、`file.usage` 是新数，改名后原编号指向新路径。
   - batch7 的 storage-order 正在改同一个文件里 `index_background` 的落盘方式和存储服务的写盘顺序。你只改失效标记、`index_edit`／`index_save` 和开机复用完成记录这几处，不动 `index_background` 的批次落盘。
3. **B5-03（中）大人看过孩子的活动记录后，单独打开回执页仍是孩子的**：只有从孩子的活动记录进入对应回执时才保留孩子；单独打开（`shell.ai_receipts` 不带成员、从设置或对话进入）一律是当前家人。要带成员的话用可选参数，鉴权和 `shell.ai_log` 一样（大人看孩子、自己看自己）。测试：按审计的步骤（看孩子的日志 → 回主页 → 打开回执）看到的是自己的；从孩子日志进回执看到的是孩子的。
4. **S31 的等待时长换算**（审计“待证实”第 3 条）：`ports/esp32s31/osal_ticks.h` 的 `ink_s31_wait_ticks` 把 esp_timer 和 FreeRTOS tick 的差（`phase`）加进了等待时长，两个时钟起点不同（FreeRTOS 的 tick 在调度器启动时才从 0 开始），所以每次带超时的等待都会多等这段起点差。改成只按相对时长换算：等待的 tick 数是剩余微秒除以 tick 周期向上取整再加 1（FreeRTOS 的第一个 tick 可能马上就到，加 1 保证不提前），不再用两个时钟的差；保留永久等待、0 不等和溢出处理。`unit-s31-osal-ticks` 加起点差的用例（起点差多少，结果都一样）。

## 边界
