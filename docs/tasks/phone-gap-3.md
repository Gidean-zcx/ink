# phone-gap-3：最后一次缺口检查（对照 R-068）

总规则先读 docs/tasks/codex-rules.md，第 7、8 节优先。报告写到 docs/tasks/phone-gap-3/REPORT.md。**只读代码、跑测试、写报告，不改代码。** 等这一阶段其余任务都合入后再做。

## 背景

R-068：系统层要达到“相当于一台什么应用都还没装的手机”。phone-gap-2（`docs/tasks/phone-gap-2/REPORT.md`）按领域打了 A、B、C，列出缺口，之后几批任务照它补。这一项是这一阶段的收尾检查，决定能不能停（完成界限见 `docs/tasks/backlog.md` 的“这一阶段的完成界限”）。

## 要做的

1. 照 phone-gap-2 的表，逐个领域重新打分：通话、短信、联系人、相机相册、时钟日历提醒、文件、设置、AI、多成员和孩子、锁屏和安全、网络、通知、语言、应用框架。每一格写证据：代码位置、测试名，有截图的给截图路径。
2. 凡是模拟器里能验证的，标“有”或“没有”。“没有”的，判断属于下面哪一类：
   - 上真机：烧录、驱动调试、真机性能；
   - 真实家庭中枢：真模型、听写、合成、账号、同步；
   - 真打电话、发短信（花钱）；
   - 以上都不是：这一类就是这一阶段还没做完的，单独列出来，标严重程度。
3. 和 phone-gap-2 比，列出这一阶段补上的项。
4. 检查每个新功能是否符合 AI 原生的要求：按钮能做的事都有能力，AI 能调；页面有快照；用户数据按成员隔离（R-061、G-002）。

## 验收

1. 报告的表覆盖全部领域，每一格都有证据。
2. “以上都不是”那一类，每一项写清严重程度和建议怎么补。
3. 不改代码。全量测试跑一遍，把原话写进报告。
