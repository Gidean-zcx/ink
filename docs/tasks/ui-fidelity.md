# ui-fidelity：和画板差得最多的页面，修到目标以内

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/ui-fidelity/REPORT.md。

## 背景

页面任务的目标是每屏与画板对照不超过 12/255（backlog 的 G4），有几页合入时超了：例如 factory-pages 的 FactoryReset、FactoryDone 是 51.6、27.6，kid-3 的 KidHome、KidToday、KidApps 也写着超标。别的页面没有统一量过。

## 要做的

预算：产品代码改动不超过 300 行（增删合计）。

1. 先量：对 `$INK_DESIGN/png/` 里每一张有对应页面的画板，用 `tools/ui_compare.py` 出分数，列成一张表（页面、分数、差在哪）。没有对应页面的画板单独列出来，不要动手做。
2. 再改：从分数最高的开始修，修到 12/255 以内，或者写清楚为什么到不了（例如内容是真实数据、画板是示例数据；画板和规范第 1 节冲突时以规范为准并记下来）。只改布局、字号、间距、图标、文字，不改行为；每页修完重新出分。
3. 规格只用规范第 1 节的；放大缩小时字、图标、间距、布局用同一个系数（ui-scale 的规则）。

## 边界

- 不改行为、能力和快照的内容（快照里的文字跟着屏幕文字变可以）。
- 同时在做的有 storage-order、fw-gaps、sound-clock（改 SetSound 和时钟）、phone-2（改通话页），这几页你不要改；navigation.c 里只改你修的页面。

## 验收

1. 报告里有全量分数表（修前、修后）【实测，模拟器】。
2. 修过的页面都在 12/255 以内，或者逐页写明原因；截图前后对比放在报告引用的位置（证据目录不进仓库的按总规则处理）。
3. 全量测试和内存检查通过；不放宽任何预算。
