## 要做的

1. **数据**：`phone.contacts` 记录从“一个号码”改成“多个号码，每个带标签”（手机、家里、工作、其他；照 Fossify 的号码类型），加收藏标记；记录版本加一，老记录读成“一个号码、标签为手机”。号码比较先规整（去空格、横线，`+86`、`0086` 前缀和不带前缀算同一个），不用“末 7 位相同”。
2. **对外接口不变**：电话和短信用的 `ink_contacts_match(query, exact, name, number)` 签名和含义不变（返回最匹配的那个号码）；`contacts.put` 仍接受老的 `number` 参数，同时接受新的号码列表；`contacts.select` 遇到多个号码时先让人选是哪一个（Fossify 的做法），再返回编号和号码。
3. **列表**：收藏的人在最上面一组，其余按姓名排（中文按拼音首字母，用系统已有的办法；没有就按现在的排序，写进报告）；顶上搜索框，按姓名、号码任意位置搜。
4. **详情页**（照 Fossify `ViewContactActivity`）：姓名下面先是动作——每个号码一行，写标签和号码，行上直接“打电话”“发短信”；然后备注；右上“收藏”和“编辑”。删除在编辑页里，写清动词“删除这位联系人”，照现有规则弹确认（找不回来的删除，D-105）。
5. **编辑页**：姓名、多个号码（加一个、删一个、改标签）、备注。用共用输入框；号码框用数字键盘。
6. **导入导出 vCard**（照 Fossify `VcfImporter`、`VcfExporter`）：从存储卡选一个 `.vcf` 文件（用系统文件选择器 F9），一个文件里多个人都能导入；认 `FN`、`N`、`TEL`（带 `TYPE`）、`NOTE`，常见编码（UTF-8、QUOTED-PRINTABLE）；号码已经存在的跳过并计数，同名不同号的当新联系人；导完给一页结果：“导入 12 位，跳过 3 个重复号码，2 条看不懂”。导出把当前家人的联系人写成一个 `.vcf` 到当前家人的空间。
7. Fossify 还有的邮箱、地址、生日、分组、头像：预算内放不下就不做，在报告里逐项列为“没做到的”，不许写成“不需要”。

## 验收

1. **照 Fossify 的参照路径走一遍**（模拟器脚本，每步截图并断言）：新建“测试甲”，两个号码（手机、工作）→ 收藏 → 回列表，他在收藏组 → 从电话拨号页输工作号的一部分能匹配到他 → 从短信“选联系人”点他，先问用哪个号码，选手机号 → 从联系人详情页点工作号旁边的“打电话”进电话 → 三个入口找到的是同一个人。同一条路径用能力调用（来源是 AI）走一遍，结果一样。
2. **导入**：导入一个含 5 个人的假 `.vcf`（其中 1 个号码已存在、1 条格式坏的）→ 结果页写“导入 3 位，跳过 1 个重复号码，1 条看不懂”→ 列表里多了 3 位，号码标签对。导出后再导入同一个文件，全部算重复。
3. **老数据**：老格式（一个号码）的记录读出来是一个“手机”号码；电话和短信的来电查名、号码匹配测试照过（`ink_contacts_match` 行为不变）。反向对照：号码规整去掉 `+86` 处理，带 `+86` 的匹配测试必须失败。
4. **家人隔离**：A 的联系人 B 看不到；孩子照现有规则。
5. **改前改后截图**：列表（有收藏）、详情、编辑、导入结果，默认和最大文字大小各一套。
6. 主工程普通全量 ctest 过（含 `ui-scale`）；ASan 跑联系人、电话短信的联系人匹配和 `ui-scene-*` 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告。报告写固件增量、产品代码行数、`gcccheck` 结果、改过的已有测试（只改定位方式和页面结构，不改业务断言）、改名或删除的能力。另写给 `notify-svc-1` 后续用的接口：怎么判断一个号码是不是“收藏的联系人”（勿扰例外要用）。
