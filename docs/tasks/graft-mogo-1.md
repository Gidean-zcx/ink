# graft-mogo-1：把 Mogo 的阅读整块搬进我们的系统（嫁接接口 + 新阅读第一版，先在模拟器跑通）

总规则先读 `docs/tasks/codex-rules.md`（第 9、10 节优先）和 `docs/tasks/vendor-common.md`（第 1～3、6、7 条；第 8 条不碰设备）。

## 为什么这么做

用户 2026-11-12 定的方向：“我们系统还是要自研的 我更接受你提出的移植完整应用嫁接和封装…到我们的系统中”；“后续也没有说要完全跟进他的更新 只是让你尽量复用 和参考成熟设计”；“mogo 感觉字体可能也太小了”。

所以：选最成熟的阅读应用 Mogo（`$INK_DEPS/../ink-hw/upstream/oss/mogo-e4p`，提交 `864f2f9`，v1.1.0，同一台 S31 硬件），把它的排版引擎、书库、阅读页、目录书签、阅读设置**整块**搬进来，不挑几个函数重写，也不自己重新设计流程；接到我们系统的底层服务上（嫁接），外面套我们的外壳、字号和 AI 能力（封装）。搬进来的代码就是我们的，可以直接改，**不跟 Mogo 上游更新**。

依据：`docs/tasks/replan-arch/REPORT.md`（乙方案：保留它的布局、绘制、排版和命中，适配运行循环、显示提交、存储、硬件和动作入口；刷新、语言、字号、AI、成员隔离各节必须照做）和 `docs/tasks/replan-arch/INTERFACES.md`；阅读排名见 `docs/tasks/replan-reader/REPORT.md` 和设计页（Mogo 排第一）。

## 要做的

1. **嫁接接口（通用，后面的传书、锁屏样式、音乐等都按它接）**：一个承载三方画面的活动，加一份小而稳定的 C 头文件（放 `system/graft/`，名字你定），说明每个函数的语义。至少包括：
   - 画面：三方往一块灰度缓冲里画，交出脏区和刷新意图（翻页、整屏、局部），经同一个 LVGL 合成（来电卡、确认卡、AI 面板、键盘在上面），再交 `display_service`，遵守 D-127（普通刷新不闪，按面积累计顺带 GC16）。现成的例子是远程网页页的灰度画面和浮层共存（`system/apps/remote/remote.c` 157–205、540–555 行附近）。不能让三方直接调屏幕 HAL，也不能在 UI 任务里等物理刷新完成。
   - 输入：触摸、按键、晃动翻页从我们的输入服务转给三方；系统手势（下拉通知栏、AI 键、电源键）先由外壳处理。
   - 文件和设置：三方的书、进度、书签、统计、偏好落在当前家人的空间（文件服务 `/me` 等，`system/include/ink/sys/file.h`）；它的 NVS 读写换成我们按家人的设置存储，不能只改一个根目录字符串。
   - 生命周期：打开、暂停（来电、AI 面板）、恢复、关闭；换家人时先关书、停后台工作、清全局状态，再给新家人打开。
   - 能力：三方的每个用户操作（打开书、翻页、跳章、加书签、改字号等）登记成能力（`system/include/ink/sys/cap.h`），按钮和 AI 调同一个入口；页面快照给出当前书、章、稳定位置、可见文字、当前面板。
   接口只放这几类必需的东西，别做成大框架；每个函数在头文件里写一句话的用途。
2. **新阅读第一版**：把 Mogo 的书库、阅读页、目录、书签、阅读设置（字号、行距、段距、边距、字重、缩进、页眉页脚）、TXT（UTF-8/GBK/UTF-16、自动分章）和 EPUB 搬进来，挂在嫁接接口上。代码放 `third_party/mogo/`（只放用到的文件，`SOURCE.md` 写来源提交、每个改过的文件和改动原因），我们的接线放 `apps/` 下的新应用。书架如果一次带不全，先保证“从书架或文件打开书→读→目录→书签→设置”这条路完整，报告写清缺什么。
3. **字号和外观按我们的来**：Mogo 界面尺寸（`main/ui/ui_kit.h` 的 `UI_PX_*`、行高、按钮高等）和阅读默认字号（`main/book/book_font_size.h`，默认 48、范围 18–90）统一经我们的缩放（`ink_ui_px()`，跟系统“文字大小”设置走：文字、图标、间距一起放大）；它的顶栏换成我们的状态栏，要打字的地方（搜书等）用我们的键盘，提示和确认用我们的弹窗。保留它的排版和点按区设计（九宫格翻页区等）。
4. **字体**：它用 stb_truetype 读 TTF，加内置位图汉字。用我们系统已有的字体文件（模拟器用 Noto Sans CJK）；不要往应用分区再塞一份大字库，报告写设备上字体放哪（存储卡或字库分区），以及要多少空间。
5. **和旧阅读并存**：新应用叫“新阅读”，和旧的阅读并排放在桌面上；旧阅读一行不改，等用户说换了再删。
6. **带上它自己的测试**：Mogo 的主机测试（`tools/*_host_test.*`）里覆盖搬过来那部分的（排版、TXT、EPUB、书签、书库），接进我们的 ctest。

## 范围和预算

- 只改：`third_party/mogo/`（新）、`system/graft/`（新）、`apps/` 下的新阅读（新）、桌面上加一个入口、CMake 里新目录的那几行、新测试、`docs/tasks/graft-mogo-1/`。不碰旧阅读、不碰别的任务在改的文件（`fixes-1112`、`hub-link-1`、`fw-size-2` 同时在跑）。
- 嫁接接口不超过 600 行；对 Mogo 原文的改动（不算原样拷贝的行）不超过 1500 行，超了先停下在报告里说明。
- 不改分区，不碰设备。

## 验收

1. 模拟器里：中文 TXT（UTF-8 和 GBK 各一本）和一本带目录、插图的 EPUB，能打开、前后翻 50 页、目录跳章、加书签、改字号后重排；截图放 `docs/tasks/graft-mogo-1/`（阅读页、目录、设置、书架；系统默认文字大小和最大一档各一套；单张不超过 300 KB）。能跑 Mogo 自己的渲染的话，同一页并排对比。
2. 来电卡、AI 面板盖在阅读页上再关掉，阅读页恢复原样；换家人后另一个人看不到前一个人的书、进度和书签。
3. 用能力调用（像 AI 那样）翻页、跳章、加书签，结果和按按钮一样。
4. 主工程普通全量 ctest 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告。报告写 S31 固件大小比改前多多少、模拟器里内部内存和 PSRAM 峰值、翻页耗时。应用分区放不下就写差多少、停在那里（`fw-size-2` 在并行腾空间），不能删功能、降字体或图片质量、改分区来凑。
