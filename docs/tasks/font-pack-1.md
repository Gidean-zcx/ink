# font-pack-1：字体分区快满了——字形无损压缩，腾出以后要加的字的地方；放不下时不再整套挤进程序区

总规则先读 `docs/tasks/codex-rules.md`（第 9、10、11 节优先）。

## 为什么

- `font_data` 分区 4,718,592 B，字体现在占 4,713,711 B：正文字体 `sans-44`（GB2312 全集，2 bpp）3,519,177 B；中等 `ui-1-36` 299,745 B、粗体 `ui-2-53` 655,678 B（各 963 个字）；6 个 Outfit 数字字体约 240 KB。只剩约 4.9 KB。
- 中等和粗体的字表是从 `system/ui`、`system/apps`、`apps`、`system/services`、`system/policy` 的 `.c` 和 `assets/i18n/*.tsv` 里扫出来的（`tools/fontgen/ui_fonts.py`），任何任务在代码里新写一个没用过的汉字，两套字体就各多一个字形。
- almanac-2 带进 8 个新字（宜忌民俗老黄北南），两套字体多 5,922 B，装不下。`tools/asset_pack.py` 的 `split()` 一旦有一个文件放不下，后面所有文件都进程序区的内嵌资源包，于是整套粗体进了程序镜像：镜像多 706,912 B，应用分区只剩 1%。第二波的音乐、电话、备忘、文件、相册、锁屏样式都会加新字，合并时都会撞上。
- 字体常驻映射在闪存里，不解压到 PSRAM（`asset_pack.py` 的注释、`system/text/ink_font.c`）。

## 要做的

1. **字形位图无损压缩**：`tools/fontgen/fontgen.py` 生成 INKF 时逐字形压缩位图（用版本号或标志位区分；方法自选，要求每个字形独立解码、解码快、不需要大缓冲，例如 2 bpp 像素的游程编码）。`system/text/ink_font.c` 读新旧两种格式；LVGL 取字形位图（`lv_get_bitmap`）和 `system/ui/theme.c` 里按比例缩放的回退路径都边解码边展开，不把整套字体解压到内存。确实需要时加一个有上限的小字形缓存，放 PSRAM。
2. **所有字体都用压缩格式**（正文、中等、粗体、数字），报告压缩前后的大小和 `font_data` 剩余。
3. **打包不再有断崖**：`split()` 里一个文件放不下时，后面放得下的照样进 `font_data`；最后有字体进了程序区内嵌包，构建要打印是哪几个、多大。
4. **正确性**：主机测试逐字形比较，每套字体的每个字形，压缩版解出来和原位图逐字节相同；已有的界面截图测试照旧全过（像素不变）。
5. **性能**：模拟器的代价计数（`glyph.blit`）照旧记；报告 S31 上每个字形解码的额外开销估算，用已有的性能测试（例如 perf-latency 系列）比较整页文字绘制，不许慢 5% 以上。

## 范围和预算

- 只改：`tools/fontgen/*.py`、`tools/asset_pack.py`、`system/text/ink_font.c` 和它的头文件、`system/ui/theme.c` 的字形回退那几行、确实需要时的 `hal_asset` 接口、相关测试、`docs/tasks/font-pack-1/`。
- 不改分区表，不改字号、字重和灰度：屏幕上的字一像素都不变，所以不需要上机看屏。
- 产品代码不超过 250 行（生成器和测试另计）。

## 验收

1. `font_data` 剩余至少 1 MB（实测写报告）；测试里临时加 50 个界面没用过的字，全部字体仍在 `font_data` 里，不进程序区。
2. 逐字形比较全过；主工程全量 ctest 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告，报告固件和应用分区剩余；gcccheck 过。
3. 反向对照：去掉解码（把压缩数据直接当位图），逐字形比较必须失败；把 `split()` 改回整串挤出，“加 50 个字”的测试必须失败。
4. 装机：报告装机和退回工具是否要跟着改（新固件读得了旧格式；退回旧试用版时 `font_data` 要换回旧的那份）。
