# voice-name-assist：改叫法（G3a），打字接话（G3b）

总规则先读 docs/tasks/codex-rules.md，第 7、8、9 节优先。报告写到 docs/tasks/voice-name-assist/REPORT.md。**只编译、跑宿主机测试，不碰设备。**

## 背景

最后一次缺口检查（`docs/tasks/phone-gap-3/REPORT.md` 的 G3a、G3b）。用户 2026-11-11：“都并行做吧，你自己按最合理的、工作量较小的方式来补齐这些”。设置页“语音和 AI”里这两行现在写着“暂不能更改”“暂不能设置”（`system/ui/shell/settings_pages.c` 约第 21、25 行）。语音前端在 `platform/include/ink/hal_afe.h`，现在只有一个固定的唤醒词；真实模型在中枢上，还没有。

## 要做的（取最小做法）

1. **改叫法**：语音前端报告它支持的唤醒词列表，设置项 `voice.name` 从这个列表里选（不支持自定义录入）；改了立刻生效。HAL 加列出和选择两个函数；模拟器的前端支持两三个名字并能按所选的触发；S31 没有语音前端，设置行照实写“这台设备暂不支持叫名字”。孩子不能改；AI 用 `settings.set` 改，和人共用。
2. **打字接话**：设置项“打字时帮你接话”（默认关，按成员）。打开且在线时，在普通文本框里停顿后，向中枢要 1～3 条接续（协议加一个方法，只发光标前最多 500 字和输入框类型），放进键盘候选条，用 AI 图标标出；点了插入，接着打字就作废。密码框、AI 不可见的框、孩子被禁用时都不发。模拟中枢给合成的接续；真实中枢没有模型时返回不可用，界面不报错。
3. 协议改动写进 `docs/hub/` 对应文档；真实中枢 `hub/` 里加最小桩，中枢测试照样通过。

预算：产品代码净增不超过 500 行。

## 验收

1. 测试覆盖：唤醒词选择后只认新名字、S31 显示不支持；接话的开关、停顿触发、插入、作废、密码框不发、离线不发、换人。每项有反向对照。
2. 模拟器全量测试和 ASan 版通过（中枢测试要建好中枢环境）；能力清单重新生成并 `--check` 通过；S31 能编过；gcccheck 通过；ui-scale 0 违规；隐私扫描。
3. 报告写清和设计的差别、截图路径。
