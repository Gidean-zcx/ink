# audit11-fix 复核（主会话，2026-11-10）

结论：**合入。** 两条都按任务书修在一处，测试有正反对照，没有改已有测试。

## 看了什么

- B11-01（`index_prune`）：只有 `hal_fs_exists` 明确返回 0 才删；返回 -1 时游标归零、本轮报读写错误，后台作业不再续排（`more` 要求 `!r`），完成标记不写、卡上“索引不全”标记保留。卡被拔出时模拟器的 `route()` 返回 `VOL_BAD`，`hal_fs_exists` 得 -1，所以拔卡途中一条都不删，比原来靠删除前再查一次卡在不在更稳。
- B11-02（`index_done`）：按目录扫描（`root` 非空）在所有根扫完后，只要清理还在做（`saving`）或这次扫描刚补齐最后一个根，就不算建好、不取消后台定时器，并排一次后台作业；索引早已建好时（`saving` 为假、之前就扫完）行为不变，所以平时查文件不会多出后台工作。后台作业走完最后一个根时也会排一次定时器，作业结束前的续排用同一个定时器，不会重复；清理出错后最多多跑一轮。
- 测试 `tests/audit11_fix/`：用包含 `file_service.c` 的边界文件把一次状态查询换成失败（只在所有根都扫完、清理进行中时触发一次），以及在清理批次之间经 AI 能力查空目录。打印结果的检查都带精度，脚本不用 git 历史。
