## 背景

用户 2026-11-12 下午：“外壳有很多我其实并不满意 希望你参考成熟设计完善一下”。之前的反馈（`docs/tasks/ui-feedback-4.md`）：“各种交互都不符合业界的设计”“大大小小的输入框”“我要求每个功能和页面都参考现代UI的设计审计”。评估标准：功能成熟度和使用体验，移植工作量和开源协议都不作限制；用户偏好乔布斯式的简洁（路径短、常用的一步到位）。

现在的外壳：规格在 `docs/product/system-ui-spec.md`（主页三屏加 Dock 是 D-60，保留大时钟是 D-106，这次可以给新方案让用户重选），代码在 `system/ui/shell/`、`system/ui/`，主题令牌在 `system/ui/ink/ui_theme.h`。现有页面截图：在本任务克隆里跑 `cmake -S . -B build && cmake --build build -j8 && ctest --test-dir build -R ui-scene` 之后在 `build/test-out/` 下（编不出来就读 `docs/product/system-ui-spec.md` 和代码描述）。主会话看过截图，问题举例：到处是粗边框、圆圈和胶囊，层次靠框不靠排版；“还没有……”“0 条通知”这类空状态占主要位置；控制中心没有常见的开关格；键盘按键大小不一；返回键、输入框、按钮样式多种。

设备：4.7 寸墨水屏触屏，竖屏 684×1216（约 297 dpi），黑白加灰阶，没有动画、尽量少刷新（D-127），触控目标不小于约 9 mm；用户是一家人（有老人和孩子），每个人有自己的空间；AI 键和 AI 面板是核心入口。

输入法、通知栏和控制中心、设置由 `frameworks-research-1` 调研，本任务不重复，只在需要和它们统一的地方写一句。

## 要回答的

1. **设计语言**：墨水屏和黑白界面里最成熟的一套做法是什么——字号层次、行高、分隔线还是边框、按钮的几种样式、输入框、开关、滑杆、分段选择、卡片、页码指示、图标风格、空状态、按下反馈。候选至少看：Kindle、文石 BOOX、掌阅 iReader、Kobo、reMarkable、Mudita Kompakt 和 MuditaOS、Light Phone III、PebbleOS（黑白界面）、海信墨水屏手机，加 iOS HIG 和 Material 3 在黑白高对比下的做法。给出一套具体到像素（684×1216 画布）的建议，并对照我们现在的 `ui_theme.h` 写清改哪些令牌。
2. **主屏、今日、全部应用、Dock**：给 2～3 个成熟方案（例如图标网格加小组件，iOS/HarmonyOS；列表式启动器，Light Phone/Mudita Kompakt；阅读优先，Kindle/BOOX），各自的结构、截图出处、适合我们这家人的理由和缺点。
3. **状态栏、锁屏和待机**：通行布局；锁屏上时间、通知、紧急呼叫、相机的处理；没有通知时怎么显示。
4. **返回、主页、正在做的事（多任务）、搜索、换家人、电源菜单、首次开机**：成熟系统怎么做，哪些我们缺。
5. **对话框、确认卡、底部面板、提示条**：iOS 和 Material 的规格怎么搬到墨水屏；AI 面板参考豆包、Gemini、Siri 的底部面板和页面上下文的做法。
6. 每一项写：推荐的成熟设计、能直接搬的代码（有的话：AOSP、MuditaOS、PebbleOS、InfiniTime、ESP-Brookesia 等，写文件和行号）、要我们保留的东西（家人隔离、AI 能力、确认卡规则 D-105、少刷新）、建议的改动顺序（先改哪项全系统见效最大）。
