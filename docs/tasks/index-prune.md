# index-prune：清掉索引里已经不存在的文件的旧记录

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/index-prune/REPORT.md。

## 背景

文件索引上限 1024 条。电脑在存储卡上删掉或改名的文件（以及别的设备外的改动），重扫时新路径会拿到新记录（改名能认出来的沿用原编号），但旧路径的记录一直留着：index-cost 和 batch9 审计都测到卡上 1000 个文件时索引已有 1010 条。旧记录白占上限，时间长了会让新文件拿不到编号（`INDEX_FULL`）。

## 要做的

预算：产品代码改动不超过 100 行（增删合计），集中在 system/services/file/file_service.c。

1. 一次完整重扫结束、确认这张卡上所有根目录都扫完以后，删掉这张卡上路径已经不存在、而且没有被认作改名的记录。只在扫描完整时做（中途拔卡、换卡、被打断的扫描不删）。
2. 被删的编号不复用（沿用现有规则）；相关的缩略图缓存一并失效。
3. 删除走现有的批量和落盘方式（不要逐条同步等待），和 index-compact 的变长记录、index-durable 的卡上标记配合。

## 边界

- 不改索引上限、记录格式和存储服务。
- 同时在做的有 confirm-hooks 和稍后 batch10 审计的修复，只改各自的文件。

## 验收

1. 测试：电脑删掉 20 个、改名 5 个文件后归还，扫描完成后索引条数等于卡上实际文件数，改名的保留原编号，删掉的旧编号查不到；扫描中途拔卡时一条都不删。
2. 测试：索引满了以后，电脑删掉一批文件再归还，新文件能重新拿到编号。
3. 全量测试和内存检查通过；S31 能编过。
