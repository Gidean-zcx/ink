# index-durable：文件改动后马上断电，索引统计和编号也不出错，而且不拖慢文件操作

总规则先读 docs/tasks/codex-rules.md，第 7 节优先。报告写到 docs/tasks/index-durable/REPORT.md。

## 背景

batch5 审计的 B5-02（docs/audits/batch5/report.md）：建好整卡索引后新建或改名一个文件，成功返回后马上断电，重启时旧的“建好”标记仍被当成有效，于是新文件没有编号、`file.usage` 是旧数，改名的文件用原编号找不到。

audit5-fix 的修法是在文件操作里同步等落盘，已撤回，原因见 docs/tasks/audit5-fix/REVIEW.md：界面在动时每次内部闪存写盘都要等墨水屏空闲，最多约 1.75 秒，拿着文件服务的编辑锁等会卡住所有文件操作，`files-app` 因此超时。

## 要做的

预算：产品代码改动不超过 200 行（增删合计）。

1. **新文件**：不要让文件操作等内部闪存。可行的做法之一：建好以后的第一次改动，在存储卡上同步写一个很小的“索引不全”标记（卡上的写不走内部闪存的队列，也不等墨水屏）；开机时看到这个标记就不信旧的完成记录，补建；下次建好、完成记录落盘以后再删掉标记。也可以用别的办法，但不能在编辑锁里等内部闪存。
2. **改名**：重启以后原编号仍指向新路径。不要在文件操作里同步等落盘。可以考虑重扫时认出改名：旧路径已不存在，新路径的大小和修改时间与旧记录一致，就沿用旧编号（这样电脑上改的名也能认出来）；这需要在索引记录里加大小和修改时间，记录格式要升级并处理旧记录。也可以用别的办法，写清取舍。
3. 重新注册 `audit5-b5-02`（tests/audit5_fix/device.c 的 index 场景，在 CMakeLists.txt 的 audit5 那一段），它按原样通过。

## 边界

- 不改存储服务的写盘顺序（storage-order 刚定的），不改刷新算法（D-110）。
- 不能为了通过而放宽 `files-app` 或别的测试的时限。

## 验收

1. `audit5-b5-02` 通过：新建、改名后立刻断电，重启后新文件有编号、统计是新数，改名后原编号指向新路径。
2. 新增计量：界面在动时（例如连续翻页、切换页面）新建、改名、删除文件的耗时，和改动前比不多于 100 ms【实测，模拟器】。
3. 全量测试和内存检查通过；S31 能编过。
