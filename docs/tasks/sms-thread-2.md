# sms-thread-2：短信会话页一页放多条气泡，最新的在底部

总规则先读 `docs/tasks/codex-rules.md`（第 9、10 节优先）和 `docs/tasks/vendor-common.md` 第 11 条。

`comm-ux-2` 合入后，会话页每页只显示一条消息（`system/apps/sms/sms.c` 里会话列表 `thread ? 1 : SMS_ROWS`），一条短短信下面是大片空白，翻页条在页面中间（见 `docs/tasks/comm-ux-2/after-sms-thread.png`）。这不符合现代聊天界面（微信、iMessage、Android 信息）：

## 要做的

1. 会话页按气泡实际高度从下往上排，**一页尽量放满**：最新一条贴近底部输入栏，往上是更早的；收发左右对齐照旧；连续几条同一方向且时间相近的只在第一条上方显示时间（超过 5 分钟再显示一次），“已发出／发送失败，未发出（点按重发）／结果未知”这些状态放在自己发出的那条气泡下方的小字里。
2. 往上翻看更早的消息用翻页（墨水屏不做惯性滚动）：翻页按钮放在页面顶部或用上下滑动，不放在页面中间；打开会话默认在最新一页。超长的单条短信照现在的办法分页。
3. 页面快照列出这一页可见的每条消息（方向、时间、状态、正文），AI 能力 `sms.thread`、`sms.prev`、`sms.next`、`sms.retry` 照旧，和页面一致。
4. 墨水屏少刷新（D-127）：发出一条新消息只刷新底部变化的区域，不整页重刷（报告写清实际刷新区域）。

## 范围和预算

- 只改：`system/apps/sms/sms.c`、`tests/sms/sms.c`、`tests/comm_ux2/` 里会话页相关的断言和截图、`docs/tasks/sms-thread-2/`。不改 `textfield.c`（`textfield-1` 在改）、`keyboard.c`、通信服务。
- 产品代码净增不超过 150 行；不新增机制。

## 验收

1. 截图：1 条、5 条、20 条（含收发混合、发送失败、长短信）的会话页，常规和 120% 字号（`docs/tasks/sms-thread-2/`，单张不超过 300 KB）。
2. 测试：一页放下多条、最新在底部、翻到更早一页再回来、重发、快照和页面一致；反向对照（改回每页一条测试必须失败）。
3. 主工程普通全量 ctest 过。
