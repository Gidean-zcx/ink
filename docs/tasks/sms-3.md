## 要做的

1. **会话列表**：每个会话一行——对方（有联系人名字就显示名字）、最后一条的开头、时间、未读标记；有草稿的写“草稿：……”。顶上搜索框，搜全部短信正文和对方，结果点进去定位到那一条。
2. **会话页**（照 Fossify `ThreadActivity`）：上面是消息，底部是编辑区（共用输入框 + “发送”主按钮），在会话里直接回，不跳到另一页；长文点开现有的长文编辑页（`ImeLong`）。离开会话自动存草稿，回来还在；每位家人的草稿分开。
3. **分段提示**：边打字边显示“第 1 条，还能打 23 字”，超过一条显示“共 2 条”（中文短信一条 70 字、拼接后每条 67 字；现有的分段计费提示照旧）。
4. **状态**（对照 Lineage 的分法，用文字不靠颜色）：草稿、发送中、已发出、未发出、结果未知、长短信“共 3 条：前 2 条已发出……”（服务给的原话照显示）。
   - **明确未发出**的那条，消息下面给“重新编辑”和“重发”（照 Fossify：针对原来那条；重发成功后会话里只剩一条这段话、状态是“已发出”——先看 Fossify 是更新原条还是删掉原条再发，照它做；短信服务做不到就写进报告，不改服务）；
   - **结果未知**的那条：只给“先核实”的说明和人工“再发一次”（人自己点才发，点之前写清可能重复）；**绝不自动重发**，AI 也不能替人重发。
   - “已送达”要模组的送达报告，短信服务现在没有；**本任务不加**，写进报告“要用户定”（要动模组的短信参数，碰 CLAUDE.md 的“不改模组配置”）。
5. **删除**：长按一条或在会话菜单里删一条、删整个会话；照现有删除规则（能撤销就给撤销，找不回来的才确认，D-105）。
6. Fossify 还有的定时发送、归档、拦截号码：预算内放不下就不做，在报告里逐项列为“没做到的”，不许写成“不需要”。

## 验收

1. **照 Fossify 的参照路径走一遍**（模拟器脚本，每步截图并断言）：写新短信给一个没存的号码 → 打一段 150 字的中文 → 分段提示从“第 1 条”变成“共 3 条” → 离开再回来，草稿还在，列表上写“草稿：……” → 让模拟器的模组明确发送失败 → 原消息下面出现“重新编辑”“重发” → 点“重发” → 成功后会话里只剩一条这段话、状态是“已发出”。另走一条：让模组回“结果未知” → 页面写“结果未知，请先核实”，没有自动重发（模组只收到一次发送，断言次数）→ 人点“再发一次”才再发。同一条路径用能力调用走一遍：AI 不能触发结果未知那条的重发。反向对照：把结果未知当失败自动重发，次数断言必须失败。
2. **搜索**：搜一个词，结果列出含它的消息，点进去定位到那一条。
3. **家人隔离**：A 的会话和草稿 B 看不到。
4. **改前改后截图**：会话列表（有草稿、有未读）、会话页（有发出、失败、结果未知三种状态）、分段提示、搜索结果，默认和最大文字大小各一套。
5. 主工程普通全量 ctest 过（含 `ui-scale`）；ASan 跑短信相关测试和 `ui-scene-*` 过；S31 宿主机测试过；`ports/esp32s31/build.sh` 编译通过、无新警告。报告写固件增量、产品代码行数、`gcccheck` 结果、改过的已有测试（只改定位方式和页面结构，不改业务断言）、改名或删除的能力、需要短信服务配合的地方。
