# audit13-fix：修 batch13 审计的 4 条中级和 7 条低级

通用规矩：`ink-codex/briefs/subagent-rules.md`（仓库外，和仓库同级的工作目录）。

审计报告是 `docs/audits/batch13/report.md`，先读它。每条中级配一个测试（修之前失败、修之后通过）；低级的能测就测，不能测的写清怎么核对。产品代码净增不超过 200 行。

## 要修的

按报告逐条修：
1. 中 1 天气页第 3 天的快照标题（`texts` 不够用）。
2. 中 2 待整理的语音备忘先被手写过、转写回来会盖掉：pending 的备忘不进编辑页（转到 PENDING 页），填字时正文不空就接在后面，两样都做。
3. 中 3 转写失败的重传：本次开机内记下失败过的 id，重试间隔逐步拉长（写清取值）；转写成功但文字为空当作完成，填一句占位说明（例如“这段录音里没听到说话”）。测试覆盖写库失败和空文字两种。
4. 中 4 后台执行器上同步打开成员数据集合：mutate 和 play 改成不在 BG 上同步打开（用 `ink_app_db_open_async`，或先试 cached、不在缓存就如实回“稍后”）；sweep 先收集已有 audio id 再比对文件。测试：在会触发的场景下文件列表能读完（参考 memo-record 报告里 files-app 那次）。
5. 低 5～11：`audio.transcribe` 卡住时清掉、`REC.why` 加锁且 cancelled 不被覆盖、`via` 转调后补登记撤销（或在能力表写明，选你认为对的并说明理由）、`memo.voice` path 判空、备份服务先结束任务再改状态（像 update-flake 那样加一个能稳定复现的测试）、S31 串口超长行返回错误并计数（上限改到能放下 UCS2 的整条短信）、`memo.c` 宏改名。

## 边界

只修这十一条，不顺手重构。同时在做的有 sms-multipart（通信服务、短信），不要改那一块。

## 验收

1. 中级四条各有测试，修之前失败、修之后通过（报告写清测试名）。
2. 全量测试和内存检查通过；S31 能编过；中枢测试不受影响。
3. 报告逐条写：改了什么、测试、还有没有没做到的。
