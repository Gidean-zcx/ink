# ui-audit-2：每个功能和页面对照现代 UI/UX 的设计审计（只审，不改代码）

总规则先读 docs/tasks/codex-rules.md，再读 `docs/tasks/ui-feedback-4.md`（用户原话和共同设计基准）。**只审计、不改产品代码和测试**，不跑全量测试和 ASan（报告里写一句）。报告写到 `docs/tasks/ui-audit-2/REPORT.md`，边审边写、分段提交（中途被打断不丢结果）。

## 要做的

1. 逐个审每个页面和流程：外壳（主屏、今天、应用列表、锁屏、控制中心、通知、成员门和密码、电源菜单）、设置的每一页、键盘和输入法的每种状态、所有输入框和表单、确认卡、AI 面板和 AI 记录、电话（拨号、通话中、来电、通话记录）、短信（会话列表、会话、新建）、联系人（列表、详情、新建编辑）、时钟（闹钟、计时器、秒表、世界时钟）、日历和提醒、备忘、文件、相册、相机和扫码、天气、计算器、阅读（书架、阅读页、阅读设置）、远程、备份和传文件、家人和孩子。截图在 `$INK_DESIGN/shots-20261111/`；不够的页面读对应源码（`system/apps/*`、`system/ui/shell/*`、`apps/*`），必要时可以用模拟器补截图（允许编译主工程，只在你的克隆里）。
2. 每个页面写：现在的样子（截图文件名）、和业界做法的差距（具体到哪个控件、哪一步，说明业界通常怎么做、举一个参照，比如“iOS 信息的新建页：收件人一行可直接输号码或搜联系人，正文输入条在底部”）、严重度（高：用户完成不了或明显别扭；中；低）、改法（布局、控件、尺寸用哪个主题令牌、流程几步）。
3. 汇总一份**统一组件规格**：按钮（主次两种）、列表行、输入框（单行、多行正文、搜索、密码）、分段选择、开关、底部操作条、页头（标题加返回）、空状态、键盘（按行统一键宽、功能键宽度、语音键的大小和位置、中英切换），每种给出尺寸和用哪个令牌，标出现在哪些页面不合规。
4. 汇总**流程问题**：完成一件常见事要几步，业界几步（发短信、新建联系人、打电话给某人、设闹钟、设计时器、拍照、连 Wi-Fi、找一本书接着读）。
5. 最后给**改造任务拆分建议**：按页面或模块分成每个约 1 小时的 Codex 任务，写清每个任务改哪些文件、不和别的任务改同一个文件（键盘和输入框组件、短信联系人电话两组已经在改，见 `ui-input-2`、`comm-ux-2`，不要重复拆）。

## 验收

1. 每个页面和流程都有一条，带截图名或源码出处和严重度；有统一组件规格、流程表、拆分建议。
2. 只新增 `docs/tasks/ui-audit-2/` 下的文件（截图可以放这里，单张不超过 300 KB，总共不超过 15 MB）。
