# ui-borders：灰底改成白底细边框

总规则先读 docs/tasks/codex-rules.md，第 7、8 节优先。报告写到 docs/tasks/ui-borders/REPORT.md。**只编译、跑宿主机测试，不碰设备。**

## 背景

用户 2026-11-11 在真机试用后说：“我感觉灰色底在真机上非常难看，看看是不是还是改成边框算了”，随后定了“灰底改边框要搞，间距在改为边框再说”。

- 主题（`system/ui/theme.c`、`system/ui/ink/ui_theme.h`）有三种底：`INK_SURFACE_WHITE`、`INK_SURFACE_STATIC`（中灰 `0x888888`，`ink_ui_gray()`，约 52 处）、`INK_SURFACE_BLACK`。次要文字早已是黑色（靠字号区分）。
- 真机用自研刷新算法（D-110），中灰靠 2×2 细点表现，看起来是一片麻点，而且比黑白刷得慢。
- `theme.c` 里还有按“父对象是灰底”判断分隔线的逻辑（约第 361 行）。

## 要做的

1. 灰底一律改成白底加黑色细边框（宽度用主题的 `INK_STROKE`，圆角照原来的），在主题里集中改，不逐页打补丁。黑底不变。
2. 依赖灰底的判断（分隔线等）改成按底的种类判断，不再比颜色。
3. 不出现边框叠边框：卡片里套的格子、列表组里的分隔线、贴着屏幕边的块，逐一看过；有冲突时按“外面一圈边框、里面用分隔线”处理，写进报告。
4. 全部页面在模拟器里截图检查（主页三页、全部应用、设置各页、文件、短信、电话、相机相册、时钟、日历、AI 面板、确认卡、电源菜单、锁屏、成员门、孩子页面），报告附截图路径；挑最典型的 6 张给前后对比。
5. 改界面规范里关于灰底的描述（`docs/product/system-ui-spec.md` 和 `docs/product/` 下相关文件），写清边框的规则。
6. 间距不在这次范围：用户说改完边框再说。

预算：产品代码净增不超过 200 行。

## 验收

1. 模拟器全量测试和 ASan 版通过（截图类测试的期望按新样子更新，报告逐条写清改了哪些期望、为什么）；ui-scale 0 违规；S31 能编过；gcccheck 通过；隐私扫描。
2. 反向对照：把一处改回灰底，对应的检查要失败。
3. 报告列出所有用到灰底的地方和改法、截图路径、规范改动。
