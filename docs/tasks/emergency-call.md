# emergency-call：锁屏不解锁、飞行模式下也能拨紧急电话

总规则先读 docs/tasks/codex-rules.md，第 7、8、9 节优先。报告写到 docs/tasks/emergency-call/REPORT.md。要等 sms-multipart-2 合入后再开始，两个任务都改通信服务和 NT26 模型。

## 背景

D-119 定了：锁屏时不用解锁、飞行模式下，都能拨 110、120、119（112 也加上）。电话应用在 `system/apps/phone/phone.c`，通信服务在 `system/services/comm/comm_service.c`，飞行模式由 airplane-mode 任务实现（设置 `net.airplane`），锁屏在 `system/ui/shell/` 下。

## 要做的

预算：产品代码不超过 250 行。

1. **锁屏入口**：锁屏页加“紧急呼叫”。点进去是一个只能拨紧急号码的拨号页：数字键盘，下面列出 110、120、119、112 四个按钮。
   - 不用解锁，也看不到联系人、通话记录和其他任何家庭数据；
   - 拨号键只接受这四个号码，别的号码提示“锁屏时只能拨紧急电话”；
   - 挂断后回到锁屏，仍然是锁着的。
2. **飞行模式**：拨紧急号码时，临时打开模组的射频；通话结束后恢复飞行模式（设置值一直不变）。没有 SIM 卡时也照样拨，模组支不支持只能上机确认，写进清单。
3. **能力**：`phone.emergency {number}`。号码只能是这四个之一，锁屏时也能用，孩子也能用。这是人亲口要求的紧急动作，不弹确认卡，并且要说明为什么不受“打电话要确认”的规矩约束。AI 能不能调它，写进报告的“要用户定”，先选保守的做法：AI 不能自己拨，只能把拨号页打开。
4. 模拟器的 NT26 模型：支持拨紧急号码，飞行模式下拨号时射频的开和关都能观察到（只模拟硬件行为）。
5. 中英文都要有。

## 验收

1. 测试要覆盖：
   - 锁屏 → 紧急呼叫 → 拨 120：拨出去了，通话中看不到任何家庭数据，挂断后回到锁屏，仍然锁着；
   - 锁屏时拨普通号码被拒；
   - 飞行模式下拨 110：射频临时打开，挂断后飞行模式恢复，设置值一直没变；
   - 孩子在锁屏时也能拨；
   - 快照里没有家庭数据。
2. 原有电话、锁屏、飞行模式的测试照原样通过；全量测试和内存检查通过；S31 能编过；gcccheck 通过。
3. “上机要核对的”：NT26 拨紧急号码的命令、没有 SIM 卡时能不能拨、飞行模式（`CFUN=4`）下怎么临时打开射频。上机时**绝不真的拨紧急号码**：只做只读查询，或者拨用户指定的普通号码来代替，花钱的事要用户同意。
