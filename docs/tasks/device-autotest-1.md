# device-autotest-1：测试版固件开机后按脚本自己操作（真机无人值守验证）

总规则先读 `docs/tasks/codex-rules.md`（第 9、10 节优先）。

背景：用户没空操作设备（“我应该也没有空配合你操作和观察 你先把能自己做的都做了就行”），主会话只能看开机日志，触摸、打开应用、相机取景帧率、阅读翻页、打字这些在真机上验证不了。模拟器已经有成熟的场景脚本（`simulator/runtime/script.c`，`tests/*/*.script`：`@1s tap 50% 80%`、`swipe`、`key`、`note`、`end` 等）。本任务让**测试版**固件也能跑同样格式的脚本，主会话装测试版、跑、拉日志，再装回正常版。

## 要做的

1. **只在测试版里有**：新的构建开关（例如 CMake 选项 `INK_AUTOTEST` 和固件 Kconfig 或 `build.sh` 参数），默认关；开的时候把一个脚本文件在编译时嵌进镜像（`INK_AUTOTEST_SCRIPT=<路径>`）。关的时候不编进任何代码，正常版二进制不变（报告给出开和关两种固件的大小）。
2. **脚本执行**：开机系统起来后（主页显示以后）按时间执行。复用 `script.c` 的解析（把解析部分拆成模拟器和设备共用的文件，模拟器行为不变），设备上支持这些动词：`tap`、`longpress`、`press`/`move`/`release`、`swipe`、`key`、`note`/`mark`（写进日志）、`end`；再加一个 `cap <能力名> <JSON 参数>`（直接调能力，例如 `cap app.open {"id":"camera"}`，走 `ink_cap_invoke`，来源标成测试），模拟器里也支持它。模拟器专用的环境动词（电量、网络、麦克风、SIM 卡、来短信等）在设备上报错跳过。
3. **注入点**：触摸和按键在系统输入层注入（模拟器和设备共用的那一层，进入和真实触摸同一个队列），不改 S31 触摸驱动；坐标用逻辑坐标，和模拟器脚本一致。
4. **安全**：测试脚本不能做花钱、发出、删除和身份类的事：`cap` 拒绝发短信、打电话（紧急呼叫也拒绝）、删除文件和成员、恢复出厂、改密码、付费服务等（列一个拒绝清单，对能力表里风险等级高的一律拒绝），点屏幕触发这些时同样由现有确认和策略挡住；日志里不出现隐私内容。
5. **结果**：每一步执行时打一行日志（`autotest: <行号> <动词> ...`），结束时打总结（执行了几步、跳过几步、用时）；系统已有的刷新耗时、帧时间日志照旧。
6. 给三个现成的设备脚本放在 `tools/device/autotest/`：开相机取景 20 秒再退出；打开阅读器翻 20 页再退出；打开备忘录用键盘打一段字再删掉。坐标用百分比，配合 `docs/` 里现有的页面布局。

## 范围和预算

- 只改：`simulator/runtime/script.c`（拆出共用解析）、新增的共用解析文件和设备端执行文件（放 `system/` 下合适位置）、`CMakeLists.txt` 和固件 `ports/esp32s31/main/CMakeLists.txt`、`ports/esp32s31/build.sh`（加开关）、新增测试、`tools/device/autotest/`、`docs/tasks/device-autotest-1/`。不碰别的任务在改的文件（阅读器、键盘、输入框、短信电话、锁屏、设置页、4G、电源、蓝牙、相机）。
- 新增不超过 400 行；设备上执行用现有执行器或一个低优先级的短命任务（脚本跑完就退出），写明栈大小。

## 验收

1. 宿主机测试：模拟器原有脚本测试全部照样过（解析拆分不改变行为）；`cap` 动词在模拟器里能打开应用；拒绝清单里的能力被拒绝并记日志；开关关闭时设备端代码不编进去（加一个检查）。
2. 主工程普通全量 ctest 过；`ports/esp32s31/build.sh` 正常版和测试版都能编过、无新警告。
3. 报告写清怎么编测试版、怎么用 `tools/device/trial_run.py` 装上跑、看哪些日志行。
