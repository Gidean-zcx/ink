# 常见任务的路径对照

【估算】本表从基线源码和已导出画面重建，不是本次点击实验或计时实验。统一把“打开一页／作一次选择／填一组字段并提交／最终执行”各计一个任务阶段；输入字符数不计。另列点按代价时，**不计文字数字键，但计点字段、完成、保存**。这样不会把“建联系人再发短信”藏在一个阶段里。起点都写在表内，已唤醒且已验证成员、网络条件满足，不计系统启动和密码步骤。

“业界几步”指所引官方流程在给定前提下的示例，不是所有手机版本、用户和路径的统计值；统一目标是本次改造建议。

| 任务／起点 | 基线现在的路径与代价 | 业界示例与代价 | 差距／建议目标 | 证据 |
| --- | --- | --- | --- | --- |
| 发给没保存的号码／短信列表 | **不能直接完成**。写短信→只列联系人；空时要求先添加联系人。退出后另建联系人再回来，多绕一整个管理流程 | 新建→收件人直接输号码→写正文发送，3阶段；无需建联系人 | **高**。同页号码＋正文，3阶段；号码有格式也由通信层规整。交 `comm-ux-2` | `sms.c:178–206`、[Apple信息](https://support.apple.com/en-euro/guide/iphone/iph82fb73ba3/ios) |
| 回复已有号码／会话页 | 回复短信→新建页→点正文输入并完成→发送，至少3阶段（进入编辑、输入提交、发送），且离开消息上下文 | 会话底部输入正文→发送，2阶段（输入、发送），留在会话 | **高**。底部输入条+旁边发送，2阶段；不再分短/长短信 | M11–M13、同上官方信息流程 |
| 新建联系人／应用列表 | 电话→联系人→添加联系人，**3次导航到表单**；再填姓名/号码→保存 | 联系人→新建，**2次导航到表单**；再填资料→完成 | **高**。独立应用，2步到表单；完整创建4阶段（含开应用）。交通信任务 | `contacts.c:156–205`、[Apple通讯录](https://support.apple.com/guide/iphone/add-and-use-contact-information-iph3e0ca2db/ios) |
| 给已存的单一号码联系人打电话／电话首页 | 联系人→点某人（编辑页）→选择这个号码（回拨号盘）→拨号，**4次导航/执行点按**；无搜索还要翻页 | 经典电话布局：联系人→某人→呼叫，约3次，多个号码再选一次。独立通讯录已打开时为某人→呼叫两次 | **高**。电话内3次，已开联系人时2次；详情直接呼叫，支持搜索，不经编辑/选号回退 | `phone.c:185–187,243`、`contacts.c:190–220`、[Apple电话](https://support.apple.com/guide/iphone/make-a-call-iph3c993cbc/26/ios/26) |
| 设一次07:30闹钟／时钟闹钟列表 | 添加→时间→保存，表面3阶段；但以截图默认07:00为前提，分+30次，加添加/保存，**至少32次点按**。名称、重复另计 | 添加→直接选/输07:30→保存，同为3阶段；数值键盘示例约4次非数字键点按（添加、时间字段、完成、保存） | **高**。阶段不必减少，消掉逐分钟调整；自选重复≤一次进入选择、一次返回 | L03–L05，`clock.c:151–181`、[HIG Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers) |
| 设置5分钟计时／时钟闹钟列表 | 计时→5分钟→开始，**3阶段**，此预设路径没有多余步骤 | 计时器→设5分钟→开始，3阶段；点最近预设可能更少 | **低（路径）**。保留预设；运行显示问题单独修 | `clock.c:274–299`、[Apple计时器](https://support.apple.com/en-az/guide/clock-mac/apdw3d5aebf9/mac) |
| 设置45秒计时／同起点 | **UI不能完成**，只有分钟预设；能力 `clock.timer_set` 已接收1～86400秒；即使AI设45秒，画面仍显示1分钟 | 计时器→设时/分/秒→开始，3阶段 | **高**。增加秒输入并显示 `mm:ss`；页面可见时只更新数字区域，不新增计时线程 | `clock.c:277,287–291,498`、[Apple自定义计时器](https://support.apple.com/en-in/guide/watch/apdf448955b2/watchos) |
| 拍照／主屏，成员已验证 | 相机→快门，**2次点按**。步骤已短；预览固定3000ms一次（实现），移动目标难对准（设计判断） | 相机→快门，2次；通常可连续看取景 | **高（体验）**。保留2步，优化取景反馈；3秒是源码间隔，不是测得的端到端延迟或实际fps | `camera.c:102–106,128–135`、[Apple相机](https://support.apple.com/guide/iphone/take-great-photos-and-videos-iph9bbc8619e/27/ios/27) |
| 连新Wi-Fi／设置首页，Wi-Fi已开 | 网络和SIM卡→找附近→翻至结果→选网络→输入密码并完成，**5阶段起**；目标在后组再加翻组步骤。列表位于一批设置之后，页数随字号/状态变，此数为常规首个结果估算 | Wi-Fi→选网络→输入密码加入，**3阶段**；扫描通常随进入列表发生 | **高**。网络页立即展示/手动找网的同页列表，保留手动刷新但不要求先穿过SIM/设备加入；约3～4阶段 | `navigation.c:1420–1520`、[Apple连Wi-Fi](https://support.apple.com/en-ca/111107) |
| 找指定书并打开／主屏 | 阅读→点当前可见书，**2次导航**；书多、书不在屏内时缺书架搜索/明确分页，不能给出可靠上限 | 书库→点书，2次；需要查找时书库搜索→结果→打开，多约1～2阶段 | **中/高**。先补可见分页/最近读过，不能用“只有几本测试书”代表真实书库可用 | B01–B02、[BOOX书库](https://booxsupport.zendesk.com/hc/en-us/articles/10701497927316-Choose-a-Book-Display-Mode) |
| 接着读上次的书／主屏，有有效记录 | 点继续读，**1次**；会带回页码；无有效记录时提示不够可行动 | Kindle/BOOX最近阅读入口点书或继续读，常为1次 | **低（已有路径）**。保留一步恢复；只改空态“选一本书”，不强行先经过书架 | `reader.c:216–232,642–648`、[Kindle指南：阅读与导航](https://d1ergij2b6wmg5.cloudfront.net/kug/kindle_scribe_2024/v1/en-US/html/kug.html) |

## 连贯性问题

| 问题 | 具体断点 | 建议 |
| --- | --- | --- |
| 返回原任务 | 短信回复跳新页，联系人选择回拨号盘；恢复完成却回未生效主页 | 原页面就地完成输入/执行；确需验证时，验证后回到原对象/原位置 |
| 结果粒度 | 取景更新≠照片保存；草稿保存≠备忘保存；请求已发≠收件人收到；收文件≠书可读；服务器收到≠备份持久完成 | 每个UI状态绑定既有结构化回执，不新增一套页面自己的成功状态机；不确定不自动重试 |
| 可发现性 | 联系人藏电话里；忘掉蓝牙靠长按；日期时间靠±；孩子时段跨多页 | 独立应用/明确详情/直接数值选择；把一次任务放在一页或一个连续选择层 |
| 墨水屏适配 | 采用少刷新不应变成计时器无法精确设秒、相机难对准；扫码正文仍连续滚动 | 保留现代任务语义，局部数字刷新、静态分页、明确忙状态；频率需硬件证据，不任意设fps |
| AI与触控一致 | 新布局不能只换按钮：收件人、输入目标、相机对象、所选家人都需同步快照 | 原子能力不改语义；页面字段、对象版本、动作启用状态与画面一并验收，凭据及本人确认例外保留 |
