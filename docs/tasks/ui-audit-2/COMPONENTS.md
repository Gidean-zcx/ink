# 统一组件规格建议

这是本次审计的改法，尚未修改代码或设计合同。基准为 [ui-feedback-4](../ui-feedback-4.md)、[界面规范](../../product/system-ui-spec.md) 和 [主题令牌](../../../system/ui/ink/ui_theme.h)。编号 C01～C13 供逐页表引用。尺寸都是 Plus 的 684×1216 逻辑像素；宿主窗口用 `ink_ui_px` 换算，不把 iOS 的 pt 或 Android 的 dp 当本机像素。

## 共用规则

- 横向边距 `INK_MARGIN=38`，内容宽 `INK_CANVAS_W-2*INK_MARGIN=608`；行间 `INK_GAP_M=14`，组间 `INK_GAP_L=29`。白底黑字，边线 `INK_STROKE=3`；不以灰色区分禁用和占位，遵守本项目已定的黑白规则。
- 标题 `INK_FONT_TITLE/INK_LINE_TITLE=53/72`，正文 `INK_FONT_BODY/INK_LINE_BODY=38/62`，列表和按钮 `INK_FONT_LIST/INK_LINE_LIST=36/53`，说明 `INK_FONT_NOTE/INK_LINE_NOTE=31/43`。当前字号档位为 90%、100%、110%、120%，孩子 110%；容器随实际行高增高、重排或分页，不能只把字放大后裁掉。依据：`theme.c:23,126–179`。
- 【估算】按主题注明的 297 dpi，9 mm 约 105 px。普通 101 px 控件约 8.64 mm；建议把独立小图标的触控区至少做到 `INK_CONTROL+INK_GAP_XS=106`，视觉仍可用原令牌，相邻热区不能重叠。键盘十列宽度存在物理例外，见 C12，不能宣称所有键都达到 9 mm。
- 等待、成功、失败均在原控件或原内容区域替换文字；无转圈动画、无自动重试。不可恢复的删除和身份权限遵守 D-105，其余直接执行。可撤销不等于必须新增撤销服务。

## 令牌落地边界

【实现】上述 `INK_*` 基础令牌在基线存在；`INK_FIELD_*`、`INK_KEY_UNIT`、`INK_TOUCH_MIN` **目前均不存在**。落地时如需命名，应由 `ui-input-2` 的主题文件所有者把这些表达式集中为别名，再由页面选规格；本报告没有假称已有这些 API。正文高度、焦点、清除、错误提示也只是规格，不代表组件已经实现。

【估算】QWERTY 十列的约60 px宽仅约5.1 mm，不可能在684 px屏宽同时做到十列且每键9 mm。建议保留用户明确要求的全键盘结构，固定等宽并改善误触；严格9 mm与全键盘的取舍列入报告“要用户定”，九宫格不在这次拆分中实施。

现有 `ui-scale` 能约束令牌来源，不能单凭通过证明上述规格一致或真实触控合格。逐页验收还需检查 90/100/110/120% 字号、键盘展开、长中文／英文、空／等／错状态和真实能力回执；本次没有运行这些测试。
