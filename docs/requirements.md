## 2026-11-02 刷新算法研究归档

2026-10-28 公共会话中的刷新算法研究已归档为[刷新算法研究](research/eink-refresh-algorithm.md)。

用户当时补充了三项表达，记为 I-037～I-039，并补入 R-011 说明：

- 刷新算法要效果好，且计算资源消耗低；
- 只用 Plus 硬件，EPDiy 代码与架构仅作参考，可以直接驱动；
- 系统或应用不应需要手动调整刷新模式。

PQ-BN v4、直驱架构与自动模式阈值属于助手设计，目前只有仿真与指令级估算。R-011 状态不变。

## 2026-10-31 调度与体验补充

用户强调硬件算力有限，需要重视底层调度、多任务系统与流程中的可感知体验。新增 R-029，承接底层优先的 R-008 与墨水屏交互 R-010；资源准入、任务分层、异步状态、刷新合并等是[调度专题](research/system-scheduling-and-experience.md)中的实现建议，尚未选定具体任务数、优先级、并发组合或延迟指标。原始记录见 I-030。

## 2026-10-30 确认与推进顺序

用户核对需求理解后补充：账户系统和服务器备份需要纳入建设，理由是初期系统可能不稳定，后续可能有朋友使用；上一轮理解摘要中的其他功能方向也需要。近期优先构建高效底层系统，使系统负载匹配 E-Ink4 Plus 的实际算力与资源，使 UI 交互匹配墨水屏特性。

- 账户与服务器备份的能力方向已确认（R-022、R-023）；注册方式、备份粒度、实时同步与多设备策略仍待定。
- 通话／短信待办、平台级 IME、LLM 输入联想及儿童新闻／百科，从候选方向纳入产品需求（R-024～R-028）。成立条件和具体实现仍需验证，首版顺序未定。
- 底层系统优先（R-008），墨水屏特性是 UI 设计的明确约束（R-010）；现代交互与 R-011 高刷目标继续保留。
- 本轮确认范围是上一轮需求理解摘要列出的功能方向；竞品资料库中未逐项讨论的建议继续按原状态维护。具体技术栈、奖励机制、默认行为及完整首版范围尚未定案。

关联原始记录见 [I-027～I-029](ideas.md)。

## 助手建议，尚未确认

- 以本地确定性的系统服务承接 AI 动作；主模型通过可配置 API 调用。
- 建立家庭成员的独立进度、内容权限和语音数据设置；共享设备或一人一机仍待明确。
- 学习能力复用同一套内容与练习基础，允许不同引导、反馈、难度和节奏。
- 先形成三个场景原型：主题学习导入、找书后读听切换、故事断点续播。
- 显示与通信均围绕已限定的 Plus；原先以 Claw4 为通信研究重点的建议撤回，保留其驱动为参考资料。
- 应用包采用版本和资源约束，安装后可发现、可更新、可卸载，失败可恢复；具体机制后续决定。
- 系统统一管理共享数据与 app 数据，支持整机用户数据恢复及选择性恢复；程序卸载与数据删除分开讨论。
- 账户系统已由 R-022 确认；将家庭成员档案、设备授权与恢复凭据分开管理仍为实现建议。具体注册方式、账户关系与备份方案见专题调研，尚未定案。
- 从固件功能提炼“随口记、统一内容入口、继续读听学、真实执行结果”等 [C-001～C-008 候选](research/firmware-feature-landscape.md)；保持全局 AI 目标，不直接采用多固件切换作为应用平台。候选顺序、首版功能均未确认。
- 跨品类新增 [C-009～C-024 候选](research/cross-category-opportunities.md)，包括查词到复习、资料转学习包、精听、曲库/音频书签、离线内容与专注模式等。它们补充而非替代用户要求，尚未决定第一批 app；HiFi 设备作为竞品不表示已经要求发烧级音频指标。
- 新增 [学习体验 C-025～C-028](research/learning-engagement.md) 与 [新闻体验 C-029～C-032](research/personal-news.md)：任务式学习、连续学习、能力成就、可恢复节奏，及个人报纸、来源对照、新闻转专题、儿童发现栏目。个人新闻与两版学习研究已明确，这些具体实现形式仍属建议。
- 将每个 app 的页面、数据、动作、行为记录、执行状态纳入统一 AI 接入检查。覆盖范围来自 G-002；结构化页面、稳定内容定位、数据索引和事件记录等机制是待验证的实现建议，详见 [AI 平台研究](research/ai-native-platform.md)。
