## 从操作到结果

| 问题 | 已读链与结论 | 仍不能证明 |
| --- | --- | --- |
| 全部单集的筛选在哪一步保存 | AllEpisodesFragment菜单/筛选提示→AllEpisodesFilterDialog→选项变化事件→全局偏好写入→页数回1并重新查询。底层ItemFilterDialog的Confirm只关闭，Reset传空集合。 | 关闭不是已实现的撤回按钮；进程异常、并发更新、系统落盘和重装恢复未运行。 |
| 单播客筛选是否与全局共用 | FeedItemlistFragment的过滤按钮→FeedItemFilterDialog→DBWriter→该feed行的过滤字段→FeedEvent→重载该播客。已订阅且非归档时显示主设置按钮，已有过滤提示另有入口。 | 此处保存于数据库；全局筛选在SharedPreferences。两者不可当同一设置或同一备份对象。其他SubscriptionsFilterDialog未补读。 |
| 清筛选是否能看见全部内容 | 全部单集页空条件仍由查询回退到已订阅源；收藏筛选额外包含已订阅/归档/未订阅状态。单播客查询则显式允许全部源状态、仍限该feed。筛选为空结果时提示可清除条件。 | 条件为空不是全数据库所有记录。Downloaded依下载日期字段，Paused依位置>0，不检查实际文件或实时播放状态。 |
| 标签编辑何时提交 | 单节目菜单或订阅批量菜单打开TagSettingsDialog。加/删标签先改临时显示列表；OK把输入框剩余文本去首尾空白后再加入并提交；Cancel没有提交回调。空名、完全相同重复名和保留的untagged值只重新聚焦输入；这不阻止OK继续提交当前标签列表。 | 不是实测取消；大小写/特殊字符的完整输入约束、重命名全库传播、关闭后同步与错误提示未核。 |
| 批量标签是否覆盖各自标签 | 初始只展示所选节目的共同标签；保存从各节目删除原共同集合，再加新显示集合，保留各自独有标签。每节目分别请求写入；root复选框受底部导航显隐条件影响。 | 不是全批次事务；中途失败、并行编辑或共享同对象时的结果未运行。无选择时批量handler直接返回。 |
| 怎样进入单集多选 | EpisodeItemListAdapter长按记录对象/位置，交给上下文菜单；选Multi-select启动选择，选择模式下点击条目或副按钮切换选中。取得选中项按列表位置遍历。 | 不能把长按本身写成已进入多选；触摸/鼠标实际菜单、屏幕旋转和数据变化后的选中恢复未知。 |
| 本地文件删除为何另确认 | 批量删除先扫描所选项：只要含本地源就展示删除/取消警告，确认才执行整组回调；无本地源则直接执行。警告说明会删除设备原文件且不能通过本应用重新下载。 | 批量数量提示在提交异步请求时产生，不等待逐项结果。本地/下载文件物理删除失败只日志，随后仍有状态/刷新路径；不保证提示等于删净。 |
| 清空队列是否删文件或停音 | Queue菜单确认→DBWriter→删除队列表记录→CLEARED事件→当前列表清空；该分支不调用媒体文件删除或STOP。单项出队与媒体删除的可选出队另有路径。 | 未运行播放服务对事件的所有反应，不能承诺一定继续播放；没有查到此链的恢复旧队列入口。 |
| 排序/移动事件能否证明已持久保存 | setQueue使用数据库事务重建列表，SQLException被捕获并记日志；调用方随后发送排序/移动事件，没有检查写库返回结果。移到顶部先逆序插入以保留传入列表顺序；底部顺序追加。 | 事务代码不是故障注入验证；不能承诺所有失败回滚，更不能把UI事件当数据库成功凭据。 |

## 取用方式与版本限制

本轮沿用F02/03/05/13深化，新增F14“筛选全局或单播客单集并恢复可见范围”。F13由已有标签浏览扩展到整理标签，原编号保留。筛选列表、排序和删除是不同任务，不把每个按钮拆成新功能。

对G-002的启发是分别表达当前选择范围、临时编辑、已发请求、写入对象及回读结果；对G-001，筛选空结果和隐藏内容应能解释，避免把来源缺席误当没有相关信息。这些是研究建议，不是本系统已确定协议。3.12.3源码不证明当前安装版本、所有厂商Android行为或Plus兼容性。
