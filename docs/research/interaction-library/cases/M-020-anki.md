# M-020 Anki：资料制卡、学习调度与数据恢复

## 结构化竞分（2026-10-28）

- 对象/产物边界：
  - 笔记（Note）与派生卡（Card）是不同对象；牌组（Deck）、牌组选项（Deck Options）、过滤牌组（Filtered Deck）和预设（Preset）进一步分离（F‑M020‑06/07/10/12/13）。
  - 档案（Profile）、同步集合与媒体文件是不同层级；媒体同步与集合单向替换的策略独立（F‑M020‑03/19）。
- 撤销/检查与恢复语义：
  - v3 多步 Undo/Redo 有边界；执行 Check Database、部分插件或直接操作数据库会清撤销历史，不能把所有操作都视为可回滚（F‑M020‑01/02/10/21）。
  - 导出/恢复对象不同：.apkg 合并、.colpkg 替换当前集合；自动备份不含媒体，恢复后需再处理媒体与同步方向（F‑M020‑03/19）。
- 对 E‑Ink4 Plus 与 5–6 岁+成人家庭的启发：
  - 把“内容（笔记/模板）/练习（卡与队列）/计划（选项与预设）/临时加练（过滤牌组）/恢复材料（备份、导出、删除日志）/同步（集合 vs 媒体）”建模为独立对象；“导出成功/同步完成”不等于可回滚或跨端一致。

## 分支与恢复边界

- 已在两端产生不同资料，首次单向同步不能不看方向就确认；文档另有合并处理。媒体同步规则独立于集合的单向替换。
- 两端复习同一卡片时，手册区分保留的复习历史与最后决定调度的状态，不能简单说“所有冲突自动无损解决”。
- 打开自动备份后，自动同步/备份暂时关闭供检查，之后关闭再打开才恢复。恢复流程需要检查内容，而不只是出现“完成”提示。
- 误评现已补v3逐步撤销原则及2.1.45多步/重做边界；具体学习页入口、撤销后题面、跨同步/重启与后台退出保存粒度仍缺。不能把旧版即时保存声明扩为所有操作不丢失。
- 完成一天的计划只代表当前调度任务结束，不能直接代表词汇或数学能力达标。
- 新旧包、文本导入、集合恢复的覆盖规则不同；不能把所有“导入”当作只新增不修改。AI 更新题库时需要查已有对象和导入策略，不能只返回新增文件名。
- “输入答案”和“自动判分”并不等价；此处仍要求使用者自评。若用于儿童或考试训练，本项目是否增加自动评分需要另外研究，不能借 Anki 的输入框作依据。
- 现行 Deck Options 简短教程仍提到 CMRR，但同页专节明确其于25.07移除；不能把旧计算入口放进当前操作链。新 Help Me Decide 标为实验功能，且当前安装构建未知。本例不推荐具体参数或承诺保持率。
- Check Media 文档同时写工具内恢复/清空入口和操作系统回收站；本轮补了缺失媒体FAQ但仍不裁定真实目录或清理期限。自动备份/同步/删除日志/含媒体导出是不同恢复材料，不能相互替代。

## 对本项目的意义（推断）

关联 G-001、G-002、R-016、H-004/005：内容对象、生成的练习、一次作答、长期调度要分别理解；AI 执行“今天先别练这个”时，应能区分一次跳过、暂缓、永久停用和删除。服务器同步与可回滚备份必须分别研究，媒体不能被漏算。这里未确定使用 Anki 的调度算法或文件格式。

对成人的启发是把临时加练、长期计划与今天的可用时间分开；对5–6岁儿童，桌面的预设/模板/过滤语法不宜直接变成日常学习入口，此为界面研究建议。资料→笔记→多张卡→每次作答→计划→统计的对象关系，使 AI 可以解释“内容更新了但学习记录保留了”“题没出现是被暂埋了”；实际采用前仍需定义本系统自己的数据规则。

本轮推断：AI处理“撤回刚才那次”应区分评分、内容改动及附件删除，能读出可撤销范围和清栈条件；自动执行的启停状态应与长期预设分开。恢复动作需列明将被覆盖的集合、可保留的附件及后续同步方向，而不是只报告一次导入完成。这里没有证明Anki已向本项目开放这些动作接口。
