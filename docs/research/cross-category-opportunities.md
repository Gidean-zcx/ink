# 从跨品类竞品提炼功能与场景

日期：2026-10-26。依据 [13 类竞品矩阵](/home/workspace/reader/docs/research/market-competitor-matrix.md)；M-xxx 为其中的产品索引。下文全部是助手分析与候选建议，未升级为已确认功能、首版范围或完整系统设计。

## 这次扩展改变了什么

此前三种优先场景和 C-001～C-008 候选来自较窄的功能样本。用户明确扩大竞品范围后，它们只保留为局部建议，不能据此收窄整个产品。研究应先判断某种体验是否有价值，再判断能否在 Plus 上实现、需要哪些服务或硬件条件。

**有依据可行**的是参考产品已经形成的任务模式，例如查词后加入复习、下载后离线听、对特定资料生成练习。**有条件可行**的是在 Plus 上把它们组合起来。专用手写、离线通用转写、高质量扫描或 HiFi 输出的可达水平仍可能 **信息不足**，不能通过功能对照表直接作出承诺。

## 功能不能只按 app 名称分类

| 用户正在做什么 | 竞品提供的启发 | 本项目可研究的共同能力 | 仍需各 app 自己处理的部分 |
| --- | --- | --- | --- |
| 发现和拿到内容 | 阅读器传书、Readwise 聚合、题库导入、播放器曲库管理 | 来源、文件、元数据、下载/转换状态、去重和离线可用性 | 书籍、题库、音频的格式校验与展示。 |
| 理解眼前内容 | Kindle 查词、欧路词典、微信读书问书、BOOX 关联笔记 | 当前内容和选区、查询入口、来源位置、上下文传递 | 词义、章节解释、题目提示与答案的不同规则。 |
| 把理解变成记忆 | Anki、百词斩、墨墨、Quizlet | 可导入的学习条目、成员记录、学习任务与恢复位置 | 卡片题型、回忆反馈、调度与知识掌握判断。 |
| 边听边用 | HiFi 曲库、Audible 书签、扇贝逐句练习、儿童故事机 | 音频会话、播放队列、位置、焦点、定时与本地缓存 | 音乐、故事、课文的控制与节奏。 |
| 留下想法并找回 | reMarkable 标签、Supernote 标题/关键词、办公本录音转写 | 原始记录、派生内容、搜索、关联与导出 | 笔记、备忘、学习摘记的组织方式。 |
| 让系统代办 | 手机 AI 连接应用、快捷指令、墨墨官方 API | 动作发现、输入参数、任务状态、权限和结果 | 每个 app 明确支持的业务动作，不能只提供“打开页面”。 |
| 专心做一件事 | 单词机、专注笔记本、Mudita、实体媒体键 | 当前任务、快捷操作、通知策略、随时恢复 | 自由读书、练习、听歌、故事等各自的会话界面。 |

这只是共同职责的候选划分。没有选数据库、插件格式、调度算法、服务协议或 GUI 框架。

## 用完整场景比较，而不只统计功能数量

以下是产品原型的比较脚本；不是已经实现的演示。

| 场景 | 期望的一段完整过程 | 值得验证的结果 |
| --- | --- | --- |
| 成人学英语与了解新闻 | 指定主题和可用时间 → 找到有出处的文章 → 阅读/听读 → 查生词 → 保存原句 → 形成复习任务。 | 少量操作能完成；回到原文容易；没有把“读过”误记为“学会”。 |
| 儿童识字与故事 | 选择感兴趣的主题 → 听/读短故事 → 认识少量字 → 做一种小练习 → 下次遇到这些字。 | 孩子能独立开始；换情境仍能识别；中断后进度明确。 |
| 成人备考 | 导入指定考试材料 → 校验题库 → 选专项或模拟 → 记录错题 → 查看解释 → 做相关练习。 | 考试版本与来源正确；解释可追溯；模拟模式不会被不断讲解打断。 |
| 自由阅读与记录 | 打开一本书 → 标记一段 → 语音留下想法 → 稍后查找、整理、导出。 | 原文、原话和整理稿有关系；自由阅读本身也是完整用途。 |
| 通勤听力 | 选择已下载内容 → 播放 → 标记难句 → 稍后逐句练 → 保存生词。 | 连续听与精听能切换；文本和音频位置一致；网络中断后仍可用。 |
| 家庭睡前故事 | 选择成员 → “继续上次” → 恢复内容 → 到设定条件停止 → 保存进度。 | 播放的是正确成员、正确版本；内容已本地可用；第二天仍能恢复。 |
| 音乐与专注 | 选专辑/队列 → 少看屏控制 → 必要提醒打断 → 返回原队列与位置。 | 输入与播放响应可靠；用户知道当前正在播放什么；纯听歌可作为独立模式。 |
| AI 跨应用代办 | “把刚才那篇文章里的生词加入我的词本，明天复习” → 按需取得能力 → 执行 → 返回词数与时间。 | 应用和提醒均真实落地；重复指令可识别；失败后能说明哪一步未完成。 |

## 对后续关键架构讨论的启发

本轮支持继续研究六种共同对象：**内容及出处、可定位片段、成员学习记录、播放会话、可执行动作、可恢复任务**。它们让书籍、词典、题库、故事、播放器和 AI 能共享必要的信息。

同时保留场景差异：音乐主要按曲目/队列组织，听书按章节/位置组织，精听还需要句段和练习，生成故事需要保存版本；这些可以共用音频底层，但不应只剩一个通用“播放”按钮。类似地，查词、知识解释和考试判分也不是同一种可信度或输入输出约定。

产品界面可以探索随任务变化的快捷入口、清楚的返回位置和真实状态；不把所有交互塞进聊天窗口，也不预先规定一套首页格子。家庭成员、账户、服务器和离线能力继续沿既有讨论细化。

基本方向经用户认可后，再用有限原型验证关键交互及 Plus 的资源边界。当前阶段不做完整系统设计、不更换硬件、不启动采购。
