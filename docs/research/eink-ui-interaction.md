# 墨水屏 UI：怎样让操作流畅、阅读稳定

查阅日期：2026-10-28。目标仅为 CloudZao E-Ink4 Plus。当前为调研与原型建议，未开始系统实现。文末保留来源与核查范围；没有 Plus 实机、光学延迟、儿童用户或功耗测试。

## 1. 判断与适用边界

**有依据可行：保留现代界面的操作语义，围绕电子纸重新设计反馈、运动与刷新。** 下拉控制中心、返回、手势、清晰的排版和一致导航仍有价值；全程跟手移动、大面积半透明叠层、惯性滚动和装饰动画应逐项评估。现代感可以来自内容层级、字体、留白与操作一致性，不必依赖持续运动。

**有条件可行：局部快速反馈、滚动后清晰化、少量动态效果。** 取决于实际屏型号、波形、历史像素状态、驱动和系统并发负载。不能承诺任何局部刷新都很快，也不能把商业设备的表现直接移植到 Plus。

**信息不足：本机全屏 60fps、无残影以及对应续航。** R-011 保留为待验证目标；产品基本使用体验应能在未达到该目标时成立。成人“无限流”可指内容持续供应和学习不中断，并不必然要求像素连续滚动。

用户已明确的是 R-010 现代 UI/下拉/手势与 R-011 高刷目标。本次询问是要求研究交互取舍，不视作撤销它们。下文均为助手建议，尚未成为新需求。

## 3. Plus 源码给出的更具体依据

固定提交 `ad8edf4150a688737c0d7c00cae4413079b262ef`，只抽查以下路径，不宣称审计全部驱动。

- `main/display/lv_adapter_epdiy.cc`：`flush_cb` 将绘图缓冲提交给 `EpdSubmit`，随后调用 `lv_display_flush_ready`。**框架缓冲可复用/提交结束不能当作光学显示完成。** `EpdSubmit` 的接收、刷新任务结束与实际墨粒达到可读状态还需分层测量。
- `main/display/epd_refresh.cc`：`ProfileWaveform`/`Draw` 根据模式与配置选波形；有短 DU、灰阶方案及灰阶变化后升级模式的分支。工作任务识别 `scrolling`/`scroll_settle`，在滚动结束条件下选 GL16；也维护局刷计数、时间及完整清理的条件。这支持“操作过程与静止阅读分开处理”的研究方向。
- 同文件 `Draw`：抽查路径向更新接口传入固定 `25`；扫描供给不足后尝试清除并完整 GC16 恢复，还与闪存写入互斥。**固定温度参数不证明已经适配真实温度；IO 并发也是体验约束。** 未验证这些错误分支的实际恢复结果。
- `display/waveforms/my_waveform.c`：有完整 DU/GC16/GL16、自定义快速裁剪、8 灰与短 DU 的定义及初始化。代码中的 8、20、30、48 等是波形相位数，不能换称每秒帧数；一个 `0–50` 温度区间的声明不证明整个温区质量合格。对默认 EPDiy A2 的限制不能推导出这个自定义分支完全不具备快刷。
- `display/highlevel.c` 的 `epd_hl_update_area`：计算变化和行列掩码，再以全屏几何范围交给驱动，组合跳过未变化像素的标志。**界面脏矩形、传输范围、物理驱动像素不是同一个概念；把更新面积减半，不保证显示时间减半。**

以上的 `display/` 短路径均位于 `main/boards/metalio-e-ink4-plus/`。面板版本差异仍见既有 [硬件研究](/home/workspace/reader/docs/research/cloudzao.md)；不将 README 的 ED047TC2 与社区 E0470A14-AF 未经核实视作同屏。

## 4. 怎样定义“感觉流畅”

建议分别记录四件事：

1. **输入响应**：系统何时接收到点击、按键或语音请求。
2. **首次反馈**：用户何时看见选中状态或收到允许的声音提示；画面提交不等于看见。
3. **稳定可读**：文字、候选词、图表何时足够清晰且不再跳动。
4. **任务完成**：何时真正播放、保存、导入、同步或设置成功。

有些操作只需一次最终显示，额外的“已点击”刷新反而增加负担。预计耗时的任务才增加局部进度状态。短暂视觉状态不能早于物理显示就被覆盖，也不能为了表现灵敏而提前宣称保存成功。

连续操作不能堆积一长串旧动画。可以合并过时的视觉帧，但答题、保存、购买/发送等业务动作不能随帧丢弃。页面换了以后，排队触摸不能误作用于新页面同坐标按钮。连按“下一页”应有明确的目标页/连续翻页规则，不能迟到地突然跳数页。

## 5. 具体交互候选

以下是基于资料的设计推论，不是现有产品的已测结论。

| 场景 | 建议先试的交互 | 可选增强与必须检查的细节 |
| --- | --- | --- |
| 下拉控制中心 | 从顶边滑动达到阈值后打开固定面板；状态栏点击也可打开；明确关闭入口 | 实机达标后再试短距离跟手预览；不用背景模糊/弹簧回弹作为基础；下拉区域与正文选择不冲突 |
| 主页/应用入口 | 稳定位置、少量高频入口、“继续读/听/学”、可见搜索；编辑位置用明确操作 | 不因后台推荐到来自动挪动入口；图标不靠细浅灰区分可点/禁用 |
| 书库/新闻列表 | 搜索、筛选、跳页；分页或整屏步进，保留少量上下文与返回位置 | 连续滚动可作为比较方案；不武断禁止。用任务完成时间、漏看与定位成本判断，不只比较 FPS |
| 正文阅读 | 点按/短滑翻页，保持排版稳定；图片先预留空间，避免加载后推走正文 | 内容/字号变更需要重新定位到语义位置；有限预排下一页，不能假定整本常驻内存 |
| 亮度/音量/字号 | 大触点分档、加减键、清楚数值；长按可连续调节 | 音量/前光可立即作用于硬件，屏幕数值节流；滑杆可预览并明确何时提交，避免松手后超调 |
| 输入法/搜索 | 固定键盘与候选区；局部更新组合串，输入事件完整保存 | 不做按键放大飞入动画；测快速拼音、候选翻页、删除与刷新忙时输入；不会因少刷屏而漏键 |
| 弹窗/通知 | 不透明面板、清晰边界、稳定按钮；一般消息集中到收件区 | 来电/闹钟仍须及时响应；不要让全屏清理或云请求阻塞接听/停止动作 |
| 加载/下载 | 保留旧内容，显示真实阶段或数量；未知时显示“正在获取”及取消/返回 | 不用常转圆圈、闪动骨架维持忙碌感；不造百分比；缓存旧新闻标注时间，完成后供用户切换 |
| AI 回答 | 首个可读片段尽早出现；后续按句/小段追加到限定区域，历史内容保持稳定 | 长句要有最长等待策略，不能一直等句号；用户回看旧内容时不自动拉到底，提供“有新内容”入口 |
| AI 跨 app 操作 | 一个稳定任务卡呈现检索/下载/导入及真实结果，提供进入目标对象的入口 | 后台业务动作可直接执行，不必把所有 app 的页面逐个演给用户看；需要人选择/确认时再呈现相应页面 |
| 听书/故事 | 播放/暂停/续播与章节清楚；进度低频更新，按需展开精细进度 | 不持续绘制波形/旋转封面；读听高亮先比较句/段级，不能牺牲必要的学习定位 |
| 游戏/互动学习 | 回合制、选项、翻卡、拼字、剧情分支、静态探索与局部状态变化 | 需要拖拽时先试“点选对象→点选目标”，跟手拖动留作实测对照；模拟器单列动态区与刷新配置 |

## 6. 视觉与刷新要一起设计

建议默认白底深色正文，关键控件使用清晰轮廓、文本与形状冗余，不把状态仅藏在浅灰、阴影或色差里。图表线型、标记和图例须在灰阶下可辨；并非禁止所有灰阶或抗锯齿，也不默认整屏纯黑白对所有内容最好。深色主题应独立测残影与可读性，不能套用 OLED 的省电推断。

把时间、电量、下载进度、音频位置等可变信息放到稳定的局部区域；界面其余内容不跟着重排。减少无意义秒钟、闪烁光标、跑马灯和整屏淡入淡出。加载完成、弹窗关闭、列表插入时尤其要避免整个画面重新布局。

候选刷新策略是“内容稳定时重清晰，操作变化时重及时，操作结束后按需要清理”。不能机械地每点一下先快刷再全刷；也不能等无限滚动结束才清理。策略需有实际残影预算、最长清理等待、手动全刷入口与失败恢复。章节结束、页面切换是候选清理时机，不保证当时用户必然不在阅读。

普通使用者只需“更清晰/更灵敏”等少量可理解选择；波形、相位、阈值留在调试端。原生 app 可提供“正文/控件/图像/动态区、交互开始结束”等意图，由系统统一裁决，避免各 app 任意抢刷。这个方向是关键架构研究建议，未确定接口、调度器或实现框架。

## 7. 对本产品的三个具体样例

**成人新闻**：先看到本期主题、来源和更新时间→点入稳定正文→选择追问/保存/延伸阅读→回到同一位置。下一条可以提前准备；新一期到来显示提示，不立即替换正在看的版面。让内容有继续探索的入口，同时明确本期结束。高价值不是靠一次多显示多少条或无限滚动来定义。

**儿童识字与故事**：一屏一个清楚任务→选择后局部显示反馈→允许听解释/再试→孩子决定继续。趣味来自剧情、人物回应、积累的作品和可理解的进展；无需长时间动画。声音是可选反馈，静音时仍可完成。测 5–6 岁孩子是否知道已选中/答错/可以继续，不能因刷新慢而误判其反应或学习能力；不把停留时长当学习效果。

**随时唤起 AI**：保留当前阅读位置→出现“正在听/处理中”的稳定状态→完成识别后确认可编辑文本→按句呈现回答或显示任务进度→完成后直接进入书/练习/提醒。若联网等待，页面仍可返回，任务状态可再查。AI 的结构化数据和动作能力应独立于屏幕刷新：既满足 G-002 的完整访问，也避免靠不停截图、切屏才能操作。

## 8. 后续最小验证，不启动全系统设计

先确认实际板卡、屏、波形和固件版本。在同一硬件上比较三组候选：控制中心直接展开/短预览；新闻分页/整屏步进/连续滚动；AI 按字/按句分段（加入最大等待）。再补键盘连输、连续翻页、错答再试、音频同时播放、来电/闹钟打断。

| 测什么 | 方法与判据 |
| --- | --- |
| 操作到可见、到稳定可读 | 输入日志与外部相机/光学记录对齐；报告中位数和高分位，区分首帧/墨粒稳定；高帧率拍摄本身不等于屏达到该 FPS |
| 操作是否正确 | 记录漏按、重复执行、跨页误触、返回位置、取消与真实完成结果；不能只记录渲染回调 |
| 文字/图像质量 | 相同温度/光线/前光/曝光下，对同一目标内容比较不同前序画面留下的残影；加真实阅读辨识任务 |
| 清理干扰 | 连续阅读中清理次数、打断位置和累计残影；包括长会话而非只看启动后的几秒 |
| 资源与功耗 | 相同任务序列测峰值内存、能耗、音频卡顿、网络/存储并发；不能仅测显示线程空载 |
| 成人/儿童使用 | 成人测找内容和恢复阅读；儿童测操作理解、误触恢复和任务完成，分别记录，不从个人偏好推到所有年龄 |

不先规定通用的“100ms/60fps就合格”。根据对照和家庭实际使用确定门槛；网页原型只能测布局与流程，不能验证真实墨水屏延迟、残影或续航。
