## 当前判断

**有依据可行（仿真与指令级估算层面）**

- 保留 Plus 的硬件：S31、TPS65185 和并行墨水屏面板。
- 不使用 EPDiy 的全局锁整段波形。改由自建扫描任务每相（约 12 ms）逐像素决定推黑、推白或不动。
- 在同一面板模型下，用异步积分器（N = 8）比较点按反馈：
  - 达到 50% 可见的平均时间，从现架构 DU20 的 136 ms 降到 48 ms；
  - 回到初始画面后没有残余直流。

**有条件可行**

最终算法 PQ-BN v4 由两部分组成：规划/执行分离，加上自动快速运动渲染。

单核 RV32 估算下，每 12 ms 相的耗时如下：

| 场景 | 每相耗时 |
| --- | --- |
| 静止页 | 0.32 ms |
| AI 流式出字 | 1.15 ms |
| 翻页 | 6.38 ms |
| 全屏快速滚动 | 平均 9.3 ms；最坏一相约 22 ms，需双核或 SIMD 核分担 |

存储需求为每像素 2.5 B（PSRAM 约 2 MB），另需约 51 KB SRAM。

成立的前提：

- 面板参数要实测标定；
- S31 的实际周期和 PSRAM 延迟要上板测量；
- 自动切换阈值可能要按真机 UI 帧率微调。

**信息不足：“60fps、无残影”**

- 本方案的驱动节奏约为 83 相/秒，测试中 UI 内容帧为 28 fps。
- 按假设参数，光学满幅转换仍需约 7.6 相，约 91 ms。
- 直流有界只能降低残影风险，实际残影需要光学测量。

R-011 的状态不变。

## 研究过程

### 阶段 0：60fps 说法与 PaperBoy 驱动（U1–U2）

**公开资料**

结论与本仓库[高刷调研](eink-high-refresh.md)一致：演示中的“60fps”指驱动或提交节奏，不表示像素光学响应缩短到 16.7 ms。

**代码核查**

核查对象是 [hpsaturn/paperboy](https://github.com/hpsaturn/paperboy) 的固定提交 `270ffd9915d7bb7e2f1efd232e5b86eaf0544d05`（2026-10-15）中的 `main/msg/msg.c`。它与作者 GitLab 原项目的关系没有逐行核对。

驱动逻辑如下：

- 每像素有 3 bit 计数和 1 bit 颜色，两像素合用一个字节；
- 输入颜色与记录颜色不同时，计数清零；
- 计数未满 4 时，朝新颜色推一场；计数满后输出空操作；
- 视频区为 432×160。

**计数器模型**

据此写出“计数器驱动”模型。仿真用的移植版与模型逐像素核对，在 820 万个像素·场中 0 处不同。

**发现的问题**

- 颜色翻转时计数清零，没走完的推送不会被抵消，每像素净直流随内容无界累积。在阶段 1 的视频场景中，最大达 138 场，rms 为 55 场。
- 只能输出二值，灰阶完全依靠空间图案或抖动。

### 阶段 1：抽象为物理约束下的量化问题（U3–U4）

**面板模型**

模型参数都是假设值：

- 像素光学状态 p ∈ [0,1]。每推一场，p 变化 u·k/T0·st·(1+噪声)，到两端饱和。
- k 是逐像素迁移率，服从均值 1、标准差 0.04 的分布。
- 首推粘滞：st = 1 − s0·(1 − e^(−停留场数/τ))，其中 s0 ≈ 0.3 ± 0.09，τ = 120 场。
- 噪声 3%。
- 可选的直流残留项（β, γ）只用于定性演示鬼影。
- PaperBoy 时序下，满摆约 3.8 场。

**问题抽象**

- 每个像素每一场在 u ∈ {−1, 0, +1} 中选择。
- 目标是最小化“人眼模糊后的误差 + λ·驱动能量”。
- 约束有两个：像素只能到达有限步长、会饱和的状态；直流必须有界。
- 按贪心或模型预测控制（MPC）的方式逐场求解。

**积分器驱动（助手设计）**

- 用 pos ∈ [0, N] 记录驱动时间的积分，每场取 u = sign(目标 − pos)。
- 由于 Σu = pos − pos₀，天然有 |DC| ≤ N。
- 可以推到中间灰。
- 可以零成本替换 PaperBoy 的计数器。

**PQ 物理量化器（助手设计）**

- 控制器为每个像素维护一个模型估计。
- 候选结果包括：保持不动，或朝某个方向推 n 场后实际能到达的状态（首推考虑粘滞）。
- 选择使 (d − v)² + μ·n·D 最小的候选，只发出第一场，残差按蛇形 Floyd–Steinberg 扩散。
- 到端时补推压实。

各指标的定义：

- **PSNR**：先对面板反射率和目标各做 σ = 1.2 像素的高斯模糊（模拟人眼），再按逐场均方误差换算。“整段”为全程平均，“末帧”为最后一场。
- **DC**：每像素净推送数。
- **残影**：在直流敏感配置下，结束后连续 60 场冲到全白或全黑，取与目标 rms 偏差中较大的一个，单位为满量程的百分比。

### 阶段 3：直驱架构与 PQ-BN（U6–U7）

**直驱架构（助手设计）**

- 只使用 Plus 的硬件。
- S31 负责 TPS65185 上电和 VCOM。
- 自建扫描任务每相输出每像素 2 bit 的驱动码：1 为推黑，2 为推白。
- LVGL 照常画 4bpp 帧缓冲，并按脏区标记 tile。
- 每像素状态放在 PSRAM，表放在 SRAM。
- EPDiy 只作为时序与电源的参考。

**为什么从 PQ 改成 PQ-BN**

PQ 的误差扩散是串行的：

- 无法按 tile、按事件或分核并行；
- 只处理变化的像素时，扰动会扩散到静止像素。

**PQ-BN 的做法**

- 每个像素独立地在“刚好夹住目标”的两个可达状态之间选择，阈值取自固定的屏幕空间蓝噪声。
- 选择时带有偏向少推的滞回。
- 到端时补推压实。
- 已经饱和的像素继续往同一端推，用来抵消反向直流，光学上没有变化。
- 像素之间没有依赖，可以向量化、事件驱动和分核运行。

**实现顺序**

1. 浮点参考版；
2. 整数版 `pqbn_fixed.c`；
3. 64 KB 的 2 bit 决策表，索引由四部分组成：目标 4bpp、模型状态 8 bit、蓝噪声阈值 4 bit、粘滞档 2 bit；
4. 事件驱动版，只处理目标变了或仍在推的像素。

### 阶段 4：压缩计算与存储（U8）

**v2 与 v3**

- v2：每像素 16 bit 状态，32 KB 镜像表，按 tile 处理。
- v3：
  - 32×4 像素 tile；
  - 已落定像素走快速路径；
  - 每像素 2 B，共 1624 KB；
  - SRAM 约 67 KB。

**测量方法更正**

为此写了 RV32IM 指令级模拟器 `rv32emu.h`：

- 内核用 clang/lld 编译为 riscv32 裸机程序，在模拟器中逐条执行。
- 周期按顺序核估算：指令数 + load-use 停顿 + 2 × 跳转成功的分支 + 2 × 跳转 + 3 × 乘法。
- 按 320 MHz 换算，一个 12 ms 相等于 384 万个周期。
- 结果与本机构建逐字节一致，见 [rv_verify.txt](eink-refresh/pqbn_v4/results/rv_verify.txt)。

由此发现旧内核在滚动场景中，每核耗时约为 x86 的 40 倍，阶段 3 的“× 10～14”过于乐观。即使是 v4，全屏快速滚动若每帧都做完整 PQ-BN，也需要 4～5 颗 S31 核。

**v4 的设计（助手设计）**

1. **规划/执行分离**
   - 规划器只在 UI 标脏的 tile 里运行，为每个未落定像素一次算出整段推送：方向加次数 n（n ≤ 6），从本相起每相推一次。
   - 执行器每相只读。8 个像素用一条 SWAR 表达式判断 n > k，再查字节表生成驱动码。
   - 每像素状态分为两部分：
     - hot 半字节：`dir<<3 | n`，7 或 F 表示已落定；
     - cold 16 bit，有三种格式：在推、休息中（含 3 bit 对数停留档）、已落定（含 10 bit 时间戳）。
2. **精确停留时长**
   - v3 的“tick 升档”会系统性地把粘滞档升得过早。
   - 修正后，视频 PSNR 提高 0.3 dB，粘滞模型误差的 rms 从 0.046 降到 0.031。
   - 关闭粘滞模型时，v4 与 v3 逐位相同（`eq_v3_v4`）。
3. **规划预算 `plan_budget`**
   - 限定每相最多规划多少像素。
   - 超出的 tile 留到下一相，从游标处继续。
4. **快速运动渲染（motion）**
   - 目标为二值蓝噪声，7 推完成一个满摆。
   - 规划完全用 SWAR（每字 8 像素），不读写每像素状态。
5. **逐行执行 `line_mode`**
   - 扫描任务逐行生成驱动线，省掉 208 KB 驱动平面和每相约 0.4 MB 的 PSRAM 读写。
   - 全屏滚动时平均每行 10.9 µs，最坏 19.6 µs，而行时间约 16 µs，因此需要几行 SRAM 环形缓冲。

### 阶段 5：自动模式（U9）

**对 U9 的回答**

三项“模式”中只有快速运动渲染会在运行中变化，并由驱动按 tile 自动决定：

- `plan_budget` 是每块硬件一个常数；
- `line_mode` 是硬件接法，集成时选一次；
- 应用和 LVGL 只负责画帧缓冲、标记脏区。

**自动切换规则（助手设计）**

状态都存放在已有的每 tile 1 字节里，不增加存储：

1. **活跃度**：新改动与上次改动相隔不超过 9 相（约 110 ms）时加 1，饱和到 3；否则重置为 1。
2. **跟不上**：上一相规划器用完预算，仍有改动没排上。
3. **进入**：跟不上期间，活跃度 ≥ 2 的 tile 切入运动模式。已有运动 tile 时，新的活跃 tile 直接加入，保证同一滚动区域观感一致。
4. **退出**：连续 12 相（约 150 ms）没有改动就切回，步骤如下：
   - 先补推压实；DC 在另一侧时多推几下回到平衡，有上限；
   - 再由 PQ-BN 整块精修；
   - 切换开销计入同一预算，分摊到多相。
5. **不进入运动模式的情况**：
   - 翻页的活跃度为 1，永远走 PQ-BN，只是按预算渐进完成；
   - 光标、打字、AI 流式出字，规划器跟得上，也一直走 PQ-BN。

**测试结果（`auto_test`）**

| 场景 | 结果 |
| --- | --- |
| 翻页 | 运动 tile 数为 0，积压 20 相后消化 |
| 滚动 | 第 2 个 UI 帧起进入运动模式；停止后约 0.65 s 全部切回 |
| 光标闪烁 | 运动 tile 数为 0 |
| 全程 | DC 与精确推送计数一致 |

`pqbn_v4_motion_enter/exit()` 保留为可选提示，不是必须调用。

## 接口要点（助手设计，供后续实现参考）

接口位于 [pqbn_v4/kernel/pqbn_v4.c](eink-refresh/pqbn_v4/kernel/pqbn_v4.c)，详见[包内 README](eink-refresh/pqbn_v4/README.md)。

**建表**

- `pqbn_v4_build()`：生成决策表、执行表和粘滞首推步长；
- `pqbn_v4_build_motion()`：生成运动模式用的表。

**运行**

- `pqbn_v4_init()`：以当前帧缓冲为已落定状态；
- `pqbn_v4_phase()`：每相调用一次；
- `pqbn_v4_exec_row()`：逐行模式下生成一行驱动线；
- `pqbn_v4_motion_enter/exit()`：可选提示。

**集成**

- 配置只有三项：`plan_budget`、`auto_motion`、`line_mode`。
- UI 层只需按 LVGL 脏区把 `tile_dirty[ty*ntx+tx]` 置 1。
- 驱动码为每像素 2 bit，1 = 推黑，2 = 推白；每行第 0 个像素位于第 0 字节的 bit 7:6。

## 局限、更正与待验证

1. **面板参数都是假设值**，需要上板标定。包括：
   - 满摆相数：PaperBoy 时序为 3.8 场，Plus 时序为 7–7.6 相；
   - 迁移率 ±4%；
   - 粘滞 s0 = 0.3、τ = 120；
   - 噪声 3%。

   直流残留模型只用于定性演示。
2. **面板与版本**：
   - CloudZao README 标 ED047TC2，kiikoread 的适配说明为 E0470A14-AF，见[高刷调研](eink-high-refresh.md)。
   - 本研究使用源码中 `ED047TC2_1216` 的定义。
   - 12 ms/相是估算值。
3. **RV32 模拟器只是顺序核估算**：
   - 没有建模 PSRAM 的 cache 与延迟，只统计字节数；
   - 没有建模 S31 的 SIMD 核与位操作扩展；
   - 只用了一颗核。

   需上板用 `esp_cpu_get_cycle_count()` 实测，再据此设定 `plan_budget`。
4. **自动切换阈值是经验值**：9 相活跃窗口、12 相退出、活跃度 ≥ 2。
5. **更正**：阶段 3 中“x86 × 10～14”的折算过于乐观，见阶段 4。
6. **未覆盖的内容**：
   - 温度补偿；
   - TPS65185 上电、VCOM 时序与功耗；
   - 灰阶直流的长期效应；
   - 触摸、音频、联网的并发（R-029）；
   - 残影的光学测量。
7. **早期论述**：原文没有保存，“7 类优化”的清单无法考证。
8. **归档媒体的改动**：
   - 视频是压缩版本，在原视频基础上降低了码率。
   - 原视频中 scikit-image 的 astronaut 测试图是真人照片，在归档版中替换为月面测试图，生成脚本一并归档。
   - 表中数值仍是原场景的结果。

## 硬件到手后的最小验证

1. **核对与跑通**：核对板卡和面板版本、引脚、TPS65185 上电序列与 VCOM；先用上游固件跑通，记录真实的相位时间。
2. **标定光学响应**：
   - 测单像素推 n 相的响应，包括满摆相数、首推粘滞随停留时长的变化、像素间离散和温度影响；
   - 用测得的数据替换模型参数和粘滞档。
3. **测周期并设预算**：
   - 在静止、AI 流式、翻页、滚动四个场景下测每相的 CPU 时间和 PSRAM 带宽，据此设定 `plan_budget`；
   - 验证规划与执行分核。
4. **光学与主观评估**：
   - 测量点按到首次可见、滚动跟手、停止后精修时间，以及残影（黑白反转、长时间静止后）；
   - 指标对齐 [UI 专题](eink-ui-interaction.md) 中“输入 / 可见 / 可读 / 完成”的分法。
5. **结合调度专题**：按[调度专题](system-scheduling-and-experience.md)，确定刷新任务的 CPU 预算，以及与音频、网络的并发方式。
