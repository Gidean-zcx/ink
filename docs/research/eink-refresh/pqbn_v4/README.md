# PQ-BN v4：计划/执行分离 + 自动快速滚动模式（面向 Metalio E-Ink4-Plus 直驱）

上一版（v3）每相都要对每个"在途"像素重新查表、重新决策。v4 把这件事拆成两半：

- **规划器**：只在 UI 标脏的 32×4 tile 里运行，对每个未落定的像素一次算出整段推送序列（方向 + 次数 n，最多 6 次，从本相起每相一次）。
- **执行器**：每相运行，只读。像素在本 tile 计划的第 k 相推一次，当且仅当 n > k。8 个像素用一条 SWAR 表达式判断，再查 4 次字节表生成驱动码。

关闭粘滞模型时，v4 的驱动输出与 v3 逐位相同（`tests/eq_v3_v4.c`）。

## 几个"模式"怎么理解：应用和 LVGL 都不用管

对上层来说接口只有一条：LVGL 照常画进 4bpp 帧缓冲，并按脏区标记 tile。下面三项里，只有第一项会在运行中变化，而且由驱动自己决定。

| 项 | 性质 | 谁决定、何时决定 |
|---|---|---|
| 快速运动渲染（motion） | 运行中按区域自动切换 | 驱动按 tile 判断：同一区域连续变化、且算力跟不上时切入；停止变化约 150 ms 后自动切回 PQ-BN 并精修 |
| 规划预算 `plan_budget` | 每块硬件一个常数 | 移植时按 CPU 余量设一次（也可以按实测周期自适应）；只限定每相最坏耗时 |
| 逐行执行 `line_mode` | 驱动的硬件接法 | 集成时选一次；输出与写驱动平面逐位相同，只省内存和带宽 |

自动切换规则（`pqbn_v4_phase()` 内部，`auto_motion = 1`）：

1. 每个 tile 记"活跃度"。UI 的新改动在上次改动后 9 相（约 110 ms）内到来，计数 +1，饱和到 3；否则重置为 1。
2. 上一相规划器用完预算、还有 UI 改动没排上时，算作"跟不上"。跟不上期间，活跃度 ≥ 2 的 tile 切入 motion。已有 motion tile 时，新的活跃 tile 直接加入，保证同一滚动区域观感一致。
3. motion tile 连续 12 相（约 150 ms）没有 UI 改动就切回 PQ-BN：
   - 在轨道上的像素补 1 推压实；若 DC 在另一侧，就多推几下顺便回平衡。
   - 然后整块由 PQ-BN 重新规划精修。
   - 切换的开销计入同一个预算，会分摊到多相。
4. 一次性的大改动（翻页）活跃度只有 1，永远走 PQ-BN，只是按预算渐进完成。小范围的持续变化（光标闪烁、打字、AI 流式输出）规划器跟得上，也一直走 PQ-BN。

验证结果见 `tests/auto_test.c`：
- 翻页：motion tile 数为 0，积压 20 相后自然消化。
- 滚动：第 2 个 UI 帧起进入 motion，滚动停止后约 0.6 s 内全部回到 PQ-BN。
- 光标闪烁：motion tile 数为 0。
- 全程 DC 与精确推送计数一致。

`pqbn_v4_motion_enter/exit()` 仍然保留。如果 LVGL 的滚动事件能传到驱动，可以用它提前一帧切换。这只是可选提示，不是必须调用。

## 这一版的改动

1. **计划/执行分离**。
2. **精确的停留时长跟踪**。粘滞档决定第一推的步长，它取决于像素停了多久：
   - 上次计划推过的像素：由 tile 计划相位和 n 精确算出。
   - 已落定像素：存 10 bit 时间戳，用滚动扫描防止回绕。
   - 整段计划都在休息的像素：存 3 bit 对数档位，在逐像素偏移的 2^L 边界上升档。这样无论 tile 多频繁重规划都没有偏差。

   v3 的"tick 升档"会系统性地把档位升得过早。修正后视频场景 PSNR +0.3 dB，粘滞模型误差的 rms 从 0.046 降到 0.031。
3. **规划预算**（`plan_budget`）。超出的 tile 留到下一相，从游标处继续。
4. **快速运动渲染（motion）**：
   - 二值蓝噪声目标，7 推一个满摆，规划完全用 SWAR（8 像素/字），不读写每像素状态。
   - 由上面的规则自动启停。
5. **逐行执行**（`line_mode` + `pqbn_v4_exec_row()`）。扫描任务逐行生成驱动线，省掉 PSRAM 里 208 KB 的驱动平面和每相约 0.4 MB 的读写。

## 计算量（RV32IM 指令级模拟，单核 320 MHz，每相 12 ms）

测试条件：1216×684，UI 竖屏旋转到横屏面板。场景前 60 相（惯性滑动最快的一段），取每相平均（括号内为最坏一相）。周期按简单顺序核模型估算。

| 场景 | 旧事件驱动 | v3 | v4，不限预算 | v4 自动模式，预算 8000 px/相（单核） |
|---|---|---|---|---|
| 静止页 | 6.57 ms | 0.27 | 0.31 | 0.32 (0.37) |
| AI 文字流式 | 22.6 | 1.67 | 1.07 | 1.15 (2.5) |
| 翻页 | 20.3 | 16.4 | 5.79 (141) | 6.38 (8.4) |
| 半屏列表滚动 | 119.5 | 73.2 | 35.5 (126) | 6.96 (14.2) |
| 全屏滚动 28 fps | 130.1 | 135.5 | 64.9 (233) | 9.29 (21.9) |
| 全屏滚动 14 fps | 94.0 | 100.9 | 39.0 (258) | 7.77 (22.1) |
| 封面网格滚动 | 133.5 | 178.2 | 112.5 (389) | 9.47 (22.2) |

每相 PSRAM 流量：v3 为 0.00~3.63 MB，v4 为 0.01~1.70 MB，自动模式为 0.01~0.61 MB。

惯性滑动全程（`rv/rvhybrid.c`，约 183 相，每相平均 / 最坏）：

| 场景 | 纯 PQ-BN，不限预算 | 自动模式，预算 8000 | 停止后精修（自动，8000） |
|---|---|---|---|
| 半屏列表 | 31.0 / 126 ms | 8.3 / 14.4 ms | 共 0.24 s 单核工作量，最坏一相 12.7 ms |
| 全屏 28 fps | 55.0 / 233 | 11.9 / 21.9 | 0.38 s，12.4 ms |
| 全屏 14 fps | 32.7 / 258 | 10.6 / 22.1 | 0.37 s，12.3 ms |
| 封面网格 | 104.6 / 389 | 12.0 / 22.9 | 0.57 s，12.4 ms |

滑动中，UI 帧到来的那一相要给所有运动 tile 做 SWAR 规划，最坏约 22 ms。平均能跑进单核；双核（规划与执行分核）时最坏相也能放下。预算 20000 的结果在 `results/rvbench4_auto20k.txt` 和 `results/rvhybrid.txt`。

逐行模式下，全屏滚动时生成驱动线平均每相 7.5 ms。平均每行 10.9 µs，低于行时间 16 µs；最坏一行 19.6 µs，所以需要几行的 SRAM 环形缓冲。

## 存储

| | 每像素状态（PSRAM） | 驱动平面（PSRAM） | SRAM 表 + tile 元数据 |
|---|---|---|---|
| 旧事件驱动 | 8 B/px = 6498 KB | 208 KB | 64 KB 表 + 行标记 |
| v3 | 2 B/px = 1624 KB | 208 KB | 32 KB 表 + 4 KB 阈值 + 31 KB tile ≈ 67 KB |
| v4 | 2.5 B/px = 2030 KB（hot 406 + cold 1624） | 208 KB，逐行模式为 0 | 16 KB 决策表 + 1.5/1.75 KB 执行表 + 2 KB motion 阈值 + 4 KB 阈值 + 25 KB tile + 0.7 KB 行摘要 ≈ 51 KB |

自动模式的状态（活跃度、待规划、运动标志）都放在已有的每 tile 1 字节里，不增加存储。

v4 的每像素状态比 v3 多 0.5 B/px，换来的是：除静止页持平外，计算量降 1.6~2.8 倍，PSRAM 流量降 2~3 倍，SRAM 少 16 KB。用逐行模式时，PSRAM 总量是 2030 KB，v3 是 1832 KB，旧版是 6706 KB。

## 接口（`kernel/pqbn_v4.c`）

```
int  pqbn_v4_build(dec[16384], exk[1536], step[4], T0, s0, tau_d);   // 决策表 / 执行表 / 各粘滞档首推步长
void pqbn_v4_build_motion(exk_m[1792], tau_nib[2048], tau[4096]);    // motion 用表
void pqbn_v4_init(ctx, now);                                         // 以当前 fb4 为已落定状态
int  pqbn_v4_phase(ctx, now);                                        // 每相调用一次：确认 UI 标记、规划、自动切换、执行
int  pqbn_v4_exec_row(ctx, now, y, line);                            // 逐行模式：生成第 y 行驱动线，返回 0 表示发零线
void pqbn_v4_motion_enter(ctx, now, sel);                            // 可选提示：把 sel[ti]!=0 的 tile 切入 motion
void pqbn_v4_motion_exit(ctx, now, sel);                             // 可选提示：切回，sel 为 NULL 表示全部
```

配置只有三项，移植时设一次：
- `plan_budget`：每相规划像素上限。
- `auto_motion = 1`：开启自动切换。
- `line_mode`：选择逐行执行或驱动平面。

调用方需要提供以下内存（字段含义见源码注释）：
- fb4、hot、cold：PSRAM。
- 表、tau、tile_dirty / tile_plan / tile_nmax、band：SRAM。

UI 层只需根据 LVGL 的脏区把 `tile_dirty[ty*ntx+tx]` 置 1。驱动码为每像素 2 bit：1 = 推黑，2 = 推白，每行第 0 个像素在第 0 字节的 bit 7:6。

## 复现

```
sim/build.sh && tests/run_tests.sh                    # 编译模拟器用的库；等价性、不变量、自动切换测试
cd sim && python3 make_scenes.py && python3 run_v4_q.py && python3 run_fling.py && python3 run_auto.py
cd rv && ./build.sh                                   # 需要 clang + lld（riscv32 目标），会打印各函数地址和命令
mkdir -p scen && python3 gen_scenarios.py scen        # 全分辨率场景，需要 Noto CJK 字体
```

`results/` 里是本包实际跑出的全部输出，其中 `rv_verify.txt` 是 RV32 与本机构建在不限预算和两种自动预算下的逐字节比对。

## 局限与更正

- **面板参数未经标定**。面板模型（迁移率偏差、粘滞 s0 = 0.3、τ = 120 相、噪声）是假设值，粘滞档的代表停留时长要按真机标定。
- **模拟器只是估算**。RV32IM 模拟器是顺序核周期估算：
  - 没有建模 PSRAM 的 cache 与延迟（只统计字节数）。
  - 没有建模 S31 的 SIMD 核和位操作扩展。
  - 只用了一颗核。

  真实数值需要上板，用 `esp_cpu_get_cycle_count()` 实测。之后再按实测周期设定 `plan_budget`。
- **自动切换的阈值是经验值**：9 相活跃窗口、12 相退出、活跃度 ≥ 2。它们在这里的测试场景上表现正常，真机上可能需要按 UI 帧率微调。
- **更正上一版说明**。上一版 README 按"x86 耗时 ×10~14（用满两颗核）"折算 S31，这个估计过于乐观。按 RV32 指令级模拟，旧内核在滚动场景下每核约为 x86 的 40 倍。全屏快速滚动若每帧都做完整 PQ-BN，即使 v4 也需要 4~5 颗 S31 核。因此滚动要靠自动 motion，或用 SIMD 核加速规划器。
