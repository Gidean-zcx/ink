# 系统场景对比（悲观档，2026-11-02，复核后重跑）

由本仓库的场景脚本（reader_basic、ai_ask、home_basic、standby）在 8 种显示驱动配置上运行得到。电流为估算，面板响应为研究的假设值，均无实机数据。

配置都是在 `profiles/metalio-plus.json`（EPDiy 端口）或 `profiles/metalio-plus-pqbn.json`（PQ-BN）上改字段：

| 列 | 改动 |
| --- | --- |
| EPDiy 端口（D-35） | 无（送行任务自旋） |
| EPDiy，送行阻塞 | `display.feeder_wait = "block"` |
| PQ-BN，规划在扫描之后（内核原样） | 无（仓库档案的默认值；扫描任务满队列时阻塞） |
| PQ-BN，规划与扫描重叠（需改端口） | `pqbn.plan_during_scan = true` |
| PQ-BN 研究配置 | `plan_during_scan = true`、`auto_motion = true` |
| PQ-BN 重叠 + 预算 12000 | `plan_during_scan = true`、`plan_budget = 12000` |
| PQ-BN 满摆 12 推（之后 / 重叠） | `full_swing_pushes = 12`，规划分别在扫描之后与重叠 |

“规划在扫描之后”是研究内核原样的唯一安全用法：规划下一相会改写本相仍在推送的 tile，扫描必须先走过那些行。“重叠”代表端口做了改造（规划跟在扫描后面逐带进行，或 tile 状态双缓冲），这项改造尚未实现。

复核前的版本（运动模式 4923 个 tile、翻页 p95 823 ms 等）主要受模拟器相时钟在空闲时停住的影响，已作废。
