# 第六轮的合成状态实验

运行：

```sh
python3 -B docs/audits/2026-11-04-codex-hub-design-r6/experiments/state_checks.py
```

结果：[results.json](results.json)。脚本只向本目录写这一个结果文件，使用虚构的人物、接收者和资料，不调用网络、模型或设备。

| 组 | 检查什么 | 证据边界 |
| --- | --- | --- |
| `recovery_log` | 旧机已正确停机时，先读日志和停机后再读的区别 | 只验证操作顺序，不模拟对象存储或进程退出 |
| `restore_dispatch` | 按协议 §3.9 的顺序判断恢复授权、历史缺口、完整性和实例变化，共 9 个分支 | 不是同步客户端或服务端的实现测试 |
| `history_gap_257_deletes` | 257 次删除只留 256 条墓碑时，增量剩 1 条，完整清单对账剩 0 条 | 数据和墓碑是合成集合 |
| `asked_authority` | 人发起这一轮、收件人在原话里、唯一匹配且非高风险，是否足以证明人要求了发送动作 | **按已写条件构造反例**；模型候选调用作为给定输入，没有测试模型会不会产生它。`operation_bound_control` 是建议增加的动作约束，既有设计没有该记录 |
| `private_export` | 同一轮已知私人来源，原文与其英文翻译能否都被文字匹配拦住 | **按字面匹配构造反例**；不声称未来实现一定使用 Python 的子串函数。说明不能把字面重合作为“不含私人资料”的证明 |

退出 0 只表示这些小模型中的断言和对照通过。报告中的产品风险仍标【文档核查】【推断】，不把合成结果写成真实中枢已发生的故障。撤销、成员切换和断线在报告中按设计约束交叉核查，没有用自行编写的计时器冒充已有实现。
