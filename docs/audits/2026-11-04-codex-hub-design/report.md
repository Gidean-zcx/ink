# 家庭中枢软件设计审查

审查日期：2026-11-04。对象：`6d10d95` 工作树中的设计与设备代码。审查完成；仅在本目录产出，未修改被审文档或产品代码。

## 一页结论

**有条件可行，但当前版本还不能作为冻结的开发契约。** 自建 Python 中枢、模块内调用、SQLite、单 WSS、浏览器独立运行的总体方向适合一个家庭，不需要推倒重来或先加微服务。应先修复身份信任、恢复一致性和两端协议，再按纵切推进；合成数据的骨架验证可以继续。

共 **25 项：严重 3、高 12、中 9、低 1**。这些是设计审查发现；中枢尚未实现，涉及中枢的泄露/丢失路径均为明确前提下的推演或最小算法反例，不声称发生过真实家庭数据事故。

最先改的五件事：

1. **首次配对建立独立信任锚。** 无 pin 时让服务同时给公钥和验证网址，攻击者可用自己的可信 HTTPS 站点自证；二维码比对目前不能证明它是用户的中枢（HUB-008，严重）。
2. **重新定义快照、停写和回滚顺序。** 多个 SQLite 单独备份不等于同一时点；快照后仍接收写入再拉镜像，回滚会丢已确认数据。演练必须验证跨库业务状态（HUB-009，严重）。
3. **同步补齐数据代次与历史缺口恢复。** ACK 后丢墓碑、再恢复旧备份会复活已删除对象；设备恢复重用版本也会吞新编辑。必须有全量对账和原子快照安装（HUB-010，严重）。
4. **让确认和异步结果始终绑定原成员、原动作。** 目前确认的来源/事件格式对不上，成员切换只清 AI 上下文，不能隔离旧作业、外发通知和帧（HUB-005、011，高）。
5. **先补两端可执行契约，再承诺“设备不用改”。** 查询 result 被丢、工具目录随页面/成员变化、45s/2048B 限制、TXT 阅读器和替身媒体都会阻断真实纵切；socket 桥本身不等于真语音/真网页联调（HUB-001、002、006、016、017，高）。

有依据可保留的判断：3 秒音频领先量低于实际 30.72 秒帧缓冲；8 个订阅和 4 个请求处理器尚未耗尽；IP 公信证书确实可申请；原费用假设下算术基本正确。D-07 每月一两百元 **有条件够用**，对真实 token、思考输出、缓存命中和朗读量仍需验证。

本轮实际运行了生产 C JSON 解析器边界实验、SQLite/恢复算法反例和 Decimal 费用重算，均退出 0；运行方法与证据边界见 [experiments/README.md](experiments/README.md)。没有运行真实中枢、付费模型或实机测试。机器可读清单见 [findings.json](findings.json)。

## D 安装、部署与运维

【文档核查】【推断】Compose + 私有镜像 + 向导、先验证 VPS 是合理起点；x86/arm64 是两份需要构建和验证的镜像目标，不能由 Compose 文件相同推定所有 NAS 可用。最小档/完整档/宽裕档内存分项相加约 2/4/8 GB，没有算术错误，但全是预算，没有实际进程 RSS、Chromium 峰值、页缓存和并发证据。应分别给主循环延迟、工作进程峰值、磁盘临时空间/备份保留/配额测量，swap 仅缓解 OOM，不能证明语音无卡顿。

安装卡点是可信入口而非命令长度：向导先创建账号、显示恢复密钥和输入 API 密钥，直到第 5 步才发证书（§4.1）。必须先建可信本地/SSH 转发引导或可信 HTTPS，再接触秘密；手机 /ping 只证明设备端口可达，不能替代 443/ACME 验证端口探测。没有公网 IP、云安全组/本机防火墙阻挡、DNS 错配、证书续签失败要在进入向导前给具体诊断，不能说 VPS 天生不用配。离线安装包、内置 Chromium/字体合理。

【文档核查】官方确实已提供 160 小时有效的 IP 证书；无域名方案并非不可行。仍要明确 ACME 客户端配置、可达端口、自动续签与持久证书存储；Caddy 默认对 IP 使用本地 CA，不能把一个 IP 站点配置直接等同于公信 IP 证书。手机认领在依赖可信 HTTPS 时不能静默降为自签。来源：[Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)，查阅 2026-11-04。仅 IP 的大陆准入条件依旧信息不足，本次不把备案推断升级为法律结论。

快照/升级/恢复是阻断项 HUB-009、010。备份密钥由用户离线保存、restic 异地加密、定期演练的方向成立；演练应验证家庭/成员/对象/块/身份一致性和一台隔离假设备的恢复。私钥与备份同机不能替代异地恢复密钥。搬家预推 urls 只处理旧机器仍在线的情况：原 VPS 突然丢失且 IP 改变时，还需用户经受信配对文件/本地设置导入新地址；公钥一致不会让设备自动找到新 IP。旧主机停用、旧令牌/旧 pin 吊销也应纳入搬家步骤。

## E 账号、配对与隔离

【文档核查】家庭→成员→设备适合共享设备；成人独立账号、孩子不需账号、家长看孩子而成人默认互不可见，与 D-16/D-23/D-25 一致。D-34 的成人一年/儿童 180 天转写和 180 天运行记录保留正确。明确服务器管理员有全量技术访问权是诚实边界；一家一库不防主进程/管理员访问其他库，Scope 仍是权限控制的重要部分。

FirstBoot 的三点文字在架构 §6.1 中大体对应网络→认领→成员；本地 system-ui-spec 仅列画板及文字约定，本次没有取得外部画板最新视觉状态。地址路径中固件预置/带 pin 的 TF 文件可行，摄像头备选依然未验证；“有 LTE 直接跳过第一步”和“未知地址要开热点填地址”互相冲突，应按 **网络是否可用、地址是否已知、信任锚是否已知** 三个独立条件推进。TF 文件读后删除不能承诺闪存介质无残留；依赖一次性码过期/使用后失效，不能放长期凭据。

首次无 pin 配对存在严重信任问题 HUB-008。屏幕上 8 位随机码、一次使用和限流是有益条件，但“看过二维码”不等于唯一设备拥有者；应原子绑定认领者、显示待加入家庭并允许设备本地拒绝，认领与 token 提交要幂等。另有两处流程缺口：未握手 10 秒断开与配对有效 600 秒矛盾；设备存令牌后 ACK 丢失，中枢立即作废令牌，设备却已转 hello，缺自动恢复路径。见 HUB-012。

令牌 256 位随机值、只存哈希、限定设备通道、吊销断线合理；Flash 不加密与丢失后靠吊销的边界已经说明。轮换需双版本确认、丢 ACK 重试和旧设备离线恢复期限；不能因 90 天到了就无条件移除旧凭据。换机应在新设备恢复并确认后再吊销旧设备。PIN 重置、远程 wipe 需明确单成人家庭的恢复证明和本地确认要求，不能在实现时放宽。

成员切换还有异步输出的隔离缺口：结束当前 AI 不等于取消浏览器、ASR、确认、作业、外发工具和已经排队的音频/文字；Scope 本身不能阻止旧成员输出进入新成员的界面。HUB-011 要求绑定会话代次。blob ACL 还须细到成员和对象，不能只凭 hash 或“在同一家目录”放行。

## F 语音与实时

【代码核查】【复现】下行抖动缓冲是 512 个 60ms 帧，约 **30.72 秒**（`system/services/audio/audio_service.c:56`），预缓冲为 3 帧/180ms。设计 300ms 首批、最多领先 3 秒低于容量，**没有发现由这个数值本身造成的溢出**。它不是对语音可无限长的保证：45 秒请求期限和 2048 字节回答总量见 HUB-006。

【推断】3 秒首字、4 秒首音是目标，当前预算不能证明达标。仅采用文中主模型 3s 上端，30ms 收尾 + 300ms ASR + 3s 模型 + 300ms 凑句 + 350ms TTS = 3.98s；再加儿童 200～400ms 检查和设备 180ms 预缓冲就至少 4.36～4.56s，尚未算 VAD 尾静音、网络和显示。首字是否可早于凑句要单列，儿童文字应和朗读经过同一检查，不能先 delta 上屏再过滤声音。要分别记录人停说、设备 end、服务收到 end、首文字可见和首样本播放，给成人/儿童、冷连接/热连接、工具/无工具的 p50/p95；不应只测服务器发出首帧。

取消必须贯穿模型请求、ASR、TTS、工具任务、发送队列，以 connection/session/turn 代次丢弃迟到输出。打断已执行的外部动作只能如实报告；不能保证每种动作都有撤销。设备关 rt.close 不会撤回已塞入网络的帧，历史“听到多少”无进度回报只能估算。识别为空不恢复播放是文档明确的暂缓，与详细设计 §7.3 的原体验有差异，应列在验收例外中。

听写用独立实时会话、段内替换、定稿后稳定、800ms 节流总体适合墨水屏；480 字节上限比 AI 通道稍留余量。final-only 的 5 秒规则须改（HUB-007）。音频服务是单 capture owner，第二个 capture_begin 返回失败；听写期间暂停唤醒词只解决入口，仍要定义 AI 键、来电、录音、锁屏抢占及退出后恢复，等 capture_end 的异步清理完成再交接。

单 asyncio 主循环有条件足够：网络协程之外，SQLite/VACUUM、分词、向量检索、Opus 转码/重采样、PDF/EPUB 处理不能同步阻塞循环。应给每路有界队列、并发额度和取消/背压；子进程有限额是正确方向，50ms 告警本身不是调度保证。
