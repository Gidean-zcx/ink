# 产品负责人视角设计审计

2026-11-04；审计快照 `2d3323f`。入库说明：报告里的 `_design/` 是审计时的离线导出，不进仓库；处理结果见[审计记录](../README.md)。本报告按聚焦、端到端体验、软硬一体和细节一致性判断产品，不冒充乔布斯，不编造语录。审计建议不自动成为需求；涉及已定选择的改动须由用户选择。正在补画的首版流程不作“缺页”问题。

**版本边界：** 画板发现固定于上述快照。审计收尾发现两个并行分支已推进，补核到系统服务 `e57fbc5`、中枢 `4ba1656`，在 §9.5 单列增量。尤其 D-105 已改为默认自动、仅高风险确认；本报告不要求把已放开的短信、电话、网页操作改回逐次确认。

## 1. 一页结论

**当前不建议把这组画板作为完成品交付；可以继续使用它的视觉基础。** 卡片、胶囊、稳定分页和原文上的 AI 浮层有依据成立。需要重做的是产品重心和关键步骤，补齐页面本身不能解决。这个判断针对任务快照的设计质量，不是对后来并行新稿或实机产品作发布验收。

**一句话定义：给一家人轮流用的随身阅读伙伴，让人安心读和听，遇到不懂的随口问，值得留下的随手记。** 这是对 D-01 首版体验的建议表达，不取消通信、相机、远程页面、单词、自动记忆等已确认方向。【需求核查】G-001、G-002、D-01、D-03、D-20；后续决定见 §9.5。

**最打动人的时刻已经露头：书还在眼前，“夜邮”已经懂了。** Ai 保留原文、解释注明来自这一页；把按键、收音、答案和继续阅读连顺，就有值得拿给家人看的体验。当前只能确认画板表达，实际响应与读听衔接尚未验证。【画板】AiListen、Ai、LockPage；【推断】完整体验价值。

最大的三个问题：

1. **第一眼说不清为什么要拿起它。** Main 先是大钟与应用清单，Today 又以任务数字带路，读听内容退到了后面。首页权重的强改版需重议 D-60，不能自行覆盖用户选择。见 JOBS-001/002、§10。【画板】Main、Today。
2. **AI 的仪式压过解释。** 大话筒、等待点、完成标题、重复问题与同权按钮挤在一个面板；它应把人留在内容里，而不是每问一句都举办一次聊天。见 JOBS-004。【画板】Ai 系列。
3. **本来想读、想记，却先被要求管理。** 选书要辨认文件管线，随手记要整理整批任务，维护页先展示容量和进度。把能力藏到合适位置，比把所有页画齐更重要。见 JOBS-005/006/016。【画板】MemoDetail、FilePicker、SetStorage、Update。

必须砍的三样：**AI 面板中央装饰与“回答完成”标题；MemoDetail 默认的“全部加到待办”；选书默认路径里的存储卡／格式辨认与重复“选中—打开”步骤。** 保留必要状态、逐条建议和通用文件管理能力；不据此删需求。十屏重做顺序见 §6。

本轮共 **16 项：严重 1、高 5、中 9、低 1**。先修首页表达、AI 就地回答、随手记和内容直达；再收紧设置、形状与文字。软总线与原子能力的分层方向成立，完整 AI 接入尚无端到端证据；已新增的听写能力、D-105 少确认原则已纳入收尾修正。报告不重复上一轮缺页与正确性清单。先行规则在 [early.md](early.md)，机器可读清单在 [findings.json](findings.json)。【代码核查】【文档核查】详 §9、§12。

## 2. 第一次拿到手的五分钟

这是按画板走的体验推演，不是用户测试或实测耗时。下表的时间是建议的演示脚本预算；前提是家庭服务器已经可用、有可读内容。全新家庭从零部署服务器不能承诺五分钟完成。【文档核查】中枢设计 `b0b5a72` §4、§6.1；【推断】使用感受与时间分配。

| 时刻／画板 | 现在给人的感受 | 应该怎样完成这一步 |
| --- | --- | --- |
| 0:00–0:40，FirstBoot | “你好”亲切，扫码不用在小屏打密码是对的。但“帮它连上网”把整个设置说得过于轻松；三个点没有解释还要做什么。 | 写“用手机设置这台设备”，说明连接网络、选择使用者。扫码为主；“在设备上设置”为次入口。设备已有配置就跳过。不要把后续流程画成一串成功页。 |
| 0:40–2:00，手机设置与设备确认 | 画板只表达扫码起点；结合服务器文档，连 Wi-Fi、连接家庭服务器、授权加入家庭是不同步骤。这里不以尚未补完的页面扣分。 | 手机承担长文本与配置，设备只呈现当前实质步骤和必要确认。地址、信任校验不能假装同一次扫码就全部解决。服务器未就绪，说明“AI 还需要完成家庭服务器设置”，仍可打开标明“示例”的离线短文。 |
| 2:00–2:30，Members → Pin | 大字头像易认，孩子直接进很好；添加成员与家人同权，成人四位码后又多一次“进入”。 | 已有成员占主区，添加成员为次入口。固定长度 PIN 输完即校验，成功回原任务；不降低验证要求。孩子直接见自己的内容与进度。 |
| 2:30–3:10，Main → Today／FilePicker | 第一眼看见大钟和一组手机应用。第一次选书又看见存储卡、扩展名和转换状态；价值出现得太晚。 | 设置后直接打开选中成员的上次内容，首次无内容则给可跳过的示例。日常从 Main 一次触达继续读；Today 给真实书名、报纸主题。书库中点可读书即打开。首页更强的改版要经过 §10 的 D-60 选择。 |
| 3:10–4:20，阅读 → AiListen → AiThink → Ai | 原文保留是最好的部分。但在三次状态变化中，话筒、等待点和“回答完成”比解释更醒目。 | 引导只出现一次：“按住 AI 键，问这一段。”保留同一面板、同一正文起点；能读的答案按句出现，关闭后原文原位置不变。网络未通不邀请这次演示。 |
| 4:20–5:00，Memo／回到阅读 | 随手记的录音入口明确，进详情却像要马上整理任务。 | 说一句话，先确认“已记下”，建议随后可选。结束时回到内容；备份在后台提供可信状态，不再要求学习一个管理页面。 |

【画板】FirstBoot、Members、Pin、Pin__filled、Main、Today、FilePicker、Ai 系列、Memo、MemoDetail；【需求核查】D-01、D-03、D-04、D-09、D-16、D-60。**五分钟的成功标准应是“完成一小段阅读，问懂一句话，知道以后怎样接着用”，不是“所有设置都填完”。** 若 AI 服务尚未可用，成功标准只到离线阅读，并清楚交代尚未完成的准备；不能伪造已经工作的演示。

## 3. 一家人的一天

以下是体验推演。报纸、听书等尚未出现在本组主流程画板的部分，仅按需求与入口评价，不记缺页，也不声称已接通。【需求核查】D-01、D-05、D-20、R-018、R-024、R-025、R-030；【文档核查】system-apps、needs-analysis §1–3。

| 场景 | 画板暴露出的摩擦 | 应该让人记住的体验 |
| --- | --- | --- |
| 早上看个人报纸 | Today 只说“6 篇”，Notifications 又说“6 篇已送到”；数字重复，题目没有出现。 | Today 直接给本期一个真实主题和篇数，点入开读；读完明确结束。这不是每日必须清零的任务，也不是读完就删掉。不要在每篇末尾追着要求再问 AI。 |
| 路上继续听书 | Today 的“23 分钟”没有书名；Control 先让人面对网络与模式开关。 | 一眼认出昨天听的故事，一次继续。关屏后继续听；想暂停时到固定位置，声音从哪里出来说清楚。蓝牙尚未实机验证，演示可先按已验证的外放路径，不凭耳机图标承诺连接体验。 |
| 读到不懂，问“夜邮是什么” | 原文与解释同屏成立，AI 面板却把简单问题演成完整聊天流程。 | 按住、问、松开；听到／读到贴着此段的解释，收起就接着读。**这是最应打磨的惊喜时刻。** 如想记词，再给“记下这个词”，不把每次问答都变成学习任务。 |
| 下午随手记取快递、带作业本 | MemoDetail 的“全部加到待办”让记录变成整理；时间和发短信混在一组。 | 原话立即留下。愿意的话逐条加提醒或起草短信；不愿意就离开。晚上说“我今天记过什么”，能找回同一条记录，而不是再生成一份摘要当作新事实。 |
| 孩子接过设备 | Members 易认，但 Main 的大钟与通用应用网格没有说明“这是我的故事”。 | 选自己的头像就见自己的书与断点，阅读和听书用同一套稳定动作；可独立阅读的孩子不需要一套卡通导航或奖励仪表盘。通信遵守 D-25，与成人相同，不新增白名单。 |
| 晚上设闹钟，第二天响起 | Clock、ClockRing 已经清楚；与日历、待办的关系却要猜，“关闭”不清楚只关这一次还是整个闹钟。 | 说“明早七点半叫我”，回显具体日期与时间；早上只有“再睡 10 分钟”和“这次不再响”。关屏保持安静，响铃不依赖 AI 在线；电源键稍后再响沿既有约定。 |

【画板】Today、Notifications、Control、Ai、MemoDetail、Members、Clock、ClockRing。以上的共同要求是**内容和进度跟着成员走，下一次能继续**；不是把六个场景再包装成六个新应用。照片、电话和短信保留各自需求与版本安排，不借“聚焦”悄悄删掉。

## 5. 问题清单

### JOBS-001｜严重｜首页把这台设备介绍成一部应用很多的时钟

- **屏幕：** Main、Apps、Today。
- **证据：**【画板】Main 原图的主要视觉面积是时钟；下方八个图标、Dock 五个入口，“继续读”只有一行；Apps 同权陈列十五个应用，其中包含“远程画面”。【需求核查】G-001、R-031、D-01 的首版重心是读听、报纸、AI、备忘、备份；R-051/D-60 又明确选择了三屏及固定通信 Dock。
- **为什么不够好：** 一眼看到能力清单，看不到拿起设备的理由。丰富的入口掩盖了最有价值的“继续”；这是产品表达问题，不是图标数量越少越好的形式规则。
- **具体改法：** 不改既定结构的版本：Main 保留日期时间与既定入口，让继续读胶囊写出书名和具体位置，Today 用书、音频和本期报纸的内容标题带路；Apps 按“读与听／记录与工具”分组，把连接和维护入口下沉。更强的推荐是缩小时钟、读听占据主位，八个快捷入口缩为四个，仍保留三屏及五项 Dock 的成员和顺序；此版本必须先请用户重新选择 D-60 的具体布局，不能直接实施，见 §10。
- **已定决定：** 涉及 D-60、R-051；不挑战 D-01、D-59、D-61，不取消 R-013 电话短信。

### JOBS-002｜高｜今日页把继续的邀请画成了任务账单

- **屏幕：** Today。
- **证据：**【画板】47%、23 分钟、20 个、6 篇、2 件构成页面节奏；“听”不写正在听的书名，报纸不写一个具体主题。【需求核查】G-001；【文档核查】needs-analysis §2、F-10 要求以完成、掌握、读完衡量价值。
- **为什么不够好：** 数字没有错，但数字无法替代内容。孩子和成人都先看见还剩多少任务，才知道能接着享受什么；“23 分钟”还要读小字才知道是断点。
- **具体改法：** 保留大阅读卡和卡片语言，书名为主，章节为辅，进度移为小字；听卡写“继续听《书名》／上次听到第 3 章”；报纸卡用当天真实标题和“共 6 篇”；单词卡写“复习上次记下的词”，数量降为辅助。一天结束用“今天就这些”，保留返回已读内容的入口，不暗示读完即删除。
- **已定决定：** 不改变 D-60 三屏结构和 D-20 首版单词最小闭环；涉及 Today 的具体呈现调整。

### JOBS-003｜中｜全部应用页让一个输入框承担两种无法预知的任务

- **屏幕：** Apps。
- **证据：**【画板】占位文案“搜索应用，或直接问 AI”，下方另有 AI 图标，Dock 又有 AI；【文档核查】system-ui-spec §2、§3.6。
- **为什么不够好：** 输入“报纸”究竟找应用还是发起 AI 对话，用户在输入前无法确定。系统 AI 应能随处叫出，不需要把每个搜索框变成问答入口。
- **具体改法：** 改为“查找应用”，只本地筛选名称；AI 继续通过实体键和既定 Dock 进入。AI 全屏入口命名“对话记录”，说明它用于找回之前的问答，不再与就地提问争同一层的主入口。
- **已定决定：** 不涉及推翻已定决定；保留 G-002、R-026 的全局能力及输入法。

### JOBS-004｜高｜AI 的出场仪式比解释本身更显眼

- **屏幕：** AiListen、AiListenTap、AiThink、Ai、AiHome。
- **证据：** 【画板】Ai 系列原图：大话筒、大等待点、状态标题、重复问题、三个同权建议；【代码核查】_design/boards/Ai.dc.html:26、:38、:42、:52、:60（仅核对布局意图）；【需求核查】G-002、R-021、R-047。
- **为什么不够好：** 回答“夜邮”的正文只有几行，外围却是一整套聊天仪式。按键时人已在说话，巨大的“正在听”并不增加理解；“回答完成”占据最先被看到的位置。三个等待点只是静态画法，本条不声称原型正在播放动画。
- **具体改法：** 首版先保持同一稳定面板边界，避免为了省面积反复伸缩；把顶部状态压成一行“正在听 · 松开结束”或“正在看这一页”，撤掉中央大话筒和三点装饰，识别稿与答案用同一正文起点。答案直接写“夜邮，就是天黑以后送的信。”，下面保留来源；追问继续用 AI 键，显式操作最多主次各一个，例如“听解释”“更多”。原文不重排，关闭回原位置。全屏对话用于找记录，不作为每次提问的必经页。后续若比较更小面板，须比较真实可读面积与刷新代价，不能声称面积减半就快一倍。
- **已定决定：** 保留 D-17/R-047 的按键、唤醒词和打断；保留 D-59、D-61；不改 D-60 的 AI Dock 入口。

### JOBS-016｜中｜维护页用容量和百分比做主角，把安心感放到了小字里

- **屏幕：** SetStorage、Update、SetAbout。

- **为什么不够好：** 进入这里最重要的判断是“我的东西有没有保住”“现在会不会打断使用”。巨大的进度让人留下来等待，清缓存和恢复出厂又暗示需要经常维护。不是要求新加恢复页；是要求已在补的流程围绕安心与离开来组织。
- **具体改法：** SetStorage 首卡写“已备份 · 今天03:00”，展开可看范围和未完成项；空间不足才把容量提到前面，平时保留为下一组。Update 下载页主文“正在下载，可以继续读”，进度缩成固定一行，主要出口“返回”，暂停为次操作；安装仍由人主动发起并确认。恢复预览沿用同一张任务卡交代成员、日期、内容与覆盖后果，不串多个完成页。“清理临时文件”先显示可释放量；恢复出厂降到“重置设备”次层。
- **已定决定：** 不取消 R-023，保留用户发起安装和破坏性操作的必要确认；不自动改变备份、更新策略。

**字、留白与图标的判断：** 正文、大标题、卡片留白以及带文字的线性图标已有一致基础，值得保留。问题是注意力分配：Main 的大钟、Today 的大数字、Update 的进度环使用了最昂贵的视觉位置；Ai 的留白则围着状态，而非原文和答案。不要用加粗更多文字来补救，应减少同权对象。系统正文沿统一左边线，嵌套建议沿同一内容起点，辅助信息一层即可；不为年份、来源、完成状态再套一圈灰胶囊。黑色填充优先标出主要动作或当前选中状态，不能靠颜色独自区分两者，必须同时有文字或勾选。IconSheet 的线形图标用于工具，实心图标用于明确选择即可，不为同一动作换另一套轮廓。【画板】Foundation、Components、IconSheet、Main、Today、Ai、Update；【需求核查】D-59、D-61。

规格中的 24 px 小字，在 297 dpi 且像素一比一显示的假设下，字号名义高度约 2.1 mm；这只是换算，不是实测字面高度或可读性。核心说明不能仅靠这一级小灰字；原图在电脑上放大好看，不足以证明孩子拿在手里能看清。保留字体体系，优先提升关键结果的层级，再用实物尺寸验证，而不是再添一种字体。【文档核查】system-ui-spec §1；【画板】Foundation；【推断】物理尺寸换算与可读性待验证。

### 9.3 模块边界是否合理

| 边界 | 判断与应守住的范围 |
| --- | --- |
| 应用与系统壳 | 合理。阅读、备忘等拥有内容与业务动作；成员选择、确认、通知、输入法等壳界面只呈现服务状态。卡片、胶囊、分页共享组件，不各造通知、键盘或确认逻辑。 |
| 系统服务与硬件 | 合理。文件、媒体、时间、通信等登记有限业务能力；存储、电源、音频焦点、刷新和资源调度留在系统机制。用户说“调亮一点”，不需要 AI 调电源轨。 |
| AI 编排与决定权 | 合理。服务器 AI 选择业务动作，设备策略决定能不能做，调度器决定何时执行。成员身份和人确认不能由模型一句“已获同意”替代。 |
| 本地与远端 | 合理。本地直接调用，远端经统一描述和回执路由；音频／图像传输留实时通道，不强塞成一串 JSON 工具调用。应用看到内容和结果，日常 UI 不需要展示服务器管线。 |
| 文件与内容 | 必须保持两层。file.list 能列文件，不代表知道书已准备好；library/content 才知道书名、处理阶段和可读版本。JOBS-006 简化的是用户路径，不是把两个服务硬并成一个。 |
| 记录、提醒与记忆 | 应协作而非混成一库。备忘原话是用户记录，提醒是用户采用的安排，AI 记忆是另有来源与保留策略的数据。JOBS-005/012 合并入口与视图，不意味着 AI 提取完自动改写原始记录。 |
| 服务器内部 | 设计合理：网关接设备，能力目录路由，语音／内容／备份等模块各负责对象，模型网关管模型与费用，后台工作进程处理重任务。控制台也调用能力，不应绕开总线直接改业务表。用户可问备份、费用和任务状态，但不能拿到模型密钥或固件签名私钥。 |

### 9.4 怎样验收“AI 是系统的一部分”

不用新增一个 AI 专属导航。后续把同一个业务动作分别由按钮和 AI 发起，检查对象、成员、结果状态与屏上回显一致；只在需要人的操作处停住。建议用四段真实场景验收：

1. 读当前段落 → 问一个词 → 可选记词 → 收起后原位置继续，来源来自当时那一页。
2. 说一句备忘 → 原话保存 → 采用其中一个提醒 → 回到原备忘能看见该提醒，另一项不会被一并执行。
3. “接着听昨天的故事” → 同一成员、同一内容和断点 → 按暂停与说暂停得到相同状态；切成员后不串进度。
4. “我的东西备份了吗” → 返回实际备份时间和范围 → 可预览恢复 → 人确认后才执行。失败或未完成仍如实回显。

这是建议的验收脚本，本轮没有执行。页面快照、执行确认、失败和离线契约已在上一轮审计提出，不再次作为新发现计数。**本轮的新判断是：这些共同能力应让入口更少、原文更稳、任务更连贯；不是让每张卡上都多一个星光 AI 按钮。**【需求核查】G-002、D-45～D-51；【画板】Ai、MemoDetail、Today、SetStorage；【推断】体验验收建议。

## 11. 做得对，不要动的

1. **卡片与胶囊的视觉基础。** 白底、克制灰阶、圆角、文字与图标组合已经有统一面貌。问题来自过多同权对象，不需再换一种风格。Foundation、Components、IconSheet 值得作为共同基线；JOBS-010 是修正规则，不是推翻 D-59。【画板】【需求核查】D-59、D-61。
2. **AI 留着正在读的原文。** Ai 的“出自这一页”、上方正文和关闭回原位，已经比独立聊天页更接近这个产品的中心。把周围仪式减掉即可，不把人每次带走。【画板】Ai、AiListenTap；【文档核查】system-ui-spec §3.3。
3. **稳定分页和固定操作区。** PhoneContacts、Gallery、Sms 的明确页数与前后页，键盘固定区域，以及无连续秒数跳动的时间显示，尊重了电子纸。不能为了“现代感”再加弹跳、滑入或无尽滚动。【画板】PhoneContacts、Gallery、Sms、Keyboard、Clock；【需求核查】R-010。
4. **家庭成员易认，孩子直入。** Members 的大字头像与姓名容易对应，成人 PIN 的原则明确；改动只在管理入口和冗余步骤，不应把交接做成账号管理课。【画板】Members、Pin；【需求核查】D-03、D-16、D-25。
5. **原位完成反馈。** SmsThread__todo_added 将“加入日历”替换成完成状态，避免又开一个完成页。这是其他建议、收藏和提醒应该沿用的节奏；结果仍须来自真实回执。【画板】【需求核查】R-025。
6. **听写和 AI 问答分开，密码输入克制。** ImeVoice 的固定识别区有利于稳定排版，ImePassword 无话筒且有简短保护说明。删掉长期教学段落即可，不改成逐字冲击上方编辑区。【画板】ImeVoice、ImePassword；【需求核查】R-056、D-33、D-65（暂定）。
7. **安静的空状态和响铃页。** Notifications__empty 没有把空白填满；ClockRing 的时间、再睡和结束非常直接。不要在这些屏塞入推荐、成就或多余 AI 提示。【画板】Notifications__empty、ClockRing。
8. **有限内容与普通通知不横幅打断。** 报纸有终点，通知平时保持轻量，有利于安心读完；调整 Today 的数字和通知层级时不要丢掉这一点。【画板】Today、Notifications；【文档核查】system-ui-spec §3.7；【需求核查】G-001。
