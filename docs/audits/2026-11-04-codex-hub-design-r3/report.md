## 新问题

### HUB3-001｜严重｜安全日志的有效旧前缀会被当作完整日志，恢复后仍可能撤销吊销和“忘掉”

**证据类型：**【文档核查】【复现】【推断】。

**位置：**`docs/hub/hub-architecture.md:376`～`:381`；验收承诺在 `:1498`。

**证据与失败路径：**新版明确允许“本机先生效、异地后台重试”，也坦诚写出此间整机丢失会丢日志。剩下的漏洞在恢复判定：异地已经有第 1～N 条，吊销和忘掉是只写到本机的 N+1、N+2；主机损毁后，异地的 1～N 能正常下载，哈希链也完全正确。因此“取不到或验证不了才停止开放”的分支不会触发。实验用三个合成操作验证了：完整链与缺末尾的前缀都验过，恢复方拿不到后两个操作。实验没有模拟 restic、对象存储或加密实现，只检验哈希链无法证明未上传的后缀存在。

**影响：**【推断】从旧快照恢复后可以重新接受已吊销设备，或重新提供已忘掉的内容。界面告知异地尚未完成有帮助，但不能据此宣称恢复安全状态不倒退，也不能让恢复程序识别缺失。本条是 HUB2-003 剩余缺口的具体化，不是又发现一份独立的同类故障。

**建议：**把异地已持久提交的安全水位与“本机暂时生效”分开；只有异地提交后才承诺跨整机损毁有效。恢复开放需有能够证明安全日志新鲜度的依据，不能只验链。若无法证明，进入人工核对/重新配对的受限恢复，核对吊销和删除后再开放旧数据。需要同时覆盖“完全没有日志”和“日志可读可验，但末尾未上传”的演练。

### HUB3-002｜高｜旧 hub_instance 不能证明未知数据集是最新副本，自动对账会跳过恢复预览

**证据类型：**【文档核查】【复现】【推断】。

**位置：**`docs/hub/device-protocol.md:278`、`:297`～`:300`、`:308`；`docs/hub/hub-architecture.md:382`、`:902`～`:904`。

**证据与失败路径：**设备旧备份在实例 I0 下只含记录 A；之后两端都有 A、B。中枢完整搬家后换成 I1，仍有 A、B。此时设备从自己的旧备份恢复，按设计生成新 dataset，数据完整，记着上次同步的 I0，没有中枢签发的 from_snapshot。它同时满足“设备自己从旧备份恢复，应预览”与前一行“未知 dataset + 非当前 hub_instance，自动 manifest”。照前一行执行，B 因不在设备清单内被移入历史。实验复现了这一选择；若中枢未搬家，同一个设备恢复反而会正确返回 restore。没有随机碰撞、恶意设备或文件损坏参与。

**影响：**【推断】单凭两端给出的这些字段，无法区分“中枢恢复后忘记了真实现用数据集”和“设备也回退到了旧数据”。错误选择权威方会使较新的中枢副本退出现行数据，用户再恢复时拿到旧集合。历史可找回降低了影响，所以定为高，不把它描述为当场永久删除。

**建议：**旧 hub_instance 只作为发生过恢复/迁移的信号，不作为允许缺项删除的证明。未知数据集默认进入预览；若希望自动接续，需有可验证的数据集沿革或恢复凭据，并区分未回退的现用数据集与设备恢复生成的新数据集。complete=false 应是全表前置否决条件。加入“两端先后恢复”和“中枢迁移后设备回旧备份”的组合用例。

### HUB3-003｜高｜“没有登录状态”仍可能带有 URL 授权，不能据此允许 AI 自动点击

**证据类型：**【文档核查】【推断】。

**位置：**`docs/hub/hub-architecture.md:249`、`:857`、`:858`、`:1500`。

**证据与失败路径：**改动把自动点击的安全边界改为“匿名上下文（没有登录状态）”，并断言副作用不会以用户身份发生。但授权也可以在 URL 中，不依赖已有 Cookie 或浏览器登录存储。官方 [AWS 预签名 URL 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html) 明确描述 URL 持有人获得签发者授予的权限；此来源只证明“无登录存储仍能携带授权”，不证明任何 S3 下载链接会删除对象。

【推断】例如用户交给浏览器一个带访问权限的访客订单/共享资料链接，页面无需登录；页面上的链接通过监听器调用取消订单或修改共享状态的接口。按当前规则，这仍是匿名上下文里的点击，不是填写表单，既不经过已登录点击确认，也不经过填写/提交确认。文档写了“读公开内容”，但没有规定如何保证进入匿名上下文的 URL、页面状态和后续跳转都不携带用户授权。网络代理的内网地址过滤不能补这个条件。此为协议边界反例，未访问或操作真实订单、共享资源。

**影响：**AI 自动点击仍可能改变用户的外部业务状态，偏离 §0“有副作用最终由人确认”的承诺。单纯分两个浏览器上下文无法验收这条安全边界；这会影响首版 browser.act 的自动执行范围，定为高。

**建议：**明确“无身份公开抓取”的可执行入口条件：不接收家庭私密 URL、授权链接及成员状态，只从允许的公开来源进入；遇到未知授权来源、身份转换或不能证明属于该范围的跳转就转用户操作/具体确认。用户提供的授权链接直接走受保护上下文。未知站点不要用“无登录存储”作为自动点击许可；审核过的站点适配器可以另外开放明确动作。

### 跨境预算与第 0 步

【复现】按概要 `:560`～`:571` 的数字，热连接、无停说等待时：

| 路径 | 非模型部分 | 留给日本端模型首个可见回答 token 的时间 |
| --- | --- | --- |
| 成人首字 ≤ 3 s | 0.98 s | 2.02 s |
| 儿童首字 ≤ 3 s | 1.43 s | **1.57 s** |
| 成人首音 ≤ 4 s | 1.66 s | 2.34 s |
| 儿童首音 ≤ 4 s | 2.11 s | 1.89 s |

【推断】成人取 2.0 s 有少量余量；儿童取 1.6 s 是四舍五入，严格预算会超 30 ms，不能拿它当达标证明。还需计入实际停说检测、设备上屏和排队；冷连接可能与说话重叠，须按时间戳实测，不能机械地每轮再加或完全不计 0.8 s。主模型使用思考模式时应量首个 **content** token，而不是 reasoning_content、SSE 心跳或连接成功。
