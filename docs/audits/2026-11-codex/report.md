# ink 独立全面审计（2026-11）

## 1. 总体判断

**有条件可行：分层方向值得保留；当前读书/AI 纵切在模拟模型中有依据可行；当前代码尚未达到“第一版可扩展底座”的验收条件。真实硬件流畅度仍信息不足。**

【文档核查】用户优先级是底层调度、有限算力下的流畅体验、后续功能扩展，同时明确需要账户与服务器备份。审计因此从这些目标倒推，而不是把所有缺失的产品功能都当缺陷。按用户后续明确指示，**I 安全、隐私、合规及 D 中相应权限/隐私子项排除**；不扫描密钥/个人信息，不评估版权或发布风险。坏输入、崩溃、资源泄漏和数据丢失属于可靠性，仍在范围内。

【代码核查】`system/main.c:23`、`system/include/ink/sys/ui.h:1`、`platform/include/ink/osal.h:1`：应用/服务/OSAL/HAL 的分层、单 UI 所有者、集中显示/音频/存储/电源服务是合理基础。它们避免每个新应用重新决定如何刷新、播放或写 Flash。**不建议推倒重来，也不建议现在先铺满应用。**

【复现】正常与 Werror 的 26 项测试全绿，确定性和主要短场景数字可复现；但新压力实验暴露了 UI 积压、假持久化、取消不完整和音频与 Flash 冲突，关键变异也有漏检。因而“纵切能跑”与“底座能扩展”必须设置两个独立阶段门。

### 1.2 最重要的十条发现与修复顺序

1. **AUD-001**：先闭合资源准入/调度/降级契约，验证实际目标固件内存，而非凭剩余几 KiB 继续堆功能（已知内存紧张，补充架构复评）。
2. **AUD-003**：修复假持久化与失败资源泄漏，数据成功回执必须可信。
3. **AUD-004**：持续使用也必须周期检查点，不能仅靠“用户停下来”。
4. **AUD-002**：输入到目标页面的等待必须有界，合并过时翻页目标。
5. **AUD-006**：取消必须让旧结果失效，贯穿中枢、解码和播放。
6. **AUD-007**：内容修订与请求幂等必须可验证，避免旧 AI 结果及重发重复执行。
7. **AUD-008**：解决 Flash 与音频的共同预算，超时强写已产生 105 ms 断音（已知风险量化）。
8. **AUD-009**：失败内容必须回到可恢复状态，空书不能使系统崩溃。
9. **AUD-011**：修正 PQ 空闲时间戳维护，长空闲不能改变内核状态语义。
10. **AUD-012**：把上述语义加入测试，两个关键回归目前可以穿过全部预算。

建议顺序：**数据与失败恢复 → 资源/工作/取消契约 → 组合压力场景和硬件预算 → 显示优化 → 扩充产品功能**。这些工作可交叠推进；无需等待所有应用完备才测底座。

## 4. 发现（严重度排序）

计数：严重 0，高 10，中 7，低 2，信息 0。已知问题复评 2 条（AUD-001、AUD-008）；17 条新发现。`known=false` 指本条具体失效或反例未见于已知清单，不意味着所在功能此前被宣称完整。

### AUD-001 · high · 底座尚缺资源准入、任务取消和降级契约；AI 内存仅比硬门槛多 1.6～4.1 KiB

- 类别：H；**已知，复评**；置信度：high。
- 位置：`docs/system/foundation.md:92; system/main.c:23; profiles/metalio-plus.json:32`。
- 证据：【复现】EPD AI 最低内部+DMA 36960 B，PQ 34360 B；相对 32768 B 门槛仅余 4192/1592 B。将 DMA 预留从 64 减至 48 KiB，AI 最低 20576 B、DMA 16040 B，两项预算失败。【代码核查】main 顺序初始化服务，失败 panic；尚无工作准入、资源预留和分级降级协议。【推断】当前纵切不能证明增加同步、索引、输入法后仍流畅。
- 影响：首版可扩展底座尚未通过验收；16 KiB 是敏感性扰动，不是已测未来功能开销。
- 复现：运行 experiments/scenarios.py 的 heap-minus16-ai；核查 foundation §3 与 main。
- 建议：先约定服务依赖、每类任务资源上限、保留量、取消、过载策略；再用目标固件静态内存及并发高水位闭合预算。

### AUD-002 · high · 连续翻页造成数秒输入积压，区域合并没有合并过时目标

- 类别：D；新发现；置信度：high。
- 位置：`system/ui/ui_task.c:421; system/ui/ui_task.c:443; apps/reader/reader.c:169; apps/reader/reader.c:234; system/display/display_service.c:85`。
- 证据：【复现】40 次 NEXT，按住 80 ms、间隔 250 ms，80 个按下/松开事件全部投递、40 次翻页；首次可见 p95=4509.936 ms，TEXT 稳定 p95=4969.851 ms，最大 5200.378 ms；普通场景分别 336.107/722.333 ms。【代码核查】24 项 UI 队列可无限等待；阅读加载、分页、绘制在 UI 任务内。
- 影响：低算力与墨水屏下，输入可积压到数秒；添加后台工作会进一步侵蚀前台响应。
- 复现：experiments/scenarios.py rapid-4hz，脚本结束前留 20 s 排空；对比 reader_basic。
- 建议：为最新页面目标合并过时请求，分块后台布局，设定 UI 工作上限和可取消代次；分开输入确认与画面稳定指标。

### AUD-003 · high · Flash 写满时队列清空被误认为持久化，且错误路径泄漏文件资源

- 类别：D；新发现；置信度：high。
- 位置：`system/storage/storage_service.c:133; system/storage/storage_service.c:293; system/storage/storage_service.c:320; system/include/ink/sys/storage.h:41; apps/reader/reader.c:226`。
- 证据：【复现】64 KiB LittleFS 写满后，write_atomic 返回 0，pending=0，底层文件 size=-1；失败大文件每次内部内存减少 512 B。小文件读取缓存得 1024 B，但底层文件仍不存在。【代码核查】n==len && hal_fs_close(f)==0 短路跳过 close；失败作业仍被移出队列；pending 注释声称 0=all durable。
- 影响：进度/未来备份可能显示成功但实际丢失；持续失败消耗有限内部内存。
- 复现：service_probe storage：64 KiB 分区，28 个 4096 B 文件及 12 个 1024 B 文件；分别查缓存和 HAL 文件大小。
- 建议：所有路径关闭文件；区分 accepted/committed/failed；显式上报 ENOSPC，调用方收到 durable 确认后才清 dirty。

## 5. 数字与模型结论

逐项表与口径见 [numbers.md](numbers.md)。关键变化是管线表的首次反馈 p95=282 ms 已过时，当前为 336.107 ms；它没有超越 350 ms 硬门槛，但裕量只有 13.893 ms。不能用旧表的 68 ms 裕量支持新增并发功能。

【复现】默认 EPD 普通翻页 p50/p95=708.512/722.333 ms；PQ 原样串行=907.585/1002.379 ms，假设重叠=654.311/714.410 ms。**后者是档案时序假设，不是已经实现的并发驱动。**【代码核查】规划写 hot/tile_plan，扫描读这些状态，直接并行存在状态依赖；分带追随或双缓冲需要新实现和新内存账，不能只开字段。

【复现】LVGL/文本相关成本×2 后 reader TEXT p95=796.915 ms（基线722.333，+10.3%），AI 流程仍运行；这只检验该组标注的敏感性，不代表所有真实 CPU 路径。默认端口送行采用 28.9 µs×1.1≈31.8 µs，而不是全局×1.3；档案已明确引用上游约32～34 µs的约束。这是**有说明的特例**，不是一律悲观的证明。改50 µs出现18次欠载，说明该结论对真实送行成本敏感。

【代码核查】虚拟双核是逻辑并行、主机任一时刻仅一任务执行；可复现优先级和资源竞争，不能证明真实双核内存序、锁外共享字段或 ISR 并发正确。host 栈估算也不是目标栈验证。TLS/Opus/网络/面板/电流仍含替身和估算；没有实物就不能保证声音质量、视觉残影、续航或可接听待机。

【复现】ISS host/target 校验值一致，配置和 PQ 汇总可复现；CoreMark 拟合 3.083/MHz、较参照低约10.1%。【推断】用 P4/S3 PSRAM 数据拟合 S31 可帮助约束量级，但不足以证明每个工作负载都保守。缓存布局、指令混合、双核争用、厂商扩展指令仍需实机校准，不能把 ISS 的“测量”写成目标芯片实测。

## 6. 实验、预算、模糊测试和静态分析

运行入口和实际日志索引见 [experiments/README.md](experiments/README.md)。

- 【复现】26 项原测试覆盖自检、死亡测试、确定性、主页/读书/AI/待机、老化/断电、管线、PQ、盖板键及可移植性冒烟；这是很好的回归起点。
- 【复现】变异5个：送行变慢、Flash守卫移除、睡前quiet移除被杀死；PQ空闲时钟关闭和盖板回退单触点存活。不是“预算全部无效”，而是缺少关键语义断言。
- 【代码核查】`optional:true` 允许未产生的错误计数缺席，适合零错误指标；不能仅凭 optional 判无效。若指标是必须出现的成功事件则应要求存在。`target_max` 记录设计目标但不导致硬失败，报告须与 `max` 区分。详见预算清单。
- 【复现】新增场景包括4Hz连续翻页、快速短按、刷新中锁屏、AI断网、混合输入、2h虚拟待机、CPU×2、内部堆−16KiB、送行50µs、其他两设备档案；观察到的“运行结束”不等于有对应预算通过，压力实验按目标指标解释。
- 【复现】连续保存初版脚本被默认30s结束时间截断，已丢弃其结论；改为断电后显式end，186.05s反例才有效。无4G最初改了未被读取的字段，该实验无效、未用于续航结论。
- 【复现】固定种子20000组 JSON/布局输入未额外触发ASan；布局使用固定小字形替身，仅证明边界/推进约束，不能验证真实中文字形质量。1000条随机hub消息、24档案、24脚本为有限随机集，不是覆盖率引导fuzzer的等价物。
- 【复现】静态工具在50个自有翻译单元上运行：GCC analyzer 3条、Clang analyzer 0条；clang-tidy 978条自有唯一诊断；cppcheck 161条唯一诊断，其中106条自有。统计口径为文件/行/检查项去重，不是缺陷数。
- 【代码核查】重点分诊：空元素qsort、二进制memcpy非NUL、数组成员误识别、负数右移等不足以作为确定缺陷；ISS ELF分配失败后未检查的指针值得后续OOM注入，尚未复现，不混入19条。tidy大量通用API/返回值/参数交换/转换告警尚未逐条关闭。本报告不开展安全规则审计。

### 7.3 到货后的验证顺序

【文档核查】SP-00～14已覆盖主要硬件不确定性。建议按依赖排序：先SP-00/03闭合芯片/PSRAM/静态占用/堆与DMA；同时测SP-01送行成本及SP-02/12的Flash-音频连续冻结；随后SP-06/07/10实测调制解调器、来电唤醒与功耗，SP-13验证光学响应，SP-14校准各状态电流。第一周目标应是把关键未知变成测量，不承诺一周完成完整产品验收。

【推断】补充现有计划：ENOSPC与坏内容恢复、持续活动断电检查点、取消后迟到结果、重复请求、100次重连、24h活跃任务/成员切换、8MB与内存不足降级。长时间静止的2h模拟不能替代这些生命周期压力。

【复现】阻塞等待送行的候选E将render p95从216.174降至39.740ms，开书从1203.104降至1115.076ms，普通翻页几乎不变。可作为D-35实机候选，不宜因为主机模型更快就立即替换默认。硬件IRAM、中断和队列行为仍须测量。
