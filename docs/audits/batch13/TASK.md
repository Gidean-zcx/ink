# 一批合并后的独立质量复查：batch13

范围：`git diff 61f55c19 d52861ef`，这一批合进来的任务：docs/tasks/port-hal-1.md、memo-record.md、i18n-1.md、dictation-flake.md、audit12-fix.md、weather.md、update-flake.md（各自的 REPORT.md、REVIEW.md 在同名目录里），以及主会话合并时改的：设置页每行缓冲的上限（`settings_pages.c` 的 `ROWS_MAX`）、媒体测试等积压事件发完再切换家人、AI 面板合并冲突、设置首页网络行的英文。
这些任务由 Claude 子代理写、主会话逐个审过并合并；这里是整批的一次独立复查，只做这一轮。

要看的：
1. 正确性：验收里写的行为是否真的成立；断电、重启、换成员、卡拔出、断网时数据会不会丢、会不会串到别的成员。
2. 规则有没有放松：确认规则（D-105，录音、发短信等）、孩子成员的限制、秘密字段不进快照和日志；设置的 `via` 转调有没有漏洞。
3. 按钮和 AI 是否走同一个能力，页面快照是否和屏幕一致；模块划分和“能调用的都给 AI 用”。
4. 资源：内部 RAM、栈、PSRAM、固定上限；**特别查一遍各页面“按行数分配的固定数组”（例如 `values[8]`、`args[8]`）和实际行数是否匹配**——batch13 里出过一次第 9 行写出数组的越界，Linux 的 gcc 带越界保护会中止，macOS 和 ASan 发现不了。
5. 并发和时序：这一批查出两个“先写状态、后做收尾”的竞态（听写、更新下载），类似写法在别的服务里还有没有；后台执行器上同步打开数据集合会卡住别的作业（memo-record 报过）。
6. 中英文：`TR()` 的用法、译文表检查、切换语言后页面是否都重画；S31 端口的新代码有没有明显错误（中断、锁、引脚出处）。
7. 可移植：CI 在 Linux 上用 gcc 编译、警告当错误、带越界保护；测试是否依赖主机的目录顺序或时间。

时间：最多 1 小时，只做这一轮，先查最可能出严重、高问题的地方。

怎么做：只读产品代码和测试，可以在自己的构建目录里编译、跑测试、写一次性实验；不改产品代码，不提交。报告放在最后一条回复里，每条写等级（严重、高、中、低）、文件和行号、复现办法、建议的最小修法；推测的写“待证实”；末尾写计数：SEVERE=n HIGH=n MEDIUM=n LOW=n。
