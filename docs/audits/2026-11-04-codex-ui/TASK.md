# 审计任务说明（2026-11-04 系统界面设计，交给 Codex）

你是独立审计方。对象是本项目**第一版系统界面和系统应用的设计**，不是代码。用户的要求原话：“用codex 审计一下设计 看看方方面面是否有问题或者遗漏”。

产品是家庭共用的 AI 原生个人设备：4.7 寸电子纸（684×1216，297 dpi，16 级灰），ESP32-S31，触摸加实体键，Wi-Fi 和 4G。设备是薄端，AI 经家庭中枢运行。

用户已经确认了总体视觉语言和主页结构（D-59～D-61：卡片加胶囊、三屏主页加固定 Dock、会频繁变的只用黑白）。**不要提议换一种风格**，除非某一点在这块硬件上确实行不通。要找的是：错误、不一致、走不通的流程、遗漏的页面和状态、和需求或硬件冲突的地方。

## 2. 要查什么

**A. 完整性（最重要）**：对照需求和产品文档，逐条判断界面有没有覆盖。列出遗漏的页面、流程和状态，分“首版必须”和“可以晚点”。至少想过这些：

- 孩子成员看到的主页和限制（R-030、D-16）。
- 空、错误、离线、加载中：没网、连不上中枢、AI 出错或超时、没插 SIM、没有 TF 卡、存储满、短信发送失败、通话失败或不支持、Wi-Fi 密码错、蓝牙配对失败、更新失败或回滚、PIN 输错和忘记 PIN。
- 电量：低电量、充电中、关机界面、唤醒。
- 后台活动：听书或朗读时在哪里控制和停止，通话中切到别的页面，AI 在后台做事的进度和回执，“在听”标记。
- 二级页面：加闹钟、加提醒、编辑联系人、写备忘、计时进行中、相机扫码结果、文件操作、加成员、蓝牙配对、搜索结果、长按图标的菜单、主页编辑。
- 没有画的内置应用（阅读、听、报纸、单词）对系统界面有什么要求。

**B. 流程走得通吗**：首次开机到能用；锁屏到进入（成人和孩子）；来电打断 AI、闹钟打断朗读、通话中来闹钟；AI 要发短信的确认；语音输入失败退回键盘；页面之间的跳转和返回路径有没有死路。

**C. 墨水屏和硬件上行不行**：

- 刷新：每种操作要刷多大、用哪种波形，和 `foundation.md` §4 对得上吗。规则“会频繁变的只用黑白”，实际页面有没有违反（比如拨号盘、PIN 键盘、列表行按下）。点阵遮罩、大块黑色、圆角和圆环的代价。文档里的刷新说法和时间估算是否自洽。
- 锁屏显示的时间每分钟更新，和浅睡、“这一页”不刷新、待机耗电（D-37、D-38）冲突吗。
- 可读性：细字、小字、灰字在 297 dpi、16 级灰、对比度有限的面板上；前光；残影。
- 实现：LVGL、字体预算（SP-05）、图片、内存预算（`foundation.md` §3）能不能支撑。相机取景在墨水屏上能做成什么样。

**D. 交互一致性**：手势之间的冲突（左右翻屏、左边缘返回、顶边下滑、底边上滑、阅读翻页、键盘）；实体键（AI、电源、音量、HOME、上一页、下一页，Plus 没有 BACK）在每种页面的含义；不滚动、只翻页的规则能不能撑住这些页面（通知多了、聊天很长、键盘弹出时）；触控目标（规范写不小于 82 px）；返回和关闭的位置；破坏性操作；同一件事不同页面的叫法和样式。

**E. AI 优先（G-002）**：每个页面对 AI 可见、可操作吗；AI 入口；确认卡覆盖哪些动作；AI 的回执和失败怎么呈现。

**F. 隐私和安全**：锁屏上露出什么；家庭共用下谁能看谁的短信、通话、备忘、照片；孩子的限制；剪贴板；语音输入；相机；传输时的访问控制；恢复出厂；D-33。

**G. 文档**：规范、依据、分类、缺口表和画板之间有没有矛盾；`docs/system/ui-dependencies.md` 的“现状”对照代码对不对，有没有漏掉的底层依赖，开发顺序合理吗；日期、农历等示意内容有没有错。

**H. 视觉细节**：从截图看对齐、层级、拥挤、截断、不一致。只记真正影响使用或观感的。

重点是**严重**和**高**；中、低也可以记，但不要为了数量去找。定级：

- **严重**：照这个设计做，用户完成不了核心任务；或者有安全隐私问题；或者在这块硬件上做不到而且没有退路。
- **高**：关键流程或状态缺失；在墨水屏上明显行不通；和已定的需求或决定冲突。
- **中**：明显变差、不一致、有歧义，但还能用。
- **低**：细节。

## 3. 规则

- 不接触设备，不读 `~/Documents/Workspace/ink-hw/`，不用联网。

## 4. 写法与格式

- 用中文，说人话：用户不是每个术语都熟，结论要让人一眼看懂。代码标识、路径保持原样。
- 每条结论标明证据类型，推断不得写成事实：**【画板】**（画板名，必要时写行号或截图）、**【需求核查】**（R、G、D 编号）、**【文档核查】**（文件和章节）、**【代码核查】**（`文件:行号`）、**【推断】**。
- `report.md`：
  1. **一页结论**：这版能不能作为开发依据；最大的几个问题；最重要的遗漏。
  2. **需求覆盖表**：和界面有关的 G、R 编号，每条写已覆盖、部分、没有、不适用，以及对应画板。
  3. **问题清单**：编号 AUD-UI-001 起，每条含定级、领域（A～H）、标题、证据、位置、影响、建议。
  4. **遗漏清单**：缺的页面、流程、状态，每条写为什么需要，以及首版必须还是可以晚点。
  5. **对缺口表的校对**：`docs/system/ui-dependencies.md` 的错和漏。
  6. 结尾写明看了什么、哪些没查（以及为什么）。
- `findings.json`：数组，每项 `{"id","severity","area","title","evidence_type","locations":[...],"impact","recommendation"}`。
