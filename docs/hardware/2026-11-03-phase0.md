# 第 0 步：只读识别、整片备份、出厂固件日志（2026-11-03）

执行：本机 Claude Code，在用户的 Mac 上。步骤与规则按 [phase0-prompt.md](phase0-prompt.md)（原为 Codex 编写），出入见 §8。

**对设备只做了读操作，没有写入。** 整片备份、原始日志、NVS、eFuse 全文只留在用户电脑上：仓库同级目录 `ink-hw/bringup-20261103/private/`，第二份备份放在本机另一个不同步云端的目录。本文是脱敏摘要。

证据类型：未注明的都是**实测**，来源是 esptool/espefuse 的读出、备份文件的离线解析，或出厂固件的串口日志。

## 结论

- **接口**：USB-C 接的是 S31 自带的 USB 串口/JTAG（全速）。esptool 能自动复位进下载模式，不用按键。
- **安全**：安全启动、Flash 加密都没开，eFuse 全是出厂默认值，下载模式没有被禁用。第 1 步可以按计划写入，任何时候都能用备份整片恢复。
- **固件**：当前从 ota_0 启动（出厂固件 2.0.66），ota_1 为空。分区表与上游 690a023 完全一致。
- **PSRAM 16 MB**（AP Memory 第 4 代，八线，200 MHz）。模拟器应以 16 MB 为准。
- **Flash**：Puya PY25Q128HA，16 MB，DIO 80 MHz。手册支持编程/擦除挂起，但 ESP-IDF v6.1 的通用驱动不对这个厂商开启挂起（代码核查）。
- **内部 RAM**（出厂固件）：可用于堆的是两段，265 KiB + 16 KiB，另有 31 KiB RTC RAM；其中 64 KiB 预留给 DMA/内部分配。静态占用 226.7 KiB。
- **刷新时序**：整屏每相 15.08～15.10 ms，与模拟器“上游管线复现”预测的 15.1 ms 一致。小区域局刷每相 12.0 ms（相长下限）。出厂固件翻页只用 20 相，整次约 0.47 s。
- **待机**：空闲 180 s 进待机。待机时切断 4G 电源、芯片浅睡，USB 随之断开。

| 项 | 值 |

| 设备 | Espressif “USB JTAG/serial debug unit”，VID:PID **0x303A:0x1001**，全速 12 Mb/s |

上机时要注意的行为：

- **每次启动后约 1.9 s，USB 会重新枚举一次**，端口消失约 0.3 s，这段日志会丢。
- **待机时 USB 断开**：浅睡期间端口消失。esptool 必须在设备醒着时运行。
- **复位只在屏幕空闲时做。** TPS65185 的 VCOM_CTRL、PWRUP、WAKEUP 接在 TCA9555 的 P00～P02 上（上游 config.h，代码核查），ESP 复位不会改变 IO 扩展芯片的输出。如果复位正好落在刷新中，芯片在下载模式里，屏幕高压却一直开着。出厂固件每次刷新以 `PowerHw: cpu` 开始、以 `EpdRefresh: … cost=` 结束，脚本据此判断空闲，并避开整分钟时钟重绘的时刻。
- **打开串口不能复位芯片。** 对 USB 串口/JTAG，“RTS 有效、DTR 无效”就是复位；pyserial 打开端口时先撤 DTR 后撤 RTS，会在中间造成一次复位。`serial_log.py` 绕开了这个问题。

**PY25Q128HA 手册要点**（上游文档：Puya 数据手册 Ver0.3，立创商城镜像，2026-11-03 查阅）：

| 项 | 典型 | 最大 |
| --- | --- | --- |
| 页编程（256 B） | 0.5 ms | 2.4 ms |
| 4 KB 扇区擦除 | 50 ms | 240 ms |
| 32 KB 块擦除 | 0.16 s | 0.8 s |
| 64 KB 块擦除 | 0.3 s | 1.2 s |
| 整片擦除 | 50 s | 120 s |
| 挂起延迟 tESL / tPSL | — | 30 µs |

- 挂起命令 75H、恢复命令 7AH，与 IDF 通用驱动的默认操作码相同。
- 恢复后至少隔 100 µs 才能再次挂起，否则擦写没有进展。
- 供电 2.7～3.6 V，时钟最高 133 MHz。

**ESP-IDF v6.1 的挂起支持**（代码核查：`components/spi_flash/spi_flash_chip_generic.c` 的 `spi_flash_chip_generic_get_caps`，v6.1 标签，2026-11-03 查阅）：

- 通用驱动只给厂商 ID 0x46（XMC）、0x20（XMC-D，经 SFDP 判断）和 0xa1（FM）开挂起能力。
- IDF 也没有 Puya 专用驱动。
- 所以原版 IDF 在这块板上**不会**做擦写自动挂起。要用，就得自写芯片驱动，给 0x85 开这项能力，并实测验证。

## 6. 运行日志：刷新、电源、4G

**刷新时序**：共 66 次刷新，`EpdTiming`/`EpdRefresh` 成对统计，见 `epd_stats.py`。

| 类别 | 次数 | 每相（中位数，范围） | 整次耗时（中位数，范围） |
| --- | --- | --- | --- |
| 局刷 20 相，小区域（状态栏等） | 28 | 12.0 ms（12.0～12.5） | 412 ms（401～440） |
| 局刷 20 相，大区域（翻页等） | 15 | 14.6 ms（12.7～15.0） | 466 ms（431～490；一次 713 ms 含屏幕电源重试） |
| 局刷 49 相（开书、回主页等换屏） | 9 | 15.08 ms（15.08～15.14） | 916 ms（906～942） |
| 全刷 48 相 | 14 | 15.10 ms（15.08～15.21） | 909 ms（899～945） |

- 66 次刷新全部 `completed = frames`、`err = 0x0`，**没有欠载或中止**。单相最长超过 16.5 ms 的有 5 次，超过 20 ms 的有 1 次（24 ms）。
- **每相时长随更新面积变大而变长**，最低是 12 ms 下限。这说明送行受行准备速度限制，与模拟器的模型一致。
- 整屏每相 15.08～15.10 ms，与[平台与模拟器 §5.4](../system/platform-and-simulator.md) 方案 A“上游管线复现”的 **15.1 ms** 吻合。该方案按每行 33.4 µs、奇偶分行、预填 192 行计算，这个数来自指令级拟合。本端口设计（D-35 方案 B）预测整屏每相 12.9 ms，要靠第 1 步实测每行准备时间来验证。
- 每次刷新在各相之外还有约 170～185 ms，包括屏幕电源上下电、比对和回写。这里分不出各部分各占多少。
- 出厂固件的“balanced”档：翻页和小区域更新用 20 相，换屏用 49 相，全刷用 48 相。我们档案里写的是 GC16 36 / GL16 37 / DU 20 相，依据是上游源码的描述。**翻页相数不同**：20 相整次约 0.47 s，模型里 37 相是 0.71～0.81 s。20 相的画质和残影是否可以接受，要靠实机观察（SP-01）。
- 翻页：排版约 43～54 ms，渲染整页约 49～60 ms；翻页期间 LVGL 报 `lv_timer_handler slow` 320～360 ms。按键时刻日志里没有，所以测不出“操作到完成”。
- 开书：从书架点开到正文显示约 2.1 s，其中一次屏幕电源上电重试多花约 0.3 s。

**异常**：开书时出现过一次 `pca9555_set_value: ESP_ERR_TIMEOUT` → `TPS probe failed` → `TPS power-on retry 1/3`，重试后正常。IO 扩展芯片和触摸共用 I2C 总线，以后的驱动要保留重试，并统计发生次数。

**电源与待机**（出厂固件 `PowerPolicy`）：

- 空闲 180 s 进待机，联网宽限 30 s，待机 1800 s 后关机；允许浅睡。
- **进待机的过程**：
  1. 全刷一次停放画面，约 0.9 s；
  2. 卸载 TF 卡；
  3. 拉低 P14，**切断 4G 模组电源**；
  4. 每次浅睡最长 60 s，周期醒来。
- 这就是上游的“锁屏即断开”，与我们 D-37 选的“保持在线”不同。
- 电源键：短按切换待机；**长按 3 s 关机**，关机时全刷显示关机画面后断电。
- 电池 4.33～4.37 V，99～100%，接 USB 时在充电。

## 7. 整片备份

| 项 | 值 |
| --- | --- |
| 方式 | `readout.py`：等屏幕空闲 → 复位进下载模式 → 读安全信息（加密或安全启动任一开启就复位回固件并停止）→ flash-id、MAC、eFuse → **在同一次连接里**整片读两次 → `verify-flash` 与设备比对 → 复位回固件 |

| 读取速度 | 70.3 s / 68.4 s，约 240 KB/s |
| 存放 | `ink-hw/bringup-20261103/private/`，第二份在本机另一个不同步云端的目录，SHA-256 已核对 |

## 8. 与提示词的出入、异常与未完成

- **执行者**：提示词原本写给 Codex，这次由本机 Claude Code 执行。资料目录按用户要求放在当前工作区，即仓库同级的 `ink-hw/`，而不是 `~/work/ink-hw`。
- **识别和备份放在一次连接里**（见 §7），不是每条命令都复位一次。前两条识别命令（chip-id、flash-id）是逐条复位的，复位后固件都正常运行。
- **复位前等屏幕空闲**：这是提示词之外加的保护，原因见 §2。
- **工具问题，都绕过了，设备没受影响**：
  - espefuse 5.6 的 `main(esp=…)` 不接收外部连接，因为 `EspefuseGroup.parse_args` 没有把连接放进上下文，于是报“缺 --port”并退出。这次退出导致芯片在 stub 里停了约 3 分钟，进入时屏幕是空闲的。之后用 `--resume` 无复位接上，读完 eFuse。改用 `init_commands(esp=…)` 后正常。
  - 复用连接时 `read-flash … ALL` 测不出容量，改为按 JEDEC 容量字节传 16 MiB。这次出错按设计复位回了固件，随后整套重做。
  - 第一次运行时设备已在待机，端口不存在，什么都没做。
- **TF 卡没有备份**：
  - macOS 挂载 FAT 卷时会写入 `.fseventsd`、`.Spotlight-V100` 等文件，违反“不改不建”；读裸设备又需要 root。
  - 可选做法：用户把卡取下，装进带写保护开关的读卡器；或由用户自己用 `sudo dd` 读出。卡里是出厂内容：书架有一本书，另有日志目录。
- **照片与标签**：用户确认“关于本机”显示 2.0.6.6，序列号和 IMEI 不知道。**主板版本号（V1.x）没有确认**（RK-01）：日志证实了面板型号 E0470A14-AF，出厂固件能正常驱动屏幕，但印刷版本号未知。
- **待机唤醒**：出厂固件每次浅睡最长 60 s，醒来后会短暂出现 USB。日志里有从待机醒来又进待机的完整过程（`share/runtime_1.txt` 开头）。

## 9. 对后续的影响（建议，未执行）

**第 1 步写入方式**：USB 串口/JTAG + esptool 自动复位，不用按键。建议把测量固件写进**空的 ota_1**，再把 otadata 改成指向 ota_1，**不碰 ota_0 里的出厂固件**。

- 复原：写回备份里原来的 otadata（0xd000，8 KB），或擦除 otadata，引导程序都会回到 ota_0。
- 最坏情况：整片恢复。
- 测量固件要沿用这张分区表，Flash 参数用 DIO 80 MHz、16 MB，芯片最低版本 v0.0。
- 具体命令和复原步骤写入前另给用户确认。

**模拟器档案的写回**：

- PSRAM 按 16 MB；
- 内部堆按“一大段 + 16 KiB 一段”的结构，DMA 预留 64 KiB 已证实；
- Flash 擦写时间按 PY25Q128HA 手册；
- 刷新时序：上游复现已被实测证实，翻页相数的差异要记录。

已写回：分支 `claude/phase0-writeback`，改动和对场景的影响见[平台与模拟器 §5.7](../system/platform-and-simulator.md)。

**D-35**：上游 C 代码的成本已经间接证实（整屏每相 15.1 ms）。本端口设计还差第 1 步实测的每行准备时间。

**D-36 / SP-12**：手册说可以挂起，但原版 IDF 不对 Puya 开启。要用自动挂起，需要自写芯片驱动并实测（软件方案，不涉及硬件），否则维持 D-36 的方案 A。

**SP-01**：`EpdTiming` 的相周期已经拿到。光学时延（操作到可见变化）和残影，仍要按 SP-01 用测试程序加慢动作录像来测。
