## 发现

- **S31 的 UART0 默认引脚就是 GPIO58/59，也就是 NT26 的 UART2**：控制台走 UART0 的固件会把日志送进模组。自检固件把控制台设成只走 USB；端口固件也要这样设（记进 backlog）。
- 加速度计出厂配置三个轴都没开，“拿起亮屏”在真机上要先开轴（accel-use 的驱动会写 CTRL1，上机时核对）。
- 4G 模组要先写帧协议层才能对话（端口后续批次）。

## 第二轮和第三轮：浅睡把 USB 弄丢了

两轮都是我自己设计的浅睡测试，**没有先看原厂代码**。

| 轮次 | 做法 | 结果 |
| --- | --- | --- |
| 第二轮 | 自检加了开加速度计的轴、400 kHz I2C、读 flash、电流，最后用 RTC 定时浅睡 2 秒 | 进浅睡后再没有输出，端口还在但不说话；脚本按出错处理，写回出厂 otadata 和 ota_1，比对一致 |
| 第三轮 | 一开机先浅睡，醒后软件断开再接上 USB，再重启 | USB 再没回来，复原脚本等了约 20 分钟。请用户按电源键后，17:17 端口出现约 12 秒：写回出厂 otadata 和 ota_1 两处，写入时工具自带的校验都通过，otadata 单独比对也一致；比对 ota_1 时端口断开，原因没有查明。之后设备不再出现在电脑上，17:26 用户短按电源键仍没有；17:33 用户拔插 USB 线后设备开机 |

**结果**：出厂固件从 0x80000 照常启动、开机刷屏正常，设备回到平时的状态。两处写回在写的时候都通过了工具自带的校验，otadata 也单独比对一致。**ota_1 的整段比对还没做成**：拔插之后 USB 连接一直不稳（读控制台时每十几秒断一两次，下载模式下刷写工具握不上手），我让芯片回到出厂固件后停手，等连接稳定时再补。期间还有一个我自己的失误：停掉旧的复原脚本时只停了外层进程，真正的解释器还开着端口，两个脚本抢了一阵端口。

**之后查原厂代码，才知道原因在哪**（出处都在 `ink-hw/upstream/Metalio-E-INK4-Plus`，提交 690a023）：

- **S31 的浅睡要打补丁才可靠**：原厂在 IDF 浅睡外面包了一层，入睡前把 PSRAM 时钟交给晶振、醒后先恢复 MPLL 校准的前置条件再切回（`main/boards/common/power_policy/s31_sleep/`，说明在同目录 `README.md` 末节，引用乐鑫提交 9726078b）。我的自检直接调 IDF 浅睡，醒后很可能没跑起来【推断】，这能解释第二轮的“端口在但不说话”。
- **醒后要专门把 USB 串口叫回来**：原厂在电源键唤醒、SD 恢复之后才做：开总线时钟、断开 pad、等 150 ms、恢复 PHY 默认值、接上 pad、最多等 800 ms 看主机连上（`power_hw.cc` 的 `ReviveUsjAfterSdRestore`，注释写明“醒后立刻踢 pad 无效”）。定时醒来不做这一步，所以待机中的出厂固件只有按电源键才会重新出现在电脑上。
- **唤醒链路只有一条**：电源键 P17 → 扩展芯片中断 → GPIO2 低电平（EXT1）。S31 只有 GPIO0～7 能做这种唤醒（IDF `soc_caps.h` 的 `SOC_RTCIO_PIN_COUNT 8`），BOOT 键 GPIO61 叫不醒浅睡。
- **电源键**：短按进出待机；按住 3 秒由**固件**发关机脉冲（扩展芯片 P13，高低各 100 ms、15 次，每 200 ms 重复一轮）。我们自己的固件卡住时长按没用，没有复位键；原厂说明里提到按得足够久时电源电路会强制断电，时长没写。
- 出厂固件待机累计 30 分钟（默认）会自动关机。调频用固定频率（最低=最高），不在两个频率之间切。

## 教训

- 无人值守的测试里不放任何会断开 USB 的步骤（浅睡、关 USB、改 USB 引脚）；要测浅睡，先照原厂代码移植补丁和 USB 恢复，再在有人能按键的时候测。
- 硬件机制先查原厂代码（规则第 6 条）。
- 复原脚本不要在端口刚出现时立刻复位进下载模式：那时引导程序可能还在跑。改成等出厂固件启动并且屏幕空闲 15 秒后再接手。

**发现**（都是只读读数，出处见原厂代码）：

- **充电芯片的输入状态码在插着线、正在恒压充电时也是 0**：第五轮读到 STATUS1（0x1E）= 0x10，即充电状态 2（恒压）、输入类型 0；原厂驱动把 0 解释成“无输入”（`common/power/cx25601n.cc:678`）。输入限流读到 960 mA（0x06=0x00、0x07=0x03，原厂换算 `:233-254`），不低，原厂初始化也不设它。负载下电池小幅放电（空闲 0、两核满载 -5 mA、Wi-Fi 扫描 -8 mA，满电恒压时）不是故障。结论：**判断“插着电”不能看输入状态码**；原厂显示充电时看的是电量计电流（大于 +5 mA 且不满为充电，小于 -5 mA 为放电，`common/power/bq27220_gauge.h:39-40`），我们的电源服务照这个做（记进 backlog）。我先前“限流太低”的猜测是错的。
- **加速度计的寄存器状态取决于出厂固件最后在干什么**：第四轮读到 CTRL1 = 0x57（原厂工作时的值），第五轮是 0x10（原厂待机前调成 1 Hz 低功耗）。我们的驱动必须每次完整初始化，照原厂 `common/sensor/sc7a20h.cc:22-31` 的 CTRL1～CTRL6 和 AOI1 设置。读数正常：平放时 z 约 1029 mg。
- **闪存读速 7.4 MB/s**：原厂、自检、我们的端口都是 DIO 80 MHz（原厂 sdkconfig），一致；这是走闪存驱动接口读的速度，内存映射读可能更快，以后测。

- **时钟芯片的中断线 P16 读成 0，不可靠**：原厂把 P16 当低有效的事件输入，读到低就清标志（`periph/metalio_rtc.cc:33-38`）；我们读到 P16 为 0 时，时钟芯片 CTRL2 = 0x00（没有标志），多半是这条线悬空被读低（hardware-parity 第 13 项）。原厂的浅睡也不用它唤醒，定时醒来用芯片自己的定时器（电源策略 README 的 P16 一行）。结论：闹钟唤醒照原厂用芯片定时器，不依赖 P16。
