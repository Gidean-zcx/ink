# 第 2 步：第一次自动上机的分析（2026-11-06）

原始数字见[自动生成的报告](2026-11-06-bench.md)。设备上写过的地方都已复原，和备份逐字节一致。本文所有结论都是【实测】，除非另外标明。没有测量电流功耗：测试时插着 USB 在充电。

## 回答了什么

| 问题 | 结果 | 意味着什么 |
| --- | --- | --- |
| 内部内存够不够 | 开机可用 274 KiB（最大连续块 164）。Wi-Fi 约占 43 KB。屏幕开后可用 179 KiB（最大连续块 76），历史最低 115 | 够，但测量固件没有 LVGL、TLS 和系统任务，Wi-Fi 和屏幕也没有同时开。两个同时开估计还剩约 145 KiB【推断】 |
| PSRAM | 16 MiB，屏幕开后可用约 14.7 MiB | 很宽裕 |
| Flash 读 | 7.1 MB/s（模拟器原来按 20） | 模型已改。翻页时读字形比原来估计慢约三倍 |
| Flash 写 | 4 KB 平均 7.7 ms，256 KB 擦除 148 ms | 这次的擦除量到的是空扇区，数字偏好，下一次改了测法 |
| 开一次密码 | PBKDF2 3000 次 242 ms（设计估计约 100） | 能接受，但比估计慢一倍多 |
| 屏幕 | 整屏清屏 923 ms，GC16 整屏约 750～780 ms，DU 小方块 325 ms | DU 不随面积变，是固定的波形时长 |
| RTC 中断线 P16 | 定时器 2001 ms 响，P16 同时变化，平时为低 | 线是好的，之前“P16 一直低”的疑问解决了 |
| TF 卡 | 读 9 MB/s（20 MHz） | 够放书和音频，不适合放要内存映射的字库 |
| Wi-Fi | 启动 237 ms，扫描 2.5 s，信号最好 -62 dBm | 正常 |
| 4G 模组 | 没有回应 | 没有回答问题：没拉 MRDY/SRDY，也可能没上电。下一次改了 |
| I²C 上的芯片 | 19、20、38、51、55、6b 都在，触摸、加速度计、RTC、电量计、充电芯片都读得到 | TPS65185 在电源关着时不应答，屏幕一样能工作 |

## 没有回答的

- **Wi-Fi 和屏幕同时开的内存**：两项没有同时开过。
- **USB 串口丢行**：屏幕工作时丢了几行（`panel_init`、`panel_temp`），已加等待，下一次看。
- **功耗**：要拔 USB、用电量计，单独做。

## 屏幕、触摸、加速度计的方向

用户看到画面上下颠倒。查了原厂驱动和我们自己的代码：

| 部件 | 结论 | 证据 |
| --- | --- | --- |
| 显示 | 测量固件写错了，系统的映射是对的 | 【实测】`EPD_ROT_PORTRAIT` 倒着；我们的 90° 等于 `EPD_ROT_INVERTED_PORTRAIT`。第三次上机的照片确认方向正确（[记录](2026-11-06-phase3.md)） |
| 触摸 | 原始坐标就是竖屏坐标，和界面逻辑坐标相同 | 【实测】第三次上机点了四个点，没有翻转也没有对调（[记录](2026-11-06-phase3.md)） |
| 盖板三个键 | 原始 y≈1600，x=100 主页、200 上一页、300 下一页 | 【文档】`boards/metalio_plus/metalio_touch.*` |
| 加速度计 | 原厂只存了 x、y，没找到使用它的业务；我们的系统也没用。竖着拿时 +x 朝上，屏幕朝上放平时 z≈-1 g | 【实测】第三次上机（[记录](2026-11-06-phase3.md)） |
| 摄像头 | 还没查 | 没有测试 |

**移植时要注意**：`input_service.c` 的 `ink_native_to_logical` 假定输入是面板原生坐标。真机的触摸已经是逻辑坐标，`ports/esp32s31` 要先转成原生坐标，或者绕过这一步。

## 第二次上机（同一天 15:11，用户同意后）

[数据](2026-11-06-bench-2.md)。**自动复原失败了，靠用户重插 USB 才恢复**，这是这次最重要的事。

| 时间 | 发生了什么 |
| --- | --- |
| 15:12:38 | 屏幕驱动一启动，电脑就再也收不到设备的任何输出。设备其实还在跑，图都显示了 |
| 15:19 | 工具等满 7 分钟后自动复原，连不上芯片（No serial data），设备停在测量固件上 |
| 15:21 | 再试一次，还是连不上。读 USB 设备信息也失败，说明 USB 连接卡死了，不是固件的问题 |
| 15:24 | 用户确认屏幕是灰阶条（测完了，屏幕电源已关，复位安全），然后拔插一次 USB |
| 15:25 | 复原成功，引导程序、分区表、otadata、ota_0、ota_1 全部读回和备份一致 |

**原因**：没有查明。【实测】两次上机，屏幕驱动初始化时 USB 输出都出问题：第一次丢几行后恢复，第二次卡死。原厂显示代码里没有碰 USB 或时钟的地方。【推断】初始化时 IO 扩展切换电源造成抖动；出厂固件是开机时就初始化屏幕，那时还没有枚举 USB，所以看不出来。**自己的固件移植时要留意**。

**丢了什么**：屏幕刷新的所有用时、触摸坐标、重力方向。用户点了两遍数字，这些数据都没收到，方向问题还是没答案。

**这次新拿到的**：

- Flash 擦写过的扇区：平均 44 ms，最长 53 ms，在模型内（第一次擦的是空扇区，数字不算数）。
- 4G 模组：拉了 MRDY 还是不回应，SRDY 为低。【推断】模组没上电，测量固件没有打开它的电源。
- 电池充满后 USB 供电时电流约 -15 mA，第一次充电时是 +88 mA。

**用户在屏幕上看到的**：大小“感觉还可以”；灰色背景和浅色字不够明显；不闪的换页残影明显；AI 星星图标不好看。已改，见 D-108、D-109 和[字号说明](../product/legibility.md)。

**工具改了**：

- 测量固件把所有结果存在内存里，跑完反复重发。USB 卡死也不丢数据，重插后就能收到。
- 工具 90 秒收不到东西，或复原连不上时，打出 `USB_STUCK` 并继续重试，运行时盯着这个字样，马上请用户重插。
- 报告不再覆盖同一天的上一份。
