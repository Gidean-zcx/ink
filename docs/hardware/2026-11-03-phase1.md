# 第 1 步：测量固件（2026-11-03）

用户 2026-11-03 同意按 [phase1-plan.md](phase1-plan.md) 写入后执行。测量固件见 [tools/hw-probe](../../tools/hw-probe/README.md)。原始输出只在用户电脑上（仓库同级的 `ink-hw/phase1/`），本文是摘要。

证据类型：未注明的都是**实测**，来自测量固件在实机上的串口输出，以及写入工具与设备的比对结果。

## 结论

- **写入和复原都按方案完成。** 只写了 ota_1 和 otadata，写后与设备比对一致。复原后出厂固件 2.0.66 照常从 ota_0 启动。
- **指令级模拟器与实机吻合。** 30 个测量区段大多相差不到 10%。所有区段的实测值都落在模拟器给的慢角以内，所以悲观档（取“拟合值 ×1.3”与慢角中较大者）对每一项都偏保守。
- **D-35 的关键数字已经测到。** 墨水屏送行每行的准备时间：上游 C 代码 **32.3 µs**，本端口的优化版 **28.0 µs**，都低于方案 B 会花屏的约 34 µs。端口档案用的 31.8 µs 比实测多留 13.6% 余量。双核同时取 PSRAM 和 LCD 中断的影响这次没有测，要等后面的送行管线实测。
- **实机比模拟器慢的几类**：
  - 内部 SRAM 的连续写，填充、清零、空操作行，慢 26～42%；
  - TLSF 分配器慢 27%；
  - JSON 解析慢 12～15%。
  
  都在慢角以内。按成本类逐项核对后，它们**不会让预期档偏乐观**：预期档取“拟合值 ×1.3”，JSON 实测是拟合值的 1.15 倍，仍在其下；内部 SRAM 连续写不是档案里的成本类；`heap.op` 档案里是估计值 1500 周期，远高于实测 TLSF 的 295。

## 对后续的影响

**D-35**：方案 B 的前提“优化后每行 ≤ 约 32 µs”在单核测量下成立，实测 28.0 µs，不需要改为预填 128 行或降行时间。还缺两项，留给后面的送行管线实测：

- 两个送行任务同时从 PSRAM 读、0 核加上 LCD 中断时的每行时间；
- 每相实际时长。

**档案**：

- 悲观档不用改，每一项都已偏保守。
- 预期档（`metalio-plus-psram16.json`）也不用改：档案用到的每个成本类，实测都在“拟合值 ×1.3”之下（实测/拟合 0.84～1.15）。反过来说，它比单核实测还慢 15～55%。要不要去掉 ×1.3 余量、让它更接近真机，等双核争用 PSRAM 实测后再定。两份档案的说明里已记下这次核对。
- 指令级模型对内部 SRAM 连续写估计偏低（memset、填充慢约 40%），已记入校准报告 §3.1。系统里用到这类写的成本类（如清屏、填充）以后要单独测。

**指令级模拟器**：

- 本次实测证实了它的拟合方法；
- 带 `#cold` 的区段在实机上没清 I-cache，不可比；
- 双核争用仍未建模，需要实测。
