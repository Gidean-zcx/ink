# 需求深读：第一版底座必须承接什么

整理：2026-11-01。依据：[想法记录](../ideas.md) 中用户原话（I-001～I-034）、[需求与边界](../requirements.md)（G-001、G-002、R-001～R-033）、[决策记录](../decisions/README.md)。目的：在设计 v0.1 底座之前，把“用户到底要什么”还原清楚，并找出哪些要求现在不做功能、但底座必须先留好位置。

阅读约定：引号内是用户原话；**底座要求 F-xx** 是助手由需求推导出的、对 v0.1 底座的要求（建议），在[底座设计](../system/foundation.md)中逐条落实。

## 1. 七条主线：用户反复表达的东西

把十几天里分散的表达按“用户真正在意什么”归并，得到七条主线。它们比单个功能更稳定，底座应围绕它们设计。

| 主线 | 用户原话（摘） | 对应编号 | 首版（方案 A）怎么体现 |
| --- | --- | --- | --- |
| ① 换掉“奶头乐” | “将原来刷奶头乐 app 的时间转换为获取高价值信息和学习扩展个人知识能力边界” | G-001、R-019、R-020 | 有终点的个人报纸、读与听、AI 帮助理解；不做无限流 |
| ② AI 就是系统 | “系统 app 的一切行为数据都可以被 AI 控制”“任何场景页面下的数据都可以被 AI 获取” | G-002、R-006、R-007、R-009、R-021 | 任意页面按 AI 键，带当前内容提问；内置 app 的动作都可由 AI 调用 |
| ③ 一家人的设备 | “供本人和子女使用的专属 AI 手机”；孩子“可以独立阅读，但是有听书功能可能会更好”；共用一台、登录切换 | R-001、R-014、R-018、R-028、R-030 | 成员切换、儿童成员、故事续播与读听切换 |
| ④ 它是一台手机 | “带 4G 的硬件必须支持短信和通话”；通话纪要、短信待办、平台输入法 | R-013、R-024～R-027 | 首版不做通话界面，但硬件已订购含 4G，底座必须为电话留位 |
| ⑤ 底层高效、体验顺 | “优先构建一个高效的底层系统，例如匹配硬件的算力，和 UI 交互匹配墨水屏的特性”；“软件调度、多任务系统这些” | R-008、R-010、R-011、R-029 | 刷新调度、资源准入、四段时延可观测 |
| ⑥ 数据不能丢 | “初期可能不稳定，后续可能会有朋友也想用” | R-022、R-023 | 账户、自动备份、刷机后整机恢复 |
| ⑦ 能长出新东西 | “可安装动态应用”“AI 渐进式了解 app 能力”；说想学什么就准备资料，说书名就找书 | R-008、R-009、R-016、R-017 | 内置 app 带能力清单；找书导入走中枢 |

两点容易被忽视：

- **④ 不是远期附属功能。** 项目最初的说法就是“专属 AI 手机”，而硬件已订购含 4G 版本（I-032）。首版可以不做电话界面，但如果底座按“阅读器”设计，日后加入来电打断、通话音频、模组待机，会动到调度、音频和电源的根基。Mudita Pure（基于 MCU 的墨水屏手机）的经验见[架构对标](../research/architecture-benchmarks.md)。
- **② 与 ⑤ 互相约束。** “一切数据都给 AI”如果理解为设备随时把全部数据塞进上下文，就和 512 KB 内部内存冲突；理解为“完整的数据入口 + 按需读取”，两者才同时成立（现有研究已提出渐进式披露，见 [AI 平台](../research/ai-native-platform.md)）。

## 2. 需求之间的张力，以及底座怎么化解

| 张力 | 为什么冲突 | 底座层面的化解（建议） |
| --- | --- | --- |
| 全部数据给 AI ↔ 单片机内存 | 书、笔记、历史记录远超设备内存 | 设备是用户数据的权威写入者，中枢保存完整副本（本来就要备份）；AI 查历史数据走中枢副本，设备只提供“当前页面快照”和执行动作（F-06、F-11） |
| 手动操作 ↔ AI 操作结果一致 | 两套代码路径必然漂移 | 所有用户可见操作都登记为“动作”，按钮和 AI 调用同一个动作（F-05） |
| 60fps 无残影 ↔ 墨水屏物理特性 | 稳定阅读需要灰阶波形，快速变化需要快刷 | 应用只声明“刷新意图”，系统统一选择波形、合并与清理；高刷作为动态区域能力单独验证（F-03） |
| 共用一台 ↔ 隐私和儿童安全 | 成员数据混在一起；孩子可能进入成人内容 | 数据按成员分区；成人成员需验证进入；儿童策略由设备和中枢的可信代码执行，不靠提示词（F-08） |
| “学习上瘾” ↔ 反奶头乐 | 停留时长指标会把产品推回成瘾设计 | 底座记录的是完成、掌握、读完，而不是停留时长；内容流都有终点（F-10） |
| 首版是阅读器 ↔ 它是手机 | 电话要求随时打断、音频切换、模组待机 | 首版就有调制解调器服务、系统级打断通道、音频焦点仲裁和电源状态机（F-04、F-09） |
| 质量优先的模型 ↔ 时延与费用 | 一线大模型慢且贵 | 中枢做模型路由、缓存与费用上限；设备侧先给即时反馈（F-07、F-12） |
| 离线可用 ↔ AI first | AI 需要联网 | 离线闭环只覆盖 R-032 的读、听、备忘、单词；AI 不可用时如实提示并排队（F-11） |
| 动态安装 ↔ 单片机隔离能力弱 | 原生代码出错会拖垮整机 | 首版内置 app，但应用清单、动作与页面上下文的格式从第一天就按“以后可下载”设计（F-05、D-08） |
| 初期不稳定 ↔ 数据不能丢 | 刷机、崩溃、断电都会发生 | 断电安全的本地存储 + 变更日志同步到中枢 + 恢复演练进入验收（F-06） |

## 3. 底座要求清单

以下是从主线和张力推导出的 v0.1 底座要求。它们本身不是用户功能，但没有它们，用户要的功能会建在沙地上。

| 编号 | 底座要求 | 支撑的需求 |
| --- | --- | --- |
| F-01 | 硬件抽象层：屏、触摸、按键、前光、音频、存储、电源、Wi-Fi、蜂窝模组都通过稳定接口访问；同一套上层代码能在电脑模拟器和真机上运行 | R-005、R-008，及到货前开发 |
| F-02 | 运行模型：少量长期系统服务 + 一个前台界面 + 有界的后台工作；资源准入、取消与恢复 | R-008、R-029 |
| F-03 | 显示管线：LVGL 绘制 → 刷新调度器按意图选波形、合并区域、管理残影；输入按页面代次投递，旧页面的触摸不落到新页面 | R-010、R-011、R-029 |
| F-04 | 音频焦点：通话 > 闹钟/提醒 > AI 语音 > 故事/有声书 > 提示音，统一仲裁暂停、压低、恢复 | R-012、R-013、R-018 |
| F-05 | 动作与能力：每个 app 有能力清单（对象、动作、页面上下文、事件）；界面和 AI 调用同一动作；动作返回真实回执；按副作用分级确认 | G-002、R-007、R-009、R-021 |
| F-06 | 数据底座：按成员分区的本地存储；断电安全；带版本的对象与变更日志；与中枢同步、备份与恢复；内容位置定位（书的段落、音频的时间点）稳定 | R-018、R-022、R-023、R-030、R-032 |
| F-07 | 中枢连接：一条加密长连接承载控制、语音流与同步；断线排队、幂等重试；设备不持有模型密钥 | R-006、SR-NF-03 |
| F-08 | 成员与策略：成员档案、切换与验证、儿童策略执行点、按成员的 AI 上下文与记忆 | R-014、R-030 |
| F-09 | 系统级打断与电源状态：来电/闹钟可打断任何前台；模组待机时主控可休眠并被唤醒 | R-013、R-015 |
| F-10 | 行为与学习事件：读完、听完、答对、复习等以统一事件记录，服务 G-001 指标和 AI 历史，不以停留时长为核心 | G-001、R-019、R-021 |
| F-11 | 页面上下文快照：任意页面在预算内（建议 ≤ 8 KB）给出可见内容、选区、状态和可用动作，并带内容定位 | G-002、R-021 |
| F-12 | 可观测性：记录输入、首次反馈、稳定可读、业务完成四个时间点，以及内存与任务水位，开发期可上传到中枢查看 | R-029、SRS |
| F-13 | 内容格式：中枢把书、报纸、故事转换成设备易排版、可定位的格式；有声内容带文字对齐信息，支撑读听切换 | R-017、R-018、R-020 |
| F-14 | 文本输入服务：统一的输入框与输入法接口（首版以语音输入为主，接口先定） | R-026、R-027 |

## 4. 首版明确不需要放进底座的

- 脚本运行时与真正的下载安装 app（D-08 第三阶段）：清单格式现在定，运行时以后选。
- 本地唤醒词：先用实体 AI 键，唤醒词等 ESP-SR 在 S31 上验证后再加。
- 游戏模拟器与 60fps 全屏：作为刷新调度器的“动态区域”能力留口，单独验证。
- 多设备同时在线的复杂冲突合并：首版一个家庭一台设备，变更日志格式预留多设备字段即可。
- 第三方 app 兼容：不做。

## 5. 仍需用户补充、但不阻塞底座设计的

- 成人成员进入是否需要 PIN、孩子能否自由切到自己的档案（底座设计给出默认方案，见决策板第二轮）。
- 个人报纸的主题、来源偏好与每天时长（影响中枢内容管线，不影响设备底座）。
- 孩子是否需要使用时长限制、家长报告的形式。
