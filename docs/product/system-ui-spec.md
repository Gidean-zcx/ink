# 系统界面规范（第一版）

更新日期：2026-11-04。状态：用户已确认视觉方向（“定了，铺开其余页面”）；交互和状态按 [Codex 设计审计](../audits/2026-11-04-codex-ui/report.md)修订过。**视觉和组件可以作为开发输入，流程和状态还没补全，见第 7 节。** 设计稿在[私有画布](https://claude.ai/artifact/PtS48RHTy15aMKa4bgbRVJ)上，只有用户能打开，页面源文件也在那里，不在仓库。

相关文档：[界面参考](../research/system-ui-references.md)（依据和具体数值）、[系统应用分类](system-apps.md)、[底层依赖](../system/ui-dependencies.md)（每个界面还缺什么）。

标了“建议”的是助手的判断，用户还没选；标了决策编号的以[决策记录](../decisions/README.md)为准。

## 1. 设计语言

卡片和胶囊合成一种（D-59）：

- **形状说明能不能按。** 圆角矩形（卡片）装内容；胶囊和圆形是能按的控件。
- **颜色只有四个。** 白底、浅灰、次要文字的深灰、黑。
- **会频繁变的只用黑白，基本不动的才用灰**（D-61）。开关、滑杆、分段选择、页面指示点、数字键、翻页键、键盘都是纯黑白；Dock、图标底圆、设置分组、搜索框可以用浅灰。
- **上面看，下面按。** 主屏上半只放时间，操作都在下半。
- **一张卡片只讲一件事**，一到两个关键信息。
- **要用户决定的浮层是不透明的面板，边框清楚，面板外点不动**（确认卡、电源菜单、选文件）。背后不铺遮罩：铺了就要刷整屏（D-97）。

数值（字号、边距、圆角、颜色）见[界面参考第 3 节](../research/system-ui-references.md)和画布上的“基础”页。

## 2. 主页结构

D-60：三屏加固定 Dock。

| 位置 | 内容 |
| --- | --- |
| −1 屏“今日” | 继续读（黑色大卡，圆环显示进度），听、单词、报纸、待办四张小卡 |
| 主屏 | 日期、时间、一行“继续读”，8 个图标（2 行，靠下） |
| +1 屏“全部” | 搜索框和全部应用 |
| Dock | 电话、短信、AI（居中的黑圆）、阅读、备忘。翻屏时不重画 |

翻屏不跟手：松手才翻，指示点跟着变。上一页、下一页键也一样。指示点只是指示，不能点。

## 3. 交互

### 3.1 操作

| 操作 | 结果 |
| --- | --- |
| 左右滑 | 翻主屏 |
| 从顶边下滑，或点状态栏 | 控制中心，整块面板直接出现，不跟手、不回弹 |
| 从底边上滑，或 HOME 键 | 有浮层先关浮层，否则回主屏 |
| 从左边缘右滑，或左上角按钮 | 返回上一层 |
| 按住 AI 键，或点 Dock 中间的圆 | AI 面板，盖住下方约 58%，上面这一页留着 |
| 长按图标 | 卡片和快捷操作 |
| 应用里 | 翻页，不滚动，底部胶囊显示第几页 |

### 3.2 按下的反馈

D-31（已定）：**默认不反色，动作的结果就是反馈**：开关变了、数字出来了、新页面到了。要等网络或中枢的操作（发短信、下载、备份）才先让被点的控件反色，再执行。

时间是目标，不是实测：屏幕空闲时 0.35 秒内看到第一个变化；正在整屏刷新时最多 1.2 秒；从浅睡唤醒另算（[底座设计 §4.5](../system/foundation.md)）。参考：出厂固件的日志里，20 相的小区域刷新中位数约 412 ms，但那是另一套固件，不代表本设计。

### 3.3 返回、关闭和手势

- 返回只退一层。关闭浮层回到原来的页面和位置（AI 面板、控制中心都是）。
- 关闭只是收起，不取消任务：AI 还在想、下载还在跑，关了也继续，取消是单独的按钮。**确认卡例外**：HOME、返回都等于取消（[系统服务设计](https://github.com/Gidean-zcx/ink/blob/claude/system-services/docs/system/system-services-design.md) §7，分支未合入）。
- 建议的手势边界，要在实机上调：上、下、左三边各留 6 毫米（约 70 px）的边缘带，起点在带内才算系统手势。

手指归谁（建议），从高到低：

1. 来电、闹钟、低电量、确认卡：独占输入。出现时，已经按着的那次触摸作废。
2. 键盘、滑杆、文字选择：手指落在上面就归它，边缘带也一样。
3. 边缘手势。
4. 前台页面的滑动：主页翻屏，应用翻页。

### 3.4 实体键

| 键 | 平时 | 锁定时 | 来电 | 闹钟 |
| --- | --- | --- | --- | --- |
| 电源键，短按 | 锁屏 | 唤醒（D-38） | 静音，不挂断 | 稍后再响 |
| 电源键，长按 | 电源菜单（代码还没有长按） | 同左 | 不响应 | 不响应 |
| AI 键 | 按住说话 | 唤醒（D-38） | 不响应 | 不响应 |
| HOME | 有浮层先关浮层，否则回主屏 | 不响应 | 不响应 | 不响应 |
| 上一页、下一页 | 翻页、翻屏 | 不响应 | 不响应 | 不响应 |
| 音量 | 调音量 | 不响应 | 建议：调通话音量 | 建议：静音这一次 |

电源键短按的三种打断语义来自[系统服务设计](https://github.com/Gidean-zcx/ink/blob/claude/system-services/docs/system/system-services-design.md) §6.2。

### 3.5 锁屏

D-38（已定）：默认 10 分钟不操作自动锁屏；锁屏 = 画面保持、底部小标记、芯片浅睡，电源键或 AI 键唤醒。**没有上滑解锁**：锁定时触摸和 HOME 都不响应（和 `input_service.c` 一致）。

| 阶段 | 屏幕 | 什么能响应 |
| --- | --- | --- |
| 已锁定（刚锁或浅睡） | 这一页加小标记（默认）；设置里可选日期待办或壁纸 | 只有电源键和 AI 键 |
| 来电、闹钟、低电量 | 接管全屏 | 这时可以点；结束后回到锁定 |
| 唤醒后 | 去掉标记 | 孩子直接回到原页；成人按 D-95 决定要不要先输 PIN |

锁定时各入口能做什么：

| 入口 | 锁定时 | 唤醒后、成人验证前 |
| --- | --- | --- |
| 通知 | 只显示数量（“1 条短信”），不显示内容（“锁屏显示通知内容”默认关），不能点 | 看不到内容 |
| AI | AI 键只负责唤醒 | AI 一律拒绝，验证后才打开（系统服务设计 §11.4） |
| 相机 | 没有入口。屏幕不响应触摸，放了也点不到；要不要加，用户还没选 | 同左 |
| 控制中心 | 打不开 | 打不开 |
| 添加成员、家长设置 | 打不开 | 先输 PIN，验证后回到原请求 |

三种锁屏画面：

| 模式 | 时间走不走 | 耗电 |
| --- | --- | --- |
| 这一页（默认） | 不显示时钟 | 不额外刷新 |
| 日期待办 | 每分钟刷新（D-96），要定时唤醒 | 没有计入现有待机估算；RTC 唤醒待测 |
| 壁纸 | 不显示时钟 | 锁屏时刷新一次 |

### 3.6 语音的入口

| 入口 | 怎么结束 |
| --- | --- |
| 按住 AI 键 | 松开 |
| 点 Dock 中间的圆、AI 页的话筒 | 停一下自动结束，也可以再点话筒 |
| 唤醒词（免按键，D-52） | 停一下自动结束 |
| 键盘的话筒（听写，R-056、D-65） | 停一下自动结束，或点“说完了”，或点“用键盘” |

语音输入：键盘候选条右端有一个黑色话筒键，点了以后键盘区换成同样大小的语音面板。说的时候字显示在面板的固定小区域，说完才进输入框，之后还能改。听写靠中枢，没网时提示并退回键盘。密码框没有话筒。AI 键仍然只叫 AI。

麦克风开着时状态栏要一直有标记（底座设计 §8），包括免按键在等唤醒词时。本地等唤醒词、正在上传、正在录音要分得清，**这一点还没有画全**。

### 3.7 通知和控制中心

普通通知只改状态栏小图标，不弹横幅（横幅每次消失都要刷新）；来电、闹钟才占全屏。通话时长只到分钟，计时器也不显示跳动的秒。勿扰时闹钟照响，来电不响铃但全屏（D-68，在底层分支上）。

| 控件 | 规则 |
| --- | --- |
| Wi-Fi | 黑 = 开。副标题是实际连的网络 |
| 4G | 黑 = 开，副标题说明状态：备用（Wi-Fi 在用）、正在使用、已关闭 |
| 飞行（建议） | 关掉 4G、Wi-Fi、蓝牙；之后可以单独再开 Wi-Fi 和蓝牙，4G 不能开 |
| 免按键 | 开 = 设置里选的那一档（亮屏时或一直），关 = 关（D-52） |
| 滑杆 | 0～10，0 是关；黑条长度就是档位，压在黑条上的字反白 |
| 音量 | 现在全家一个音量，听书、AI 和提示音共用。闹钟要不要有最低音量，随闹钟一起定 |

## 5. 给实现的提醒

- 公共零件对应界面框架里的组件，先做它们，页面就是拼装。
- 图标是同一套几何的三种画法：`line`（关着、列表）、`duo`（应用图标，放在不动的地方）、`solid`（打开、按下）。需要把矢量转成各尺寸位图的工具。
- 字体：中文 Noto Sans CJK（常规、中等、粗体），数字 Outfit（细、常规、中等）。大字号只放数字子集。现在的构建只生成常规 24、32 px；四个字号的 2bpp 粗算约 5.12 MiB，还没乘字重，超过 SP-05 的 4 MB 目标，要先核算。
- 系统浮层要有统一的层级和刷新规则：键盘、AI 面板、确认卡、来电。
- 每个页面都要对 AI 可见（G-002），和设计一起做，不是最后补。没有快照回调的页面，AI 什么也看不到。
- 触控区不小于 82 px（约 7 毫米）。例外：键盘字母键约 61 px 宽、候选条高 72～76 px（一行要放十个键，要用原尺寸做任务验证）；滑杆分档按整条算；状态栏高 52 px，它只是手势的补充入口。开关的热区是 120×84，实现时让带标签的整行都能点。

每类操作的刷新规格（[审计报告 §5.3](../audits/2026-11-04-codex-ui/report.md) 校对过，**不是实机验证过的波形配置**）：

| 操作 | 改动范围 | 刷新方式 |
| --- | --- | --- |
| 开关、分段、指示点、滑杆、数字键 | 旧状态和新状态的并集 | 黑白快刷。现在的配置没有 A2，回退 DU（20 相）；要求旧像素和新像素都是黑白 |
| 文字输入、候选、识别稿 | 输入行和候选条，不重画整个键盘 | 分批提交最新内容，不丢键 |
| 翻主屏、打开页面、翻页 | 内容区；状态栏和 Dock 有变化才刷 | GL16（37 相）。“先黑白再补灰”是待实现的机制 |
| AI 面板、确认卡、选文件、电源菜单 | 面板，关闭时恢复底下那块 | 模态按 GC16（36 相）算 |
| 听写、回答、进度 | 固定文本块和变化的数字 | 按片段节流，有最长等待和取消 |
| 时钟跳分钟 | 数字那一小块 | 锁屏时另算唤醒和耗电 |
| 相机取景 | 约 62% 屏 | 单独定频率，退路是拍一张再看 |
| 唤醒 / 切换成员 / 清残影 | 只去标记 / 整屏 / 整屏 | 用哪种要按场景定 |

记录刷新时间时分四项：输入到接收、第一个反馈、稳定可读、业务完成。

## 6. 没有验证的

- 设计稿已用无头浏览器逐屏渲染（68 个画板，没有溢出，没有脚本错误），经过一次 Codex 设计审计。这只说明版面和链接，不说明实机效果。
- 没有上过实机：浅灰和白能否分清、Outfit 细体的观感、所有刷新时间。
- 灰底控件（设置分组的行、Dock）从灰变到别的颜色，能不能走快刷，要状态过渡和实机校准。
- 页面上的书名、人名、号码、容量都是示意；二维码不是真的；相机取景和相册照片用的是占位图。AI 面板在原型里都用同一个读书示例，不代表实际的页面上下文。
- 蓝牙、通话声音能否按图上实现，取决于实机验证（[底层依赖第 3、6 节](../system/ui-dependencies.md)）。

## 7. 审计后还没补的

审计认为这些是首版必须补的（完整列表和串联场景见[报告第 4 节](../audits/2026-11-04-codex-ui/report.md)），**这是建议，要不要、什么时候补等用户决定**：

| 范围 | 缺什么 |
| --- | --- |
| 身份 | 首次配网、绑定中枢、建家庭和 PIN、恢复已有设备、没有手机时怎么办；儿童版主页和受限状态；PIN 的创建、修改、错误、等待、忘记；成员切换、闲置退出、时长用尽时草稿、播放、AI、剪贴板怎么交接 |
| 数据 | 本地保存、等待上传、中枢收到的区别；备份失败和整机恢复；隐私说明、记录查看和删除、留存期限（D-34） |
| AI 和语音 | 不可用、超时、取消、部分完成、排队、拒绝、过期、撤销失败；不同确认级别的确认卡；听写的各种失败 |
| 输入 | 光标、选择、复制粘贴、草稿、长文本分页 |
| 内容 | 备忘的创建、修改、删除、清单、待转写；全局播放卡和后台任务入口；导入、转换、下载、可读、离线的全过程；阅读、听、报纸、单词和系统的交接表 |
| 异常 | 通用的加载、无结果、无网、中枢离线、TF 卡缺失或写满；文件删除和无线传输授权；低电量、充电、关机图、开机恢复、更新安装和回滚 |
| 压力 | 多通知、长文件名、长回答、长聊天、键盘占位、最大字号 |
| 取舍 | 搜索结果、长按菜单、卡片增删、主屏固定位置：要么画完，要么明确后移并隐藏入口 |

可以随功能晚点的：联系人、通话和短信的状态、通话录音、闹钟和日历编辑、蓝牙配对、相机和扫码、远程交互、四个内置应用的内部页面。
