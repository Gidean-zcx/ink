### 本轮判断如何变化

1. 用户补充硬件约束后，通用 Android/Linux 手机不再作为可直接选择的实施路线；商业设备只用于体验比较。
2. 最初仅有视频线索，高刷属于待查证。找到作者本人对 PaperBoyS3 的说明后，更新为“存在特定硬件和场景下的 60Hz 驱动依据”；仍未证明 CloudZao 适配和无残影。
3. 从 README 初查进一步抽查固定提交，确认两款墨水屏确有驱动源码；Claw4 有拨号/挂断路径。判断由“上游宣称”细化为“部分代码存在，未编译或实测”。
4. ESP-SR 上游已有 S31 支持信息，但 Plus 当前依赖清单中的 ESP-SR 条件仅列 S3/P4；不能把芯片组件支持当成板卡现成唤醒能力。
5. 后续限定 Plus，并扩大板级核查：同一提交已有 NT26 构造、引脚与电源路径。此前“墨水屏与通信尚未汇聚、先看 Claw4”的研究侧重修正；型号边界没有因此放宽。

### 助手提出、仍待讨论

- 产品主线可以组织为“表达目标 → AI 准备内容 → app 稳定执行 → 随时继续”。
- 学习采用共同的数据/练习基础，儿童和成人按能力、兴趣、目标调整引导；不把游戏化和专注割裂。
- “无限流”先探索连续出题、少操作、可恢复的节奏；是否滚动、是否无限延长会话单独讨论。
- 做场景原型时优先讲清楚主题学习导入、读听切换、故事续播，再决定第一批 app。
- 家庭成员档案、离线基础能力、敏感操作权限和内容来源记录属于建议，未被自动升级为用户需求。

- 系统 AI 可研究“刚才那句话是什么意思”“继续上次的故事”等场景，需定位正在读/听的内容及断点。精确读听同步是否成立，要对应内容版本和定位信息。
