# 第三十四期：AI修改的是哪些材料，导入后能否真正使用

2026-10-27。继续逐功能研究，本期深入Anki Desktop。补读原目录剩余30页正文、复核编辑与浏览的关键章节；没有运行Anki或验证原生App。目录页、操作说明和实测分别记录，全部65组产品仍为部分覆盖。

## 五个会改变设计判断的细节

| 场景 | 文档揭示的具体行为 | 对本项目的参考问题，尚非设计决定 |
| --- | --- | --- |
| AI改一道题的答案 | 一条笔记可以生成多个练习卡；选中单卡后，笔记级编辑仍可能影响其他派生卡。标签与旗标的作用层级也不同。 | AI能否准确说明改动对象、关联练习和影响范围？成人资料纠错与孩子个人记录怎样分别处理？ |
| 把一批词卡整理一下 | 批量切换状态会根据“当前项”的状态作用于整组；替换默认限制在选中笔记，也能取消限制。查重后打标签不等于合并删除。 | “全改成某状态”与“每项翻转状态”应明确区分；检索范围、选区和修改范围是否一致？ |
| 导入数学练习 | MathJax根据公式文本排版；LaTeX路径由电脑生成图片，再同步给其他端显示。显示公式不代表可以自动判题。 | 对Plus，源文本、显示资源、朗读说明和答案规则分别怎样准备、核验？预处理位置仍待决定。 |
| 家长修订一份共享题库 | 发布者更新不会自动更新已经下载的副本；接收者要重新下载导入。新包删掉的卡也不会自动从接收者集合消失。 | 内容修订、撤回旧题和保留孩子学习历史，需要什么明确结果？不能只报告“题库已更新”。 |
| 数据同步到自有服务器 | 服务端与客户端存独立副本，客户端配置服务地址和凭据；协议升级有兼容条件。页面仍可能显示“AnkiWeb”字样。 | 配置成功、实际连到的服务、同步完成与可恢复备份应分别可见；该例不决定本项目账户或服务器方案。 |

上述事实及版本边界见[Anki案例](../research/interaction-library/cases/M-020-anki.md)与[逐页来源摘记](../research/interaction-library/artifacts/anki-content-and-maintenance/source-notes.md)。公式、分享和自托管同步分别登记为F-M020-23～25；既有编辑、模板、浏览、导入、排错补回原编号。

## 资料怎样复用

后续不必从第1期开始翻。先打开[按设计问题查依据](../research/interaction-library/design-reference-guide.md)，选择“AI批量修改学习资料”或“导入公式/新版题库”，再沿任务F→证据E→原文章节→未知分支回查。

本批保留30个新页面来源，但只有3项新增任务；概念页、平台目录页不当功能数。原60行Anki目录就地更新，没有复制一份目录制造覆盖量。55个桌面手册页面现都已读正文，仍不能称Anki全部交互研究完成：每个设置组合、错误弹窗、取消/撤销、跨设备恢复以及真实操作体验仍有缺口，AnkiMobile/AnkiDroid也不是同一个研究范围。

进入正式设计前，尤其需要核验：AI更改的影响范围是否可解释；公式/字体/音频是否真正可用；题库更新能否保留个人历史；备份能否恢复。这些是依据竞品提出的验证问题，尚未升级为已确认实现方案。
