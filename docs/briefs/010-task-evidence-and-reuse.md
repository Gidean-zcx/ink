# 第十期：让竞品资料成为可以复查的设计依据

整理及资料续补：2026-10-27；有限实际网页操作：10月26日。阶段仍为产品研究。

此前的功能盘点确实不够深入。现在已补操作手册、版本记录、静态界面及有限的实际网页操作，但**仍未逐一研究完每个产品的每个功能，也没有手机或电子纸实机验证**。65组产品全部是部分覆盖；最新登记量和逐项深度见[案例索引](../research/interaction-library/case-index.md)，不能当完成率。

## 以后怎样反复查用

资料按四层组织，同一事实尽量在任务和证据层维护：

| 层次 | 查什么 | 入口 |
| --- | --- | --- |
| 产品与功能目录 | 具体型号、平台、版本；完整目录能取得就逐条登记，未取得就标未知 | [产品索引](../research/interaction-library/case-index.md)、[逐条目录](../research/interaction-library/inventories/README.md) |
| 用户任务 | 前提、入口、动作、反馈、数据变化、结束/返回、异常与恢复；沿用稳定F编号 | 各产品案例及[任务覆盖表](../research/interaction-library/coverage.csv) |
| 证据 | 来源、查阅日、版本、章节/页码、截图或动作记录、散列；区分宣传、文档、观察、实际操作 | [E证据索引](../research/interaction-library/evidence.jsonl) |
| 设计问题 | 跨产品比较机制与代价，分别说明事实、推断、候选建议和未知 | [七个问题域](../research/interaction-library/comparison.md)、[剩余缺口](../research/interaction-library/backlog.md) |

例如设计“孩子听到一半问AI，再继续故事”，先从横向表进入读听恢复，定位相应F任务，再读取E证据和适用条件。此时可以比较暂停、关闭、换内容、换成员、刷新/重启分别恢复什么；具体采用哪种方式，仍需结合本机资源和孩子理解能力讨论。

## 怎样避免资料越多、结论越虚

- **目录与已分析任务分开。** 手册章节、帮助标题可能重叠，也包含非功能页；没有核定全功能总数就不报完成百分比。
- **正常路径与失败分支一起保存。** D4仅说明实际尝试并观察过，不代表通过；定位错误和产品反馈异常也分开。
- **版本冲突保留原位置。** BOOX两类同名手势帮助方向不同；NotebookLM创建帮助与FAQ对复制的说法冲突。不能挑一条方便的说法当全产品规则。
- **资料缺口与产品不支持分开。** 没找到删除恢复步骤，不等于产品没有恢复能力；没有实机，就不评价手感、残影和续航。
- **正式设计引用任务和证据编号。** 简报负责提出问题，原件留临时研究区，正式库保存短摘记、必要图片及定位，避免重复堆整本材料。

接下来仍需补当前构建的完整学习回路、新闻过滤/规则的实际结果、真实听音及中断恢复、AI内容校订和执行失败，以及各型号未读目录与恢复分支。资料库已能支持有边界的讨论，尚不足以宣告全功能研究完成。
