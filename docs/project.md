## 每次收到新想法时

1. 先读最新入口、需求及相关想法，检查同一主题是否已有记录或未合并修改。
2. 先回答当前想法的可行性、成立条件与主要限制。区分资料事实、推断、估算和实机验证，按需要补查来源。
3. 将原始表达和有价值的结论补入 ideas.md；想法、明确需求、助手建议分别标记。用户表达含糊时保留待定，不自行替用户定案。
4. 用户明确提出新要求或变更要求时，同步 requirements.md 及关联条目；需要新的技术或竞品依据时，更新对应研究文件。
5. 核对变更文件和链接，再保存到 GitHub。小范围资料整理可以直接提交；涉及实现、范围较大或需要评审时使用独立分支和 PR。
6. 回复本次结论、保存位置及仍需决定的关键点。远端写入失败时明确说明；必要时用 Issue 暂存，并在正文补录后完成归档。

用户可直接说“ink 项目：我有个想法……”或“把某项确定为需求……”，无需先准备完整需求文档。新会话若没有项目上下文，附本仓库链接即可从这里恢复；仓库中的最新记录是接续依据。
