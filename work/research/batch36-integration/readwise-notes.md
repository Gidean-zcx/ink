## 哪些控件实际改变什么

| 对象/动作 | 源码定位与本次证据 | 限制 |
| --- | --- | --- |
| 高亮进入图前的筛选 | 22–38行：去掉特定活动前缀和去空白后不足20字符的文本，重复ID只保留首次。合成输入8条，输出5条 | 按字符数过滤会排除简短中文摘录；不等于内容价值判断。没有测试全部缺字段/坏格式 |
| 同书关联与跨来源关联 | 70–96行：同一book_id内两两连边；外部connections只核端点存在并按无向对去重 | 同源不代表语义相关；源码未核跨来源是否真的跨book_id，也未拒绝自连。后两项仅代码判断，未构造故障运行 |
| 来源数量 | 124–159行：图例仅列至少2条高亮的来源，计数也取图例长度。样本有3个book_id，界面报2个来源，但第三来源节点可打开 | 此计数不等于输入材料或实际图中来源总数 |
| 点击节点 | 331–367行：详情呈现全文、可选笔记、原文链接、关联理由和同来源摘录 | 理由与标签来自输入，不经渲染器事实验证。外部原文链接未点击，样本URL使用example.invalid |
| 从详情跳关联项 | 状态2→3→4：选择从101变201再变202，详情更换，原来源筛选仍为1；源码还将视图居中/缩放 | 跳到另一来源不清空筛选。没有修改高亮/关系或保存阅读进度的控件 |
| 图例筛选 | 369–375、398行：切换filterBookId，通过透明度弱化其他来源；没有删除节点 | “弱化显示”不等于从数据集中移除；鼠标悬停与已选节点也是不同状态 |
| 关闭与清空 | 状态5点击屏幕esc，详情关闭但筛选仍为1；状态6按键盘Escape，筛选清空。329与562–568行分别支持 | 外观同为退出，影响范围不同；触屏设备不能假定具有键盘退出语义 |
| 重载 | 状态7打开单条来源，状态8重新加载后选择和筛选清空；源码未保存这两项 | 不表示真实Reader书库数据丢失；仅该生成网页的视图状态 |
| 窄屏详情 | 320×640全新页面打开节点102：面板宽460、左边界-140，正文左边界-111；截图有左侧截断 | 本地样本的CSS适配问题，不是E-Ink4 Plus或Reader移动端实测；不测帧率/残影 |

## 可复查的样本与记录

输入：[highlights.json](highlights.json)、[connections.json](connections.json)。数据明确标为Synthetic/Research fixture；包含重复ID、短中文、活动条目、单条来源、反向重复关联与失效端点，用来核对过滤和控件范围。关联理由由研究者写入，没有运行大模型。

[生成命令和退出结果](generation-log.json)：对未修改的官方Python文件显式传入两个输入和输出路径，exit 0。Python阶段只使用标准库读取输入并生成本地HTML。

浏览器为Chromium 156.0.8078.4，桌面1200×820；[环境](environment.json)、[动作](actions.json)、[状态](states.json)、[网络](network.json)、[错误](errors.json)、[窄屏记录](narrow-fresh.json)均归档。控件通过可见定位器和鼠标操作；JS只读取节点位置/DOM/状态，没有直接调用业务函数强制打开详情。桌面记录共10状态，窄屏另1状态。

状态9是调整视口后点击旧坐标、未打开详情的尝试，不能当窄屏验证成功；随后新建320×640页面，重新定位可见节点点击，才取得窄屏证据。没有隐去首次未完成的尝试。

## 对产品讨论的价值

以下是助手分析：AI生成的知识关系、原文高亮和用户确认应能区分；计数需要说明实际统计对象；退出详情、清除筛选和结束任务应各有明确结果。中文短内容过滤、窄屏布局及联网依赖也是采用类似功能前的验证项。尚未决定本产品采用图谱界面或这份实现。
