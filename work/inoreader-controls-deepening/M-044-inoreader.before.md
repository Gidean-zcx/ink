# M-044 Inoreader：信息筛选、保存、离线与听读

查阅：2026-10-26。范围：官方带操作步骤的 Filters/Rules 功能说明，主要是 web 配置、服务端处理、多端读取；功能有套餐条件，未固定 app 构建或实际订阅。**D2 文档重建，无登录配置、无执行规则、无连续视觉观察**。

## 流程与状态

| 流程 | 操作与反馈 | 作用范围/数据变化 | 证据 |
| --- | --- | --- | --- |
| F-M044-01 筛选与去重 | Automate → Filters → 新建；选订阅源/文件夹/全部范围，选保留匹配或移除匹配，填写标题/正文/作者/URL 等条件并保存。重复过滤可按 URL、相同标题或近似标题。 | 保存后针对新文章；去重保留先到条目。被过滤文章不出现在 web、app 或 API。未来加入范围内文件夹的源也受规则影响。 | E-INO-01 |

## 分支、冲突与未知

- 过滤影响数据是否进入可访问列表；仅让不喜欢的文章排后面是另一种行为。对既有文章是否追溯执行、修改过滤后能否找回旧条目，当前材料不足。
- 近似标题去重可能影响同一事件不同来源的保留；这属于需要样本验证的风险推断，尚未观察到误删案例。
- 官方称 Run rule 为预览；本轮未实测其对各种动作是否绝无副作用，不能替用户配置外发动作或把它描述成已验证的安全沙箱。
- ALL/ANY 条件组合、级联次序、循环防护、失败重试和修改规则后的处理，仍缺具体操作证据。
- 服务器生成朗读与文章离线下载属于两条链；必须另外核验音频是否缓存及生成失败后如何恢复。免费资格以现行功能页为依据，不把旧“Pro 专属”的历史介绍直接套用。
- “继续阅读”的存在没有说明其进度是否像 Reader 一样区分浏览位置与最远阅读处。不能由相似按钮补出相同数据语义。

## 对本项目的意义（推断）

关联 R-020、G-001、G-002：高价值新闻应区分订阅、纳入、排序、去重、已读与收藏。AI 要解释“为什么没看到这条”，需要规则与处理结果。若源数据在上游已被过滤且 API 不返回，AI 不能声称自己检查过全部原始内容。是否提供被排除条目的解释/回看能力，是本项目候选问题，尚未确定设计。

## 后续观察脚本

用隔离的测试文件夹订阅自建测试源，输入同 URL、同标题、相近标题的文章及一条不同观点报道；记录过滤前后 web/移动/API 的差异、修改规则后的旧数据，以及预览与真实执行结果。只使用本地标记类动作即可研究大部分流程；当前没有执行这些测试。
